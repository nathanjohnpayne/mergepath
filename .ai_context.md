## Firebase and Google Cloud Tooling

The approved Firebase authentication model keeps each project's deployer service-account key in the 1Password Firebase vault (`op://Firebase/{project-id} — Firebase Deployer SA Key`), with shared 1Password ADC as a legacy resolver fallback. This describes credential custody and legacy resolution, not an approved way to deploy: production deployment remains blocked until separately reviewed tooling ensures repository build code and dependencies have neither deploy credentials nor author/reviewer PATs and cannot reach credential-manager files or preflight caches; publishes an immutable artifact with a digest and attestation bound to the intended repository and full source revision; and has trusted post-build tooling verify that binding and artifact integrity before acquiring deploy credentials, then deploy the verified artifact without rebuilding or executing the candidate checkout and inject each credential only into its consuming subprocess. The current scripts do not provide that isolation; see [Build and deploy isolation](docs/agents/shared-operating-rules.md#build-and-deploy-isolation) and [DEPLOYMENT.md](DEPLOYMENT.md).

### Scripts

| Script | Canonical source | Installed to | Purpose |
|---|---|---|---|
| `gcloud` | `scripts/gcloud/gcloud` in this repo | `~/.local/bin/` | Local wrapper that refreshes access tokens from a 1Password-backed or explicit source credential for normal `gcloud` commands |
| `op-firebase-deploy` | `scripts/firebase/op-firebase-deploy` in this repo | legacy helper | Existing resolver only; do not use for production deployment while the production block remains |
| `op-firebase-setup` | `scripts/firebase/op-firebase-setup` in this repo | legacy helper | Existing account/IAM setup only; do not run it to enable production deployment while the production block remains |

Install on a new machine:
```bash
cp scripts/gcloud/gcloud ~/.local/bin/gcloud
chmod +x ~/.local/bin/gcloud
```

### Credential Model

- Each project has a dedicated GCP service account: `firebase-deployer@{project-id}.iam.gserviceaccount.com`
- The per-project Firebase-vault SA key remains the approved credential-custody model; the existing resolver order is documented as legacy behavior in `DEPLOYMENT.md` § [Deploy credential precedence (canonical)](DEPLOYMENT.md#deploy-credential-precedence-canonical), not as authorization to deploy
- Do not use `scripts/op-preflight.sh --mode deploy` or `--mode all` for builds or deployment; neither is an approved deployment setup. Review-mode preflight is for review work only
- Keep the approved 1Password-backed deploy-auth model; do not replace it with deploy-key-on-disk or routine `firebase login` guidance
- The local `gcloud` wrapper resolves source credentials through a narrower 3-step chain (`GOOGLE_APPLICATION_CREDENTIALS` → shared 1Password ADC → local ADC file) for ordinary non-deployment `gcloud` commands. It does not consult per-project Firebase-vault SA keys
- No deploy service-account key is committed to a repo; the legacy resolver materializes the 1Password key as a tempfile during its invocation, which does not make that flow approved for production deployment
- Routine key replacement and completion remain blocked until separately reviewed, non-deploying validation proves the replacement usable; metadata, key IDs, resolver logs, and production deploys are not substitutes. Suspected-compromise containment is a separate owner-led incident decision; this guide neither authorizes revocation nor requires production deployment to validate or contain it. See [key rotation guidance](DEPLOYMENT.md#rotating-a-firebase-deploy-sa-key)
- Runtime application secrets follow a two-lane 1Password model, reconciled with 1Password docs as of 2026-05-21: attended local agents should use 1Password Environments and the client-specific adapter that applies (Codex MCP where available, the 1Password local `.env` validation hook for supported non-Codex agents); CI/headless workflows should use explicitly scoped service-account tokens only after the relevant decision ticket approves the scope. Shell scripts may continue to use `op://` references, `op run`, and `op inject` where a generated runtime file is genuinely required; Secure Note `notesPlain` whole-file bootstrap is retired.

### Deployment status

Production deployment and the legacy `op-firebase-setup` / `op-firebase-deploy` flow remain blocked until the isolation conditions above are met. Do not install or invoke the legacy deployment helpers as a workaround. This guide provides no production deploy command. Routine key replacement remains incomplete until non-deploying usability validation succeeds; suspected-compromise containment is a separate owner incident decision, as described in `DEPLOYMENT.md`.

The installed `gcloud` wrapper remains available for ordinary non-deployment Google Cloud commands. Do not treat that support as Firebase deployment approval.
