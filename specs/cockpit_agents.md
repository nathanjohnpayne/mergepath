# Cockpit agents and accounting (#1590)

## Source contract and scope

`mergepath/cockpit/agents.py` supplies a read-only `AgentsProvider.fetch(deadline) -> Sample` under `cockpit-agents/v1`. Trusted launch configuration supplies an immutable enrolled inventory, configured `Checkout(repo, path)` roots, the canonical hub source root and optional explicit provider price keys and shared GitHub client. `discover_checkouts(root, repo)` uses the installed Git worktree inventory with a five-second bound and an environment without ambient credentials. The launch owner defaults to the hub main checkout and its worktrees; repeatable explicit checkout configuration may add enrolled consumers. Browser requests cannot select roots, local files, commands, pricing models or upstream endpoints.

`resolve_history_settings(settings, inventory, root)` resolves the operator's launch JSON once and returns `(checkouts, price_keys)`, an immutable checkout tuple and read-only copied price-key mapping. Only the keys `checkouts` and `price_keys` are accepted. An empty settings object discovers the inventory's sole hub from the trusted canonical root and its Git worktrees. Optional `checkouts` maps an enrolled repository slug to a nonempty list of absolute existing directory paths; each adds that configured checkout and its discovered worktrees. Trusted symlinks and platform aliases resolve once, duplicate `(repository, physical path)` pairs collapse, and one physical root assigned to two repositories is refused. The combined inventory is capped at 64 unique roots, and all Git discovery shares one five-second launch deadline with the existing scrubbed environment. Invalid configuration or failed discovery aborts launch rather than silently substituting a checkout.

Optional `price_keys` accepts only `claude` and `codex`, mapped to exact existing `anthropic.<model>.<tier>` and `openai.<model>.<tier>` rate objects respectively in canonical `scripts/phase-4b/prices.json`. That table is read through the bounded no-follow local reader only when keys are supplied; scalar rate-field paths, unknown models/tiers, wrong-provider keys and malformed tables are refused. Omitted keys remain unavailable; there is no inferred default model. The shared launch owner loads the operator's settings file through its existing bounded no-follow JSON loader and supplies registered reviewer identities from governing policy separately.

The history source reads `.mergepath/phase-4b-ledger.jsonl`, live `.mergepath/phase-4b-loops/*.jsonl` and the actual canonical archive suffix `*.jsonl.archive`. A ledger record has no repository field and a trusted hub checkout can review consumers. A unique genuine run ID plus PR, or an exact local legacy loop match plus PR, establishes its target. Unmatched ledger rows remain whole-history/account-visible with target attribution unavailable, and repository filters exclude them. Checkout location never assigns them to the hub. Every non-approval loop remains eligible, including unavailable/refused adapter attempts. `APPROVED` accounting is a cross-check over `loops[]`, never additional token spend. The optional shared GitHub client reads only APPROVED reviews by configured registered reviewer identities and extracts `<!-- p4b-accounting:v1 ... -->` blocks. Each local ledger line is admitted atomically only after every loop passes the established normalizer and the whole line fits the remaining normalized-row budget; rejected lines contribute neither partial history nor an approval accounting group. Every remote block must contain nonempty loops that pass the established loop normalizer before its original loops are passed to the canonical accounting helper. Missing accounting evidence is explicitly unavailable (`no_evidence`); empty or malformed blocks are invalid responses. Neither contributes a checked PR. Cross-checks cache each selected PR for 1,800 seconds, select at most eight recent locally recorded PRs, follow at most five pages per PR through the shared client's pagination boundary, and report denied, malformed, mismatched and truncated coverage explicitly. Cached observation times remain available. A denied remote cross-check preserves local history; its absence is not proof of agreement. No GitHub writes, credential expansion or model calls occur.

An accessible configured checkout without a telemetry directory is an observed empty history, so the UI can say no runs. Opening a checkout root alone does not establish an observation when its telemetry directory is refused. A checkout contributes an observation when its scan succeeds (including empty scans) or telemetry files are successfully read; unreadable/refused-only telemetry contributes none. `hasObservations`, `observed_checkouts`, `coverage.checkouts` and `history_complete` distinguish empty, partially observed and unavailable data. The projection propagates `coverageValid = hasObservations && history_complete`, withdrawing complete coverage for partial scans while retaining readable rows and diagnostics. Incomplete empty scans say coverage incomplete, never no recorded runs. Scheduler failures retain the previous last-good envelope and age with stale marking.

## Identity and aggregation

A genuine `p4b-...` identity is scoped by enrolled repository and de-duplicated across checkout, live-log, archive and approval copies. Compatible posted/not-posted lifecycle observations merge. Conflicting terminal verdict, reviewer, head, PR or measured values mark the run conflicted, expose a diagnostic and remove its token/cost/elapsed amounts from available totals. Approval or adapter output never establishes current merge authority.

Legacy rows lacking genuine `run_id` keep a source/record locator identity. They are not assigned synthetic cross-checkout identities. Within a single checkout, exact canonical loop occurrences already present in local logs match approval occurrences using a multiset, so repeated identical independent loops retain their multiplicity. Log-envelope timestamps do not prevent matching older approval loops that lacked start metadata. Independent legacy loops across checkout roots remain separate, with the legacy coverage count visible. Historical times are never fabricated from approval generation time or file mtime; undated rows remain available in the table and are excluded from dated chart bins.

Totals are computed by the existing pure `p4b_acct_compute_totals` function in `scripts/phase-4b/accounting.sh`, through a bounded subprocess with a scrubbed environment. It neither reads cached credentials nor invokes `gh`, `op` or an adapter. The provider returns the canonical all-history totals and per-PR totals without changing their measured-sum semantics. Coverage counters identify how many runs exposed tokens. Missing measured fields remain explicit null; the UI never labels a partial measured sum as complete spend. Browser-bound amounts must remain finite and within the JavaScript safe numeric range; opaque PR and run identities are strings.

## Cost and provenance

A CLI-exposed `tokens.cost_usd` is `reported`, with the CLI token provenance. It is a reported amount, not an independently verified invoice. Missing reported cost may be priced only with an explicit configured model/tier key from the versioned `scripts/phase-4b/prices.json`; the provider does not infer an exact historical model from the reviewer name. Every estimate exposes the configured key, table version and source.

Measured input/output/cache splits use their corresponding versioned rates and are labelled `estimated`, API-equivalent and not billed. Codex total-only rows retain null input/output/cache/reasoning splits. Their pricing returns a `bounded_estimate`: a lower and upper amount spanning the applicable input, output and cached-input rates, multiplied by the reported total. There is no invented 80/20 split or exact scalar cost. Missing mapping, rates or measured counts yields `unavailable`. Combined costs retain estimate labels, ranges and measured-run coverage. Reported and estimated values are never presented as verified billed spend.

## Local read boundary

Configured roots are resolved once from trusted launch configuration, accommodating platform aliases such as macOS `/var`. Every subsequent directory and file component uses `openat`-style descriptor-relative operations with `O_NOFOLLOW`; symlinked state/log directories and files are refused. Only regular files are read; nonblocking opens prevent FIFOs from hanging. Each poll is bounded by its monotonic deadline, 64 configured roots, 512 files, 2 MiB per file, 32 MiB total bytes, 10,000 normalized history rows, 128 PR groups and 256 approval groups. History selects eligible `.jsonl` and `.jsonl.archive` names in lexical order within each trusted checkout, sharing the global 512 read-attempt budget with ledger files and reserving one attempt for the final price-table read. Unrelated directory entries do not consume eligible-file capacity. Excess eligible files or exhausted shared capacity retain the readable bounded subset with incomplete coverage and a stable diagnostic; selection does not promise the newest files, every checkout or all history. Unknown repository slugs, malformed records, non-finite/negative/unsafe quantities and oversized sources fail visibly. Diagnostics contain stable plain text, never raw file content, machine paths or credentials. Group/deadline failures fail the scheduler source and preserve last-good data.

## History UI and design evidence

`assets/agents.js` registers the history panel on the shared `agents` source. Its pure projection, provider/day aggregation and DOM view use textContent, shared six-state badges, local buttons and stable run IDs. The initial view contains seven UTC days, paired Claude teal/Codex striped bars, compact printed amounts or bounds beneath dates, totals with measurement coverage, and the run table. Range bars show the upper bound, explicitly labelled in the legend. Per-provider controls hide the other chart series; a PR button narrows the same table to all recorded loops for that PR and exposes its canonical loop/token/elapsed totals. All-recorded-date and clear-PR controls are local filters and make no network requests. Unknown finding buckets and elapsed values remain unavailable. Legacy IDs and unavailable Codex splits are labelled. The table scrolls within its panel on narrow viewports.

Visual reference: the owner export pinned to design commit `4453251f417efd5850e4015a37de01e4287233cb`, agents/history source and PNG exports, and the runnable authentic Main export (`ed8a20689ee570f773ffcd4873974e59a5504857948d171d5a4804cf268f92e2`). The implementer personally read the relevant source/spec/images and exercised Calm, Busy, Speed bumps, Boulder, dark and reduced-motion states in an own IAB tab before UI authoring. The unavailable hidden-visibility option was omitted; no browser-global settings were changed. History mock dollar figures and exact scalar Codex prices were replaced by supported measurements and truthful uncertainty.

Chart height transitions retain the inspected 700 ms `cubic-bezier(.2,.8,.2,1)` token. Shared reduced-motion preferences set the duration to zero, including an OS preference change while the page remains open. The chart evicts expired dates from both its map and DOM when the seven-day UTC window advances, retaining surviving day nodes. Filter buttons and surviving run nodes are retained on repeated snapshots; no reward or row-entry animation is invented for static historical records. A real authenticated synthetic fixture was exercised for provider and PR filtering, both themes, reduced motion and a 390 px viewport. It retained document width 390 px with the table's internal scrolling. Computed chart transitions were 0.7 s normally and 0 s under a live OS-reduced-motion change. The initial mobile provenance wrapping was corrected to compact values/ranges with full accessible labels. These observations cover the history slice, not final integrated/live-panel acceptance.

## Live dependency

The integrated live consumer follows merged #1589 advisory heartbeat semantics and is specified in [`cockpit_live_agents.md`](cockpit_live_agents.md). The history source retains `live: null`; the separate `live_agents` source and registered `live_agents.js` panel supply observed stage/process identity, adapter start/elapsed/timeout, terminal summary and confirmed posting evidence. Invocation/barrier elapsed must not masquerade as adapter timeout consumption. Crashed, unknown and stale process evidence require separate presentation. Neither heartbeat presence nor a posted historical approval proves current-HEAD merge clearance.
