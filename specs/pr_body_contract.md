# PR-body contract

`scripts/lib/pr-body-contract.mjs` is the single parser for the pull-request body declarations used by identity, review, and self-review checks. It accepts the existing CLI modes `--author`, `--author-count`, `--has-self-review`, and `--json`; `--json` continues to emit `author`, `authorCount`, and `hasSelfReview`.

## Marker and membership contract

`Authoring-Agent:` and `## Self-Review` retain their strict raw column-zero syntax. The parser counts every visible Authoring-Agent declaration, lowercases one valid identifier, and reports an empty author for zero, duplicate, or invalid declarations. A Self-Review marker is an exact level-two heading at source column one.

Ordinary sync and sync-all use the same self-review formatter for commit messages and PR bodies. Operation correctness names the canonical source; regression and security statements reflect the possible effects of the selected artifacts. Test coverage describes selected canonical tests and fixtures and calls for consumer CI evidence on the resulting head. Ordinary sync marks selected source-absent canonical paths as removals in both serialized file lists; test guidance includes additions, updates and removals. Generated wording does not assert a copy for a selected deletion, upstream review clearance, passing CI, absent test changes or an unchanged attack surface.

Every sync-all PR records its requested scope before consumer overrides: the resolved destination-path count and digest used by the branch, the requested and total opted-in manifest-entry counts, whether path and repository filters actually narrow their respective sets, and every opted-in manifest path omitted by the request. Any omitted entry makes the introduction describe a narrowed sync rather than a full mirror. A full replay claim means all opted-in canonical, kit and templated entries were requested; consumer overrides and installed acceptance remain separate. Native materializer fixtures exercise full and narrowed requests and bind the reported digest to the pushed branch (#2490).

CommonMark with GFM extensions decides whether a raw candidate belongs to the document's top level. Candidates inside blockquotes, lists, footnote definitions, table cells, fenced code, inline code, or raw HTML are excluded. A footnote definition is a container in the same sense a list item is: an unindented, non-interrupting line after `[^x]: note` is a lazy continuation of the definition's paragraph, and GitHub renders it inside the footnote, or not at all when nothing references that footnote. Treating such a line as a live declaration would spoof author identity, so the node type is part of the container set. A blank line closes the definition and an ATX heading interrupts it, and both leave what follows genuinely top-level. Existing HTML-comment treatment remains: real HTML comments are removed before marker syntax is checked, while comment-looking text in code remains code. Real HTML flow comments may retain zero through three leading ordinary spaces in both mdast values and source spans; those spaces do not prevent stripping, while four-space indented code, fenced code and inline code remain literal. This contract does not add a Markdown dialect, a marker form, or a hand-maintained container parser.

The parser uses GFM tokenization and mdast handlers to establish source positions and block membership; it does not render Markdown or consume rewritten inline link nodes. Its GFM post-parse transforms are therefore omitted, retaining the CLI's marker and membership results while avoiding an irrelevant recursive linkification walk.

## Known limitation: pathological Markdown parsing cost

micromark opens list containers with no nesting bound, and its document tokenizer re-shuffles its whole event array as each container opens, so a single line of repeated list markers costs quadratic time. A 60,042-byte body of `'- '.repeat(30000) + 'x\n\nAuthoring-Agent: codex\n\n## Self-Review\n'` does not complete in 45 seconds, where the handwritten parser this one replaces answers it in about 0.2 seconds. The list markers contribute 60,000 bytes and the content-and-contract suffix contributes 42 bytes. PR bodies are untrusted input that every validator invocation re-parses, so this is a denial-of-service surface. micromark 4.0.2 and mdast-util-from-markdown 2.0.3 are the current upstream releases and neither exposes a depth option.

A per-line nesting ceiling was implemented and withdrawn. It bounds the cost, but **that veto strategy** cannot be made answer-preserving: vetoing a marker turns it into paragraph content, which changes whether the next unindented line is a lazy continuation. This is a result about the two strategies measured below, not a proof that no bounded implementation can preserve answers---a mitigation that *rejects* an over-nested body outright, rather than parsing it under a veto, is a different design and is not ruled out by this evidence. In a targeted search over bodies whose nesting sits within ten levels of the ceiling, roughly 66% diverged from an unbounded parse at ceilings of 64, 128 and 256 alike---the rate is a property of the boundary, not of its height, so raising the ceiling only moves which bodies are misclassified. Every divergence was fail-closed, rejecting a valid declaration. That search was a one-off experiment run while the ceiling existed; it is not part of the committed suite, which carries no depth corpus, so the figure belongs to the experiment that produced it and is recorded here rather than asserted by a test. A cost-proportional variant bounding total containers rather than per-line depth was also measured and is worse on cost (15s at a 1,000-container budget, 140s at 8,000), because vetoing new opens does not unwind the containers already open.

The original local blockquote benchmark measured 96ms at 5,000 levels, 191ms at 15,000, 1,042ms at 30,000 and 1,256ms at 32,760, near the 65,536-character body-size limit. These are measurements on that environment, not a wall-clock bound imposed by the body-size limit. A later [review on Node 20.20.2](https://github.com/nathanjohnpayne/mergepath/pull/1281#discussion_r4076032754) reported 30.6–32 seconds for the committed 30,000-level fixture; a local rerun on the same Node version took 1,206ms. Runtime therefore depends materially on the execution environment. Both the regression fixture and every production invocation now run under a portable 120-second watchdog; see § Production invocation bound below. This replacement still provides no general parsing-time guarantee---the bound says when an invocation is abandoned, not how long a parse takes---and the remaining input-side mitigation scope is tracked in #1289.

Same-line list nesting is not the only shape that reaches this cost. A 65,441-byte body of `'['.repeat(32700) + ']'.repeat(32700) + '\n\nAuthoring-Agent: codex\n\n## Self-Review\n'` does not complete in 15 seconds either, where the parser being replaced answers it in about 50ms. The brackets contribute 65,400 bytes and the contract-marker suffix contributes 41 bytes. That one is inline link-reference nesting rather than container nesting, so it is a distinct vector reached through a different part of the parser, and no container ceiling would have bounded it. Both are recorded here so the limitation is not read as narrower than it is.

### Accepted risk

This is a recorded risk acceptance, not a deferral notice. It is written here because the limitation is a property of the shipped parser, and a reader reaching this section should not have to reconstruct whether anyone weighed it.

**Accepted by the repository owner on 2026-09-17, reaffirmed 2026-09-23, on the record in [#1281](https://github.com/nathanjohnpayne/mergepath/pull/1281).** The decision was taken after a per-line nesting ceiling had been implemented, measured, and withdrawn, and with both rejected mitigations and their measurements in front of the owner.

What is accepted, as narrowed by the production bound below: this parser gates an identity and self-review check, runs on fully untrusted pull-request body text, and has no input cap and no nesting cap, so a pathological body still costs real wall-clock time on every validation. What is no longer accepted is the unbounded form of that exposure: an adversarial body now fails the gate closed at the bound instead of stalling it for as long as the enclosing job permits. The residual is cost, not hang---up to the bound per invocation, three invocations per `pr_body_validate`.

Why it was accepted rather than mitigated here: the replacement fixes 38 disagreements with GitHub's renderer across the archived 122-case corpus and closes two identity-spoofing bypasses (footnote definitions and table cells) that the handwritten parser also had. The two mitigations measured in this change both failed---the per-line ceiling changes answers at any height, and the cost-proportional budget is worse on cost---and the remaining candidate, rejecting over-nested bodies before parsing, is a different design that had not been built or measured. The owner judged the correctness gain to outweigh an availability risk on a check that is already gated behind CI rather than user-facing.

What would reverse it: a report of this surface being used to exhaust CI budget within the bound, or evidence that the exposure reaches beyond CI wall-clock. Mitigation is tracked in [#1289](https://github.com/nathanjohnpayne/mergepath/issues/1289), which carries both rejected strategies, their measurements, and the two traps a pre-parse bound has to clear---it cannot use the parser to measure nesting, and it must not return an empty author, which downstream reads as "no same-agent risk".

## Production invocation bound

Every production parser invocation runs under a wall-clock watchdog of at most 120 seconds. `scripts/lib/pr-body-contract.sh` routes `pr_body_authoring_agent`, `pr_body_authoring_agent_count` and `pr_body_has_self_review` through one wrapper that spawns the parser with Node's own synchronous child-process timeout and `SIGKILL`, so the bound needs neither GNU `timeout` nor macOS-only `gtimeout`---which matters because this file is propagated to consumers whose runners differ. The reviewer-assignment and weekly-audit workflows call the generated parser directly with the same Node timeout upper bound and kill signal; the weekly audit clamps that bound to its remaining allowance. Assignment falls back to its default reviewer on a parser error; the weekly audit records each timeout as a per-PR parser infrastructure error, continues with later PRs, publishes the report, and fails the overall audit, including for Dependabot PRs. A timed-out PR remains incompletely audited and cannot become a missing declaration or heading violation or be excused by an owner override.

Hook timeout parity applies to the registrations each configuration owns. The hub's Claude configuration and the canonical Codex configuration retain a tightly bounded `label-removal-guard.sh` registration; a consumer-owned Claude configuration may omit that unrelated hook. When present, its timeout must remain positive and below the parser-calling guard's aggregate parser bound. Allowing an absent consumer registration does not allow a present non-parser registration to inherit the larger parser timeout.

The bound is 120 seconds because the slowest legitimate parse recorded on any fixture is about 32 seconds, for a 30,000-level blockquote near the body-size limit, on an environment where the same fixture takes about 1.2 seconds locally. 120 seconds is roughly 3.75 times that worst observation, so runner-speed variance cannot turn a valid body into a rejected one, and it is the bound the parity suite already used for the same reason. It is a resource bound, not a parsing-time guarantee.

On expiry the shell wrapper exits 124 and emits no stdout; it still forwards any stderr the parser produced, so a timeout is diagnosable. Both halves are load-bearing. The status lets its callers distinguish "the parser did not finish" from "the parser answered", and those callers test it, so a timeout reaches their fail-closed guards. Suppressing stdout matters because `spawnSync` can return partial output alongside the timeout, and an empty author is read downstream as "no same-agent risk", which disables the authoring-agent exclusion in gate (b)---fail-open in the one place it must not be. `pr_body_validate` was the one shell caller that did not test these statuses; it now reports a parser that did not complete as an infrastructure failure rather than as a missing declaration, the same distinction it already drew for an unreadable policy file. Direct workflow calls use `execFileSync`, whose timeout throws instead of returning status 124; the weekly audit retains that infrastructure error in its report rather than throwing before later PRs are audited. Within the 30-minute job, the weekly audit retains its 25-minute script budget and one-minute reporting reserve. REST pagination and GraphQL reads carry an abort signal and a deadline race; parser and verifier subprocesses receive a positive timeout capped by the remaining audit allowance. A fast PR can start with less than the parser maximum available. Expired allowances report incomplete discovery or per-PR coverage, retain the remaining unaudited PR list and fail the audit; verifier timeouts cannot become policy-clearance evidence. Before its bounded issue write, the workflow retains the UTF-8 report in safely encoded log chunks and the job summary. A failed issue write is not retried and still fails the run, with coverage evidence retained. External cancellation can still interrupt reporting.

## Enclosing workflow inventory (#1622)

This source audit distinguishes a parser watchdog from the allowance of the step and job that enclose it. A reviewed finite route requires both declared enclosing limits to exceed `sequential calls × PR_BODY_CONTRACT_TIMEOUT_SECONDS + 30 seconds`; an absent step limit inherits the job, and an absent job limit means GitHub's 360-minute default. Equality fails. The 30 seconds is an ordering margin for watchdog exit handling, not an allowance for all other work in a step. Earlier checkout, API and review work can consume a job's remaining time; declared timeout ordering does not reserve wall-clock time or prevent external cancellation.

`tests/test_pr_body_workflow_bounds.py`, invoked by native parity, parses every workflow and required-workflow template as YAML. It requires Python 3 with PyYAML, which repo-lint provisions; direct local parity runs need the same parser dependency. The live hub inventory requires the exact file/job/step identities below, rejects changed literal runtime invocation signatures and refuses unknown or nonpositive `timeout-minutes` expressions instead of claiming their floors. YAML merge keys and aliases are evaluated before checking bounds. New literal parser calls and calls to the reviewed shell entrypoints in an unenumerated step require classification. It derives the per-parser bound from the production shell constant, checks the shared helper cardinalities and the two required-template predicate passes, and retains the existing direct-JavaScript bound checks in parity. This is a bounded source inventory, not a general shell/JavaScript call graph: new indirection or control flow requires review of the actual run block and helper paths.

All production steps below currently omit `timeout-minutes`. The job column records the current declaration, or `default 360`; the effective step limit is therefore that job limit. Workflow names are relative to `.github/workflows/` except the explicitly named inert required-workflow template.

### Shell entrypoints, test routes and non-executing references

The shell facade's `pr_body_validate` makes three parser calls: count, author and self-review. `scripts/validate-pr-body.sh` makes one in self-review-only mode, three normally and four when successful validation is followed by `--print-author`. `scripts/codex-review-check.sh` makes at most two for a shared-author body. `scripts/merge-clearance-gate.sh` delegates once on its external-review path; its derive-only paths do not parse bodies. `scripts/workflow/merge-group-required-checks.sh` adds one self-review call to that dispatcher per predicate pass. `scripts/workflow/approval-merge-continuation.sh` has a retained syntactic delegation ceiling of two checker evaluations (four parser allowances). With one stable governing author it makes zero body-parser calls: shared-author PRs exit before those checks, while a different native author does not enter the checker's shared-author parser branch. The four-call allowance deliberately protects the enclosing declaration against delegation/control-flow changes; it is not a claim that four parses are attainable in that stable-policy path. Its protective-only mode exits before both checker entrypoints. These conditions are reasons for smaller actual counts, not permission to omit a route from the audit.

Local entrypoints remain separate from declared production workflow routes. `scripts/hooks/gh-pr-guard.sh` makes two calls and retains its existing aggregate hook-registration guard. `scripts/gh-as-author.sh` validates through three calls only for a PR-create command; sourcing the library for an API/comment write does not parse a body. `scripts/phase-4b-review.sh` permits four initial calls and four on each of its two author revalidations, at most twelve; its adapter timeout does not enclose those parsing sections. `scripts/post-phase-4b-handoff.sh` makes two calls. `scripts/pr-review-policy-nudge.sh` can invoke the three-call validator, and `scripts/workflow/stalled-prs.sh` can invoke the checker under its own local gate budget; neither currently has a production workflow invocation. Printed commands in the resume helper, the merge writer's packaged helper inventory, documentation strings and mere shell-library sourcing are references rather than proof that a parser runs.

## Generated runtime and rebuild

The generated standalone runtime remains at `scripts/lib/pr-body-contract.mjs`, the propagated consumer path. Its readable source and build inputs are hub-only: `scripts/lib/pr-body-contract.source.mjs` and `scripts/lib/pr-body-contract.bundle/`. A consumer executes only the generated runtime and performs no npm install or network operation.

Rebuild or verify it from a hub checkout with `node scripts/lib/pr-body-contract.bundle/rebuild.mjs --write` or `node scripts/lib/pr-body-contract.bundle/rebuild.mjs --check`. Both commands create a fresh temporary build directory, run the pinned `npm ci --ignore-scripts`, and bundle the source; `--check` byte-compares the result with the committed runtime and fails when it is stale.

The lock pins every build dependency. The rebuild uses its esbuild metafile to identify bundled packages and embeds each package's version, locked npm source, declared license, and packaged license text in the generated runtime. A generic attribution file is insufficient because consumers receive the standalone runtime.

The generated runtime disables ESLint rules for that artifact and removes micromark's two upstream `no-bitwise` directives. This keeps dependency implementation details and unused upstream lint directives from breaking a consumer's lint run; consumer lint configuration and the readable source remain unchanged. In `--check` mode, the pinned hub-only ESLint dependencies validate the generated output against the recommended JavaScript rules with unused-disable diagnostics treated as errors. Negative controls remove the exemption or restore an upstream directive and must produce lint errors. The hub parser suite runs this rebuild and lint check; consumer suites skip it and install no build or lint dependencies.

## Regression coverage

`tests/test_pr_body_contract_parity.sh` verifies the stable CLI result and all existing consumers' shared-parser use. Its #1192 corpus covers renderer-confirmed quote-first-block, list-transition, nested-list, comment, code, and malformed-heading outcomes. Focused private-helper assertions also verify indented flow-comment stripping and code preservation directly, because unchanged membership results alone do not establish this internal consistency.

The parity suite's propagation entry requires the audit workflow alongside its native deadline/report fixtures, so a path-scoped sync cannot deliver those assertions against a stale workflow.
