# Cockpit CI observations

`mergepath/cockpit/ci.py` owns the read-only `ci/v1` provider. `CIProvider(client, inventory)` is a scheduler callback returning `Sample`; it uses the existing shared client and deadline. Register source `ci` once, with 20-second hot and 120-second idle cadence, and bind the fixed CI panel before scheduler start. Complete bounded REST pagination covers open pulls, Actions runs in an explicit default 24-hour rolling recent window plus all queued/in_progress/waiting/pending/requested runs regardless of age, all run attempts' jobs and all check-runs (`filter=all`) for observed SHAs. The payload names recent_seconds; this is recent history, never all history. Completed jobs are cached by repository/run/attempt in at most 256 entries; active jobs and same-SHA checks refresh each scan. Each repository scan is atomic: reaching a page bound or encountering a denied/malformed/deadline response retains that repository's last-good runs/groups and original observed_at, with stale/error/attempted_at/retry_at metadata. A never-observed repository retains no invented rows or age. Successful repositories remain usable. Per-repository failures use bounded exponential retry delay, preserving shared provider Retry-After/backoff. The projection conservatively downgrades the selected coverage to stale if any selected repository is stale or missing; the shared registry must OR this downgrade with scheduler staleness, never permit a freshness upgrade. No partial scan establishes absence or clearance. Each callback reserves 250 ms of the source deadline for publication and rotates repository priority. Once the request budget is spent, it starts no additional scan and marks untouched coverage unavailable/stale for the next fair attempt; deadline exhaustion does not delay those untouched repositories behind a per-repository error backoff. This publication margin is operational slack, not an absolute CPU-time guarantee for arbitrary ordinary JSON trees. Unexpected whole-callback failures still retain the scheduler sample.

Rows group by enrolled repository, PR number (or null when unattached) and exact SHA. Current HEAD is determined from the separately observed open pull, never from the old run's pull-request metadata. Missing or closed PR HEAD evidence remains unknown. Each run names its latest run attempt and explicitly labels jobs_scope as all-attempts; each job retains its observed run_attempt or null/unknown instead of pretending every job belongs to the latest attempt. The panel names the configured recent_seconds window in visible copy. Each run retains jobs and every observed step, including `check_*`, with status, conclusion and timestamps; no suite-count parsing is performed. Opaque API IDs, PR numbers and step identities are canonical positive decimal strings even beyond JavaScript's safe integer range. Unknown timestamps remain null. Names are capped at 1,000 Unicode code points and check-output diagnostics at 4,000; browser validation counts the same units as the Python producer. A job check-run URL must retain the exact HTTPS API authority, endpoint structure and canonical check ID. Only its owner/repository path, within the existing ASCII inventory grammar, compares case-insensitively with the enrolled repository; the payload keeps the inventory spelling.

A failed check is superseded only by a successful check with matching repository, SHA, name and known producer identity, whose observed start is later. Actions producer identity includes its app ID and workflow ID; supersession additionally requires a proven common `workflow_run_id` from the existing check-suite mapping. The producer string retains its established UI schema; a passing independent run cannot clear a failure even if workflow and triggering event match. An ambiguous suite-to-run mapping or missing run lineage preserves every observation. Genuine retries within the same run may supersede earlier attempts under the existing later-start requirement; another workflow with the same job name cannot clear it. Other apps use their app ID. Missing producer or ordering evidence never proves supersession. Failed history remains visible with superseded and old-HEAD labels. Unsuperseded failed current-HEAD checks are actionable speed bumps. A run whose failure cannot be tied to check evidence remains visibly failed with unavailable current-check evidence; it cannot establish a clear claim. Queue age is information only. The exact `gh run rerun <id> --failed --repo <repo>` is display text, never executed.

Observed bounded check output diagnostics have check-run provenance. The specific installation-rate-limit message establishes token exhaustion without fabricating remaining/reset/secondary-pool evidence. Explicit CodeQL diagnostic text stating a not-retryable failure establishes that condition; workflow names and generic finalize errors do not. These observations may contribute boulders only for unsuperseded current-HEAD failed checks. FAIL extraction is separately sourced from job logs and does not reinterpret diagnostics as log lines.

`LogExcerptCache` is the on-demand seam. Trusted construction injects `read_log(repo, job_id, deadline)` through the shared read transport, never an alternate credential/subprocess/transport. The authenticated scoped GET route `api/ci/excerpt` accepts exactly repo, run, attempt, job and step. Each input must match the current observed CI envelope and a failed step in an enrolled repository; no URL or command is accepted. A stale envelope refuses new fetches explicitly. The documented step-log endpoint returned 404 in root's authenticated probe; no speculative index retry is made. Cache identity includes repo, run, attempt and job; selected-step time-window extraction uses timestamped job lines when both observed step boundaries are available. Repeated requests coalesce behind one bounded job read, cache complete log bytes (including empty logs), deterministic permission denials and oversized-body refusals for 120 seconds in at most 32 jobs, and share a maximum of two active reads with no executor queue. Transient failures, including deadline exhaustion before a read starts, are returned without caching; an explicit retry can read again while still honoring the shared client's backoff and transport fence. Deadline exhaustion remains unavailable. Body cap is 2 MiB at the shared reader and extraction seam; extracted output retains the newest tail in chronological order, at most 80 FAIL lines, each at most 1,000 Unicode code points, and 32 KiB total. When step timestamps are absent, a FAIL line is untimed, or a fractional FAIL timestamp falls in the remainder of the second containing the observed completion boundary, extraction falls back to the labelled whole-job tail. Second-resolution REST metadata cannot distinguish that failure from an adjacent step; no widened window is presented as selected-step evidence. Control/ANSI escape sequences are removed; display uses textContent. Empty, denied, unavailable and stale outcomes are distinct. Callback exceptions publish finite existing error categories only.

`assets/ci.js` projects the single shared SSE snapshot and registers `ci`; it adds no polling or EventSource. It preserves one expanded run, stable nodes and keyboard focus across updates. Browser excerpt requests resolve relative to the authenticated namespace and abort/discard obsolete responses. Themes and glyphs reuse shared tokens; running pips blink at the reference's cadence, tone/detail changes use 360 ms, and normal entry uses the shared ease. Manual/OS reduction removes movement, stagger and loops with readable resting frames, including preference changes while open. Reference mock queue thresholds and generic CodeQL-finalize claims are superseded by the settled acceptance contracts.

Tests: `tests/test_cockpit_ci.py` covers provider, grouping, supersession and bounded on-demand reads; `tests/test_cockpit_ci_ui.cjs` covers projection and DOM/disclosure/request behavior. Root integrates these suites into the hub-only Cockpit check/test wrappers and spec mapping. The provider, assets, tests and spec remain hub-only. Authenticated actual-server visual/motion evidence is recorded externally; unit tests alone do not complete browser acceptance.
