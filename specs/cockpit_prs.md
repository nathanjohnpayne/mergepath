# Cockpit PR observations

Ticket #1587 provides a read-only open-PR source and reusable row view. It registers once with the foundation scheduler and shared GitHub client. Fast observations use one repository-batched GraphQL connection query, then bounded alias batches for required checks with explicit PR-number context. Both the PR HEAD and commit oid must agree between reads. Bounded continuation queries complete every truncated PR, label and head-check connection. A disappeared row is looked up by its previously observed number: only an explicit MERGED observation rewards it; CLOSED is ordinary removal. Missing/denied data, including a null or malformed GraphQL repository, retains last-good repository observations and keeps their age; retained row and Road-hazard copies are explicitly stale until successful recovery. Partial repository coverage is disclosed and cannot support a fresh-clear claim for the selected scope. Repository start order rotates across cycles; upstream work stops 250ms before the scheduler deadline so retained coverage can still publish.

Required legacy `StatusContext` state `EXPECTED` is pending/running. Required `CheckRun` observations collect `startedAt`, the producing `checkSuite.app` identity and slug, and the Actions workflow plus workflow-run identity through `checkSuite.workflowRun.id` and `checkSuite.workflowRun.workflow`. For one PR HEAD, attempts with the same check name and known app/workflow/run identity collapse to the uniquely latest known start time after complete context pagination. Independent Actions workflow runs remain separate even when the workflow and triggering event match. Different apps or workflows remain separate, and missing identities, missing/invalid start times or tied latest start times retain every observation. GitHub Actions requires known workflow and workflow-run identities; legacy StatusContext entries remain separate because their creator does not establish a producing app. Optional checks cannot supersede required evidence. These are display observations, not a branch-protection verdict. Field and state definitions come from GitHub's [Checks](https://docs.github.com/en/graphql/reference/checks), [Actions](https://docs.github.com/en/graphql/reference/actions), [Apps](https://docs.github.com/en/graphql/reference/apps) and [Commits](https://docs.github.com/en/graphql/reference/commits) schema references.

## Evidence and budgets

Existing Codex ledger/human-stop, feedback-accounting, CodeRabbit read-only probe and Phase 4b totals helpers supply slower enrichment. A bounded local read bridge routes helper gh API calls through the same GitHub client, headers, serialized transport and deadline; it refuses all writes and unrelated repositories, provides no ambient gh/keyring path and passes no credential to child processes, including jq. CodeRabbit runs trusted code from a private context containing the target PR's resolved governing base policy and target-base .coderabbit.yml; unavailable target context stays unknown. Accounting record attribution uses that same target policy through the existing helper override, never the hub reviewer list for a consumer. Capture HEAD/base SHA/base ref/base repository identity before materialization, pin the resolver to that tuple and recheck it after the ledger, before CodeRabbit context and before returning any receipts. A same-HEAD base advance refuses all mixed-context receipts. Native JSON output goes through the foundation tree validator. Every enrichment receipt names repository, PR, HEAD, observation time and individual source availability. HEAD changes invalidate enrichment immediately. Same-HEAD receipts refresh on a 120-second slower cadence; PR updatedAt changes also make enrichment due. A bounded round-robin queue prevents a permanently HEAD-change-only cache and unbounded helper fanout. Failed source refreshes retain explicitly stale prior evidence; unknown sources supply no guessed zero.

The five meters headline remaining / denominator, retain used / source / observation / stale, fill by used share, show a boulder at zero and a bump only when at most two remain and the limit is at least five. Policy limits come from the ledger's governing base snapshot. Cockpit settings defaults (10 rounds before Phase 4b, one rerun) are labelled advisory display settings: they do not change routing, stop automation, request reviews or authorize merges. CodeRabbit's five-commit meter is explicitly an advisory display threshold, not a claim about the target .coderabbit.yml auto-pause setting. It counts commit identities after the newest trusted review's commit_id within a complete current-HEAD commit list. Commit timestamps do not prove when a commit was pushed; a later resume-only timestamp, absent/rebased anchor or moved HEAD therefore leaves the count unknown. The read-only CodeRabbit probe's exit 7 means no review yet, an observation rather than a helper failure. Terminal findings and skipped states render as completed outcomes, with a skipped reason when known; neither shows a pending spinner. LLM totals reuse trusted-reviewer Phase 4b record extraction and accounting semantics, disclose measured-loop coverage and reported versus notional costs; Codex input/output splits remain unavailable. Malformed loop/token objects and indistinguishable duplicate legacy loops make accounting unavailable without discarding other PR evidence. Genuine run IDs deduplicate exact repeats and reject conflicts; PID-only identifiers cannot establish global invocation identity. Token sums preserve the helper's measured-only semantics using native integer arithmetic before browser publication to avoid jq/browser precision loss. Opaque identities and exact large integers are decimal strings before browser publication.

CLEAN is only GitHub's merge-state fact. Rows disclose gate labels, reviewDecision, required checks, Codex human stops and request evidence without declaring merge clearance. A request comment supplies no HEAD anchor, so unanswered requests are shown as outstanding with HEAD unknown unless the shared ledger summary explicitly anchors active work on HEAD. Precedence is human stop, UNSTABLE, DIRTY, spent budgets, near budgets, CodeRabbit pause/rate limit, BEHIND, unaccounted feedback, draft, CLEAN fact, running, waiting. All four gate labels remain visible. Every bump/boulder contributes a stable PR-owned Road hazard with observed timing; no guessed ETA is supplied.

Helper outputs must have object-shaped source receipts, an array of object-shaped accounting records and object-shaped HEAD/base/repository metadata before tuple comparison. Malformed data and subprocess failures degrade the affected helper source; a helper failure escaping the reader degrades that PR's enrichment without discarding successful fast PR/repository observations. Same-HEAD last-good receipts retain their observation time and become stale; a never-observed failed source stays unavailable. Stable deadline errors remain `deadline_exceeded`, including subprocess timeouts. The existing deadline guard stops later enrichment once the request budget is spent, while retained/fresh fast rows still publish. Fatal interpreter/control exceptions are not caught.

## Row and integration seam

`build_row(repo, raw, enrichment, settings, observed_at)` is the provider-side enrichment seam. `cockpit-prs/v1` contains `repositories[]` with repo, rows, observed_at, stale and error. A normalized row identity is `repo#number`, with number as a decimal string; HEAD is evidence currency, never a second row identity. The model includes basic fields, lifecycle, required check records/links, labels, five budgets, spend, feedback, Codex and CodeRabbit receipts, state/label/reason and owned hazards. Unknown enrichment is represented by null values and explicit source error/status. `partial_row` supplies the same schema for an audit-reported sync PR without inventing enrichment.

`CockpitPRRows.RowView` receives a row plus observed transition context and performs only DOM rendering. `RowList` exports the stable keyed collection and single-open disclosure controller for both PRs and later Fleet use. It performs no fetch, policy adjudication or mutation. Focus, nodes and expanded budgets survive repeated snapshots, HEAD changes and filtering. Initial rows enter over 360ms with 40ms stagger by their sorted position; only subsequently observed new OPEN identities use the 700ms fresh-entry animation. Only a fresh observed OPEN→MERGED transition triggers the 900ms ribbon pop, 2600ms local glow/five dots and 7000ms removal. Repeated merges do not restart timers; reopened/closed/removed rows cancel obsolete reward and removal work. Stale or first-seen historical merges have no reward. Reduced motion renders readable resting states without movement, hover lift or stagger; it also applies when the preference changes while open.

Root owns shared registration/loading: instantiate `PRProvider(client, inventory, root, checkout_roots=...)`, register source `prs` with scheduler defaults, bind panel `prs`, add relative `assets/prs.css`, then scripts `assets/pr_rows.js` and `assets/prs.js` after components/app. The module registers through `CockpitApp.registerPanel`. No new HTTP route or browser polling is needed. The shared registry must conservatively combine envelope and projection stale flags for partial repository observations.

## Validation

`tests/test_cockpit_prs.py` covers provider pagination, source failure/retention, same-HEAD evidence refresh, policy/helper receipts, all gate labels, budget boundaries, unknown data and exact integer strings. `tests/test_cockpit_prs_ui.cjs` covers projection/count/hazard validity, stable row/disclosure/focus behavior, partial sync-row reuse and timer interruption. Tests are hermetic and bounded to 60 seconds; expected duration is under ten seconds. Root integrates these suites in the existing Cockpit check and propagation allowlist. Browser acceptance uses the actual authenticated Application/Handler with deterministic fixtures and a transport that refuses real requests; visual/motion evidence remains a separate receipt.
