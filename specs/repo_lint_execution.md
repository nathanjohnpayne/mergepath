# Repo-lint execution model

## Purpose

The `repo-lint` workflow preserves one stable required context named `lint` while avoiding duplicate work and keeping exhaustive regression nets off unrelated pull requests' critical path.

## Event contract

Target-repository pull-request heads run through `pull_request` only. Feature-branch pushes do not start a second copy of `repo-lint`, Markdown prose wrapping, or OWL validation. A `push` run is retained for `main`, and pull-request concurrency cancels an older in-progress head when a newer commit arrives. The target repository contains zero `merge_group` triggers. For #1058, a separately protected organization-owned public policy repository materializes the required repo-lint workflow beside the authorization workflow. The organization workflow ruleset binds both by source repository id, exact path, protected ref, and full SHA; a distinct target-repository ruleset supplies the native singleton merge queue. Public source visibility is mandatory for every target visibility because authorization's sole write-authority handshake fetches its exact SHA without credentials. The external repo-lint workflow supplies the pull-request and synthetic merge-group lint results without letting target content define its own group trigger. Scheduled and manually dispatched target runs remain deep CI in Mergepath and in consumers that carry the canonical `scripts/ci/` kit; kit-less consumers have no deep implementation to execute. A missing wired wrapper soft-passes only where the hub-only `scripts/sync-to-downstream.sh` marker is also absent; the same absence on the hub fails the step.

## Scope classifier

`scripts/ci/repo-lint-scope.sh` is the single scope decision. A pull request enters deep CI when it changes CI workflows, scripts, tests, specifications, rules, agent operating documentation, architecture decisions, either repository manifest, `AGENTS.md`, `REVIEW_POLICY.md`, or `ai_agent_tooling_standard.md`. Other pull requests use the fast lane. An unreadable pull-request diff fails closed to deep CI, and every non-pull-request event is deep once the canonical `scripts/ci/` kit is present. A consumer checkout that intentionally or temporarily lacks that kit emits `deep=false` because it has no deep check implementation to execute; the hub fails instead of taking this exception.

The classifier reads `scripts/ci/repo-lint-dependencies.json`, the machine-readable dependency graph for expensive wrapper checks. A direct change to `scripts/ci/check_<name>` selects that wrapper. A dependency named by the graph selects every wrapper that owns it. The graph declares four trigger classes, from widest to narrowest effect. `full_triggers` are the lane's own definition (the workflow, the classifier, the graph, the shared selector, the sync engine, and the consumer-safety, residue and optimization suites); a change there selects the complete deep surface. `consumer_replay_triggers` are the inputs that define the consumer shape (the sync manifest, the bootstrap exclusion list, the propagation-closure allow-list, the consumer verdict classifier and the shared wrapper-mode contract); a change there selects the complete consumer replay without forcing every self-test. `deep_triggers` are the governance documents (`specs/*`, `rules/*`, `docs/agents/*`, `docs/architecture/*`, `AGENTS.md`, `REVIEW_POLICY.md`, `ai_agent_tooling_standard.md`, `.repo-template.yml`); their only deep-lane readers are the hub-only harnesses, so they request the deep legs in smoke mode and the complete replay runs for them on the next push to `main` and on the daily schedule. `wrappers` maps a changed path to its owning wrapper or wrappers, and every test a declared wrapper references must be declared under it; the suite derives that set from the wrapper sources so a newly referenced suite cannot route to the wrong partial selection. The derivation reads the raw wrapper text, comments included: a test path a wrapper names only in a comment is declared under that wrapper or the comment is reworded, with no per-wrapper or per-path exemptions (#2227). A comment stripper has to model shell syntax, and each construct it misreads hides a live reference silently, as a first-`#` truncation did for references written after a quoted issue number (#2176); raw scanning can only over-ask, which fails loud. A live witness, a reference that exists only in a comment, pins the extraction. A propagation-lane head (`mergepath-sync/*`) selects the complete surface on every repo. Unknown CI implementation paths fail closed to the complete surface, while prose beside the implementation (`scripts/**/*.md`, `tests/*.md`) requests nothing by shape. The classifier emits one JSON array of selected wrapper names plus three explicit bits: `full`, `consumer_replay`, and `self_tests` (true when the selection is full or names a wrapper in the graph's `self_tests` list, which must equal the suites the workflow enrols); consumers must not reconstruct dependencies with source-text greps.

On a consumer checkout, which the classifier recognizes by the absence of BOTH hub markers (`scripts/sync-to-downstream.sh` and `.mergepath-sync.yml`), the rules narrow. A consumer's deep lane is only the kit's `--self-test` suites: the consumer-safety and residue harnesses SKIP there, and the self-tests build their own fixtures instead of reading the repository. Consumers also keep their own product files under `specs/`, `tests/`, `scripts/` and `docs/agents/`. So, in consumer mode, the governance-document triggers request no deep lane at all, `consumer_replay` is always false because the replay harness has nothing to run there, and the unknown-path catch-all covers only the kit-delivered CI shapes: `.github/`, `scripts/{ci,lib,workflow,hooks,phase-4b,gh-projects}/`, top-level `scripts/*.sh` and `scripts/*.cjs`, `tests/test_*` and `tests/fixtures/`. Consumer-local specs, app tests, `.mjs` scripts and app source take the fast lane. Direct wrapper changes, declared dependencies and non-pull-request events behave exactly as on the hub, and a checkout carrying either marker keeps the hub rules. On the hub, `tests/test_repo_lint_optimization.sh` checks every path in `.mergepath-sync.yml`: any delivered path the hub sends to deep CI must also be deep in consumer mode unless it is one of those governance documents, so a newly delivered shape cannot silently fall onto the consumer fast lane.

## Required result

`lint-fast` always runs the live repository assertions. The deep lane is three jobs whose display names share the `deep-safety (...)` prefix the latency audit keys on, each selected by one scope bit and each carrying the same kit-less setup and `.git/config` hygiene bookends. `deep_safety` runs the `consumer` and `residue` matrix legs whenever `deep=true`: the consumer leg runs the consumer-safety harness in smoke mode (its `REPO_LINT_FULL` is pinned false, so it replays only the classifier's selected wrappers on the consumer-shaped fixture and always executes the structural #979/#1256 guards over every wired step), and the residue leg receives the full/checks selection and probes the selected wrappers' lattice while retaining its cheap structural/non-vacuity assertions. `deep_consumer_replay` runs only when `consumer_replay=true` and replays every wired wrapper with `REPO_LINT_FULL=true`, sharded over three independent fixture copies by `REPO_LINT_SHARD=<index>/3`: the harness orders the wired wrappers measured-heavy first (its `REPLAY_HEAVY` list, in descending replay cost, then the sorted tail), the shared selector numbers that order and each leg runs those its round-robin shard owns, so the shards partition the set, the heaviest wrappers land one per shard, and the replay's critical path is one shard rather than the whole set. `deep_self_tests` runs only when `self_tests=true` and splits the enrolled `--self-test` suites over a `phase-4b` leg (Phase 4b automation and accounting), a `coderabbit` leg (CodeRabbit wait with the nudge, auto-clear, publisher and projects suites) and a `gates` leg (token output, documentation ownership, merge clearance and Cockpit), every step pinned to exactly one leg and the two slowest suites on different legs, so the critical path is the slowest single suite. A full selection executes every wrapper and every enrolled self-test. An always-running aggregator publishes the required `lint` result and fails unless the fast lane succeeds and every deep job has the result its scope bit requires: a selected job must have succeeded (a failure, a cancellation, or an unexpected skip all fail) and an unselected job must have been skipped. A skipped job satisfies branch protection on its own, so this aggregator table is the only place the lane's completeness is asserted, and path filtering never leaves branch protection waiting for a missing required context.

`lint-fast` is itself a matrix of two to four integer shards, declared once on the job with `fail-fast: false` and a job timeout, and never carrying a job-level condition, so it cannot be skipped. Every check step is pinned to exactly one shard with `if: matrix.shard == N`; the setup prelude (checkout, making the kit executable, the `.git/config` snapshot, Python and yq provisioning) carries no pin and runs on every shard, so each leg is a complete, self-contained copy of the single serial job minus the checks pinned elsewhere. The pins are balanced by measured per-step time from the Actions jobs API, not by subject, and are re-balanced by moving pins when the measured sums drift. Sharding moves no assertion: the set of checks executed per head is unchanged, and the consumer soft-pass tails are unchanged. A pin naming a shard outside the matrix would run nowhere, and an unpinned check would run on every leg, so the regression contract asserts that every check step is pinned, that every pin resolves to a declared shard, and that every declared shard carries at least one check.

The #777 identity-hygiene pair is per-shard. Every leg records its own `.git/config` baseline in its first steps and closes with `check_git_identity_hygiene`: the plain call (live identity assertion, baseline comparison, the tracked-tree scan, and the paired regression suite) runs on one shard, and every other shard closes with `--verify`, which re-runs only the live identity assertion and the byte-comparison against that leg's own baseline. The scan and the suite read the checkout, which is identical on every leg, so they are asserted once; the invariant that the suites a runner executed left `.git/config` untouched is per-runner and is asserted on every leg. `--verify` fails closed when no snapshot was recorded for the checkout or its baseline is gone. The two closing steps are pinned `==` and `!=` to the same shard number and are the job's final two steps, so exactly one of them is the last step on every leg.

The aggregator reads the matrix job's rolled-up `needs.lint_fast.result` and passes only on `success`; a failed, cancelled, or skipped shard fails the required `lint` context. The regression contract executes the published aggregator step body under the result table GitHub can hand it rather than inspecting its text.

The token-output gate uses `--scan` in the fast lane and `--self-test` in deep CI. Documentation ownership and auto-clear workflow validation use `--check` in the fast lane and `--self-test` in deep CI, keeping live workflow assertions required while moving their implementation fixture suites off unrelated pull requests' critical path. The complete consumer simulation runs on every push to `main`, on the daily schedule and manual dispatch, on propagation-lane heads, and on pull requests that change a `full_triggers` or `consumer_replay_triggers` input or an undeclared CI implementation path; other deep pull requests get the consumer smoke mode. The residue lattice remains a deep-CI check on every deep selection. Consumer simulation recognizes only a wrapper's canonical `<check>: SKIP (...)` line as a skipped verdict; nested test output containing `SKIP` does not change the wrapper result.

### Budget

The deep/governance p95 budget is 12 minutes (`--deep-p95-max 720` in `.github/workflows/repo-lint-latency.yml`), unchanged by #1655. Measured on 2026-10-13 (run 38433656174, serial `deep-safety (consumer)` leg: 26 minutes), the critical path is now bounded by the slowest single step rather than the sum. On the first run of this model (PR #2172, run 38451869092, a full selection) the legs took: phase-4b 591s (automation 409s, accounting 82s), gates 725s before the three-way split (CodeRabbit wait 268s, merge clearance 91s, documentation ownership 89s, token output 85s, Cockpit 40s), replay shards 294s/604s/229s before heavy-first ordering (check_codex_scripts 164s and check_gh_as_author 144s shared a shard), residue 324s, consumer smoke 121s; every leg pays about 100s for the final `check_git_identity_hygiene` suite plus about 15s of setup. The deep lane's critical path fell from 26 minutes to about 10 minutes and the run was bounded by `lint-fast` (1161s, #2163). Over the 60 pull requests merged before the change, 57 selected the full surface; the narrowed triggers and extended graph select it for 26, the complete replay for 30, and the self-test legs only when an enrolled suite is affected. No suite, wrapper, assertion, or harness probe was removed: the complete replay moved from every deep pull request to the triggers above and the main/scheduled backstop, and the remaining pull requests replay exactly the wrappers whose declared inputs changed.

The token-output gate's owning contract and execution-oracle corpus live in `scripts/ci/token_output_gate.py`. `printf -v NAME` and `printf -vNAME` assign only in option position before the format and `--`; operand-position spellings emit. The owner-ratified attached exemption is an allowlist: a target matching `^[a-z_][a-z0-9_]*$` except `_`, `auto_resume` and `histchars`; a literal format containing only `%s` conversions/plain text; literal values or one double-quoted plain ordinary-name expansion without modifiers, subscripts or arithmetic; no assignment prefix, redirection or wrapper; and the existing in-file builtin-provenance check. Other attached spellings remain conservative, and safe rejected forms carry written corpus declarations. The separate `-v NAME` and numeric-diagnostic scope remains unchanged. Finite callback-option provenance detection and the existing bounded quoted-target reader are retained; managed-variable denylists and per-case arithmetic/error/heredoc lexer annotations are removed. The scanner does not prove ambient shell state: imported `printf` functions can emit otherwise allowed arguments, and the noninteractive oracle does not settle terminal-only output. Those are explicit owner-accepted residuals. Existing captured diagnostics [#2058](https://github.com/nathanjohnpayne/mergepath/issues/2058), invalid-name indirection [#2059](https://github.com/nathanjohnpayne/mergepath/issues/2059) and separate-option diagnostic [#2061](https://github.com/nathanjohnpayne/mergepath/issues/2061) limits remain declared.

The token-output gate recognizes completed `name()` and `function name` headers whose brace or subshell body opens on a following line, including after inline or intervening shell comments. Helper discovery and function-body line spans consume the same matcher; function-local `set +x` receives no credit whether the function is called or uncalled. The called fixture is declared conservatism, not an invocation or control-flow model. Header parentheses are not mistaken for an empty body, and a header without a following compound command is not a definition. Multiline quoted data and real comment text are excluded using existing lexer context, including offsets remapped from child substitutions. Already-lexed executable substitutions inside interpolating heredocs remain discoverable while surrounding heredoc data, quoted delimiters and nested heredoc data stay masked. The separately measured preexisting adjacent-comment/unmatched-quote lexer limit remains declared under [#2080](https://github.com/nathanjohnpayne/mergepath/issues/2080).

Token-output helper discovery retains every recognized body per name and applies the existing emitter fixed point to all retained bodies (#1467). A name is emitting if any recognized body emits, including through another promoted helper. All-safe definitions and chains remain clean. The owning module documents and measures conservative findings when textual emitting definitions occur after a call, in a false branch, or before an executed safe redefinition; it does not infer invocation, control flow, definition execution or runtime lookup.

The fast `check_pr_review_policy_nudge --check` assertion requires the Label Gate job's literal JavaScript blocking-label array to equal the literal alternatives in `mergepath_is_blocking_label` in `scripts/lib/blocking-labels.sh`. Adding or removing a label on either surface alone fails with the named `blocking-label parity` diagnostic. An unreadable, empty, ambiguous or unrecognized representation also fails; the assertion reads both sources as data and executes neither. The two definitions remain separate so Label Gate retains its current inline execution and trust boundary. Deep CI runs the add/remove mutations on each surface in `tests/test_pr_review_policy_nudge.sh` and the real workflow behavior tests in `tests/test_label_gate_live_labels.sh`. The dependency graph includes the shell predicate so changing that surface selects the paired regression suite.

## Local pre-push mirror

`scripts/git-hooks/pre-push`, installed per clone by `scripts/install-git-hooks.sh` (`core.hooksPath`, local config only), runs `scripts/repo-lint-prepush.sh` before a push (#2221). It is hub-only: neither file is in `.mergepath-sync.yml`, the runner soft-passes on a checkout without the classifier or the workflow, and the hook passes where the runner is absent. The runner diffs each pushed branch against its merge base with the remote default branch (a push to the default branch is classified as a `push` event, and a missing merge base fails closed to the complete selection, as the scope job does for an unavailable diff), feeds the paths to `scripts/ci/repo-lint-scope.sh`, and derives the steps and their `run:` bodies from this workflow. Fast-lane steps whose wrapper is not graph-declared always run; graph-declared wrappers run when the scope job's `checks` names them or `full` is set, and with `MERGEPATH_PREPUSH_LIVE=all` otherwise; the selected deep-lane steps run only on `MERGEPATH_PREPUSH_DEEP=1`. Setup steps and the per-runner identity-hygiene bookends are not run locally. Because the checks run on the checkout, a hook run refuses a pushed tip other than `HEAD` and uncommitted changes to tracked files, and it treats missing CI tooling (ShellCheck, PyYAML, and markdown-it-py when the deep lane runs) as an environment error rather than letting checks skip their assertions. The hook never replaces the required `lint` context. `tests/test_repo_lint_prepush.sh`, wired in the fast lane through `check_repo_lint_prepush`, executes the scope job's classify step and an independent evaluator of every job and step `if:` expression on the same fixture pushes and requires the hook's plan to cover exactly the check steps CI executes, its deep lane to equal CI's, and its selected wrappers to equal the scope job's `checks`.

## Approval coordination

An approval records merge readiness in GitHub's review state; it does not reserve a runner while required checks execute. Candidate-controlled `pull_request` and `pull_request_review` jobs perform one-shot readiness probes with `github.token`; they reference none of `AUTHOR_MERGE_TOKEN`, `MERGE_QUEUE_POLICY_TOKEN`, or `MERGE_QUEUE_SOURCE_TOKEN`, and any armed state fails closed there. Successful canonical repo-lint, optional local-annex, and policy-gate completions re-enter trusted default-branch `workflow_run` continuation, while the five-minute scheduled sweep remains the backstop for a consumer annex whose display name cannot be enumerated. Those trusted jobs bind `merge-queue-policy` before receiving its three pairwise-distinct environment-only secrets. Each entry resolves the live PR by number or exact head SHA. Dependabot short-circuits to its separately governed durable lane. For every other PR, trusted continuation verifies all three credentials and the exact governing policy, revalidates a latest-state registered reviewer approval plus current-head checks, and runs merge clearance, complete feedback accounting, zero unresolved conversations, and #1099. An existing arm survives only when the policy token proves the exact active target rulesets, protected environment, complete repository/inherited-organization/environment secret inventories, and branch protection; the source token proves both exact disabled source workflows; both read tokens resolve to the governing author; and the latest live arm has one exact authorization marker. Every other armed result stops without mutation for human/admin disposition. GitHub provides no conditional disable or compare-and-swap primitive, so continuation never calls `--disable-auto`, creates or refreshes an arm, enqueues, dequeues, directly merges, or mutates protection.

Issue #1058's target-side trusted-default-branch `pull_request_target` observer, protected target `repository_dispatch` final auditor, and two external organization required workflows are canonical in [`merge_group_required_checks.md`](merge_group_required_checks.md). The observer handles `auto_merge_enabled` and `enqueued`, writing respectively the exact-head authorization marker and exact queue-entry attestation after stable live administrative checks. Administrator topology/activation and arm-policy proofs establish the exact target/`main` ruleset scope, no-bypass state, exact environment policy, and complete three-scope secret placement. The required authorization workflow's pull-request admission uses read-only `github.token`; it binds both rulesets and both source-pinned workflows, treats draft state neutrally, and rejects SHA-like head names, stack members, and every target `.github/workflows/**` destination or rename source before queue admission. On a group, read-only exact-target-base precheck and postcheck jobs surround one exact-SHA source-pinned handshake with the sole job-scoped `contents: write`. That job fetches the public source without credentials, sends exactly one nonce-bound same-repository dispatch, and never retries ambiguous delivery. The protected target auditor applies exact actor/repository/action/`main`/base/workflow guards before its three pairwise-distinct environment-only credentials, re-reads private topology/action/queue state, and writes the unique author marker; the observer and auditor are the only #1058 author-token writers. The handshake accepts only that marker plus an exact successful time-bound auditor run, then postcheck replays all public predicates and the final binding. The external repo-lint workflow supplies lint on the same PR and group surfaces. From handoff through native merge, all mutable administrative, public-source, rollout, PR/review/comment/thread/accounting, check/status, queue/action, default-base, and group inputs stay frozen; any mutation ejects or aborts and requires a fresh owner action/group. Target-base executable trust is transitive through the prior pinned bridge; neither external workflow nor either target writer is a queue controller or merge mutator. Rollout is human-only. It activates the organization workflow ruleset before the repository queue ruleset and removes them in reverse order; no agent merges, arms, enqueues, or removes `human-hold`.

This event-driven path does not treat CodeRabbit as an additional merge requirement after a registered reviewer has approved. CodeRabbit's required-severity and conversation state remain represented by their existing required gates; advisory review arrival is not polled by a runner.

## Latency telemetry

`.github/workflows/repo-lint-latency.yml` runs daily and on manual dispatch from the trusted default branch. `scripts/repo-lint-latency-report.sh` asks the Actions API for the most recent completed `repo-lint` workflow runs in the closed `created` range from the window start through `--as-of` (or computed now), and their job/step timing records. It re-applies both time bounds locally, retains the selected raw workflow-run list and complete per-run job responses, writes normalized run data plus JSON and Markdown summaries, publishes the Markdown to the Actions job summary, and uploads that evidence as a retained artifact.

An ordinary pull-request sample is a successful `pull_request` run with no active `deep-safety` job. A deep/governance sample is a successful `pull_request` run with at least one active `deep-safety` job. The report uses nearest-rank percentiles and requires at least 20 samples in a segment before enforcing ordinary p50 <= 5 minutes, ordinary p95 <= 8 minutes, and deep/governance p95 <= 12 minutes. A smaller sample is visible as `insufficient-sample`, not a false regression. Distinct workflow run IDs on the same head SHA are a duplicate-execution alert when the eligible `pull_request`/`push` group contains at least one pull-request run, even when one duplicate failed or was cancelled. Repeated scheduled or manually dispatched backstops on an unchanged SHA are not duplicates. Threshold or duplication alerts fail the scheduled audit while preserving the summary and artifact; collection and configuration failures are reported separately from audit alerts.

An audit verdict is also routed to one tracked issue by `scripts/repo-lint-latency-issue.sh` (#2165). On an alert the workflow opens an issue labelled `area:ci-infra` and `audit`, or refreshes the existing open one in place; the lookup reads the complete open-issue list with `--paginate`, keeps only issues (not pull requests) opened by the workflow identity (`github-actions[bot]`, configurable with `--author`) whose body carries the hidden `<!-- mergepath-repo-lint-latency-audit -->` marker — never the title, and never a marker planted by another author — and the lowest-numbered match wins. The body is rewritten on every alerting run, and a comment is posted only when the set of alerts changes, so daily refreshes do not post daily comments. That comment is posted before the body refresh; if it fails, the refreshed body keeps the previous alert set in its marker so the next run retries the comment, and the step fails. On a clean verdict every open tracking issue receives a recovery comment and is closed. A collection failure (any exit other than 0 or 1) produces no verdict and leaves the issue untouched. The run still fails while the alert stands. A failed dedupe read or a failed write fails the routing step rather than opening a duplicate or reporting nothing; labels are read with `--paginate` (a bounded list would misread a label beyond it as missing), and a label that cannot be ensured or re-applied degrades the filter, never the dedupe, and fails the step after the issue is written. The routing step runs under `always()` so a transient failure in the artifact upload cannot skip a produced verdict. Coverage: `tests/test_repo_lint_latency_report.sh`.

## Regression contract

`tests/test_repo_lint_optimization.sh` validates target trigger absence, concurrency, dependency selection, hub/consumer scope modes and consumer-mode completeness against the manifest, the four trigger classes and the `consumer_replay`/`self_tests` bits, the graph's self-test enrolment against the workflow and its declared test references against the wrapper sources, the shard selector's partition and fail-closed parsing, the three deep jobs' gating and leg pinning, the aggregator's result table (executed against every passing and failing combination, not grepped), the fast-lane shard matrix and its pins, the per-shard identity-hygiene closing pair, split gate modes, consumer verdict classification, and the event-driven approval continuation. `tests/test_git_identity_hygiene.sh` covers the `--verify` mode: Parts A and B only, against the recorded snapshot, failing closed without one. The #1058 structural checker additionally proves external required-workflow materialization, public exact-SHA source execution, read-only precheck/postcheck separation from the sole dispatch-only write job, protected target-auditor runtime guards, nonce/run binding, exact successful auditor evidence, and post-audit replay/final-fence behavior. `tests/test_655_repo_lint_local_observed.sh` retains exact-head and optional-annex semantics without requiring a runner-held wait.

Token-output callback discovery recognizes literal `mapfile` and `readarray` short-option bundles such as `-tC`, rescanning only the callback value as shell source. For a literal option prefix it stops at `--` or the array operand and consumes other options’ values without interpreting them as source. A proven literal option sequence selects only its final callback; unknown callback values or option prefixes retain the existing per-known-callback fallback. An unresolved prefix retains conservative rescanning of later known callbacks rather than inferring runtime option consumption or array lookup. The bounded extractor, execution-oracle cases and unchanged deferred-depth contract live in `scripts/ci/token_output_gate.py` (#1450).

Interpolating helper heredocs distinguish plain stdin DATA from executing expansions. Plain DATA is non-emitting only when existing literal builtin/classifier facts prove that boundary: existing proven argument-emitter facts other than echo do not forward their stdin, and SAFE storage/control builtin facts such as read store or discard it; default SAFE classification for an unknown external command is not proof. Known stdin consumers and unknown owners retain the existing bounded HD quote, escape, parameter-value and continuation distinction. Noninterpolating heredocs remain inert. Inside any inventoried actual command substitution—`$(...)`, backticks, Bash5.3 `${ command; }` or `${| command; }`—main's unchanged raw positional predicate is conservative regardless of command roles, inner quoting, output routes, helper invocation, unused arguments or positional binding. Arithmetic and parameter-error expansions outside command substitutions remain executing expansions with their existing bounded admission. The [owner substitution decision](https://github.com/nathanjohnpayne/mergepath/issues/1496#issuecomment-6156188282) replaces the former per-family alias/source/pipeline/tee/cardinality/diagnostic machinery and its private Lexer coordinate hooks; quiet substitution cases share one module-owned conservative class with explicit reasons. Ordinary Lexer and reader APIs/ASTs return to main; no parser, runtime role/binding/count/FD/stage model or additional child depth is introduced. All historical fixture bodies remain available; rules and disagreement declarations record the owner-directed change. Bash5.3 brace forms remain version-qualified because Bash5.2 rejects them, and the `${1:-unknown}`-only backtick case retains its explicitly declared inherited-main raw-regex miss. Compound-command heredoc ownership remains #1468. The contract and central structural controls live in `scripts/ci/token_output_gate.py` (#1496).

Resolved `echo` owners retain main's conservative helper-heredoc DATA behaviour, including `command echo`, `builtin echo`, and quoted, escaped or path forms that the existing resolver reduces to echo. The [superseding owner decision](https://github.com/nathanjohnpayne/mergepath/issues/1496#issuecomment-6158711314) removes echo from the inert owner set entirely. Plain echo and quiet echo-owner samples now share one module-owned conservative class: the scanner does not prove alias/function/source/eval/startup/builtin-enable/hash lookup state or whether the owner forwards stdin. The private identity/shopt/read-position/dispatch helpers and per-definition fourth field are removed rather than expanded. Existing printf inert precision remains unchanged, as do noninterpolating heredocs, escaped DATA and parameter-length controls. Ordinary Lexer/readers/alias APIs, the central substitution rule and deferred depth remain unchanged; no state, binding, command lookup, filesystem or execution model is added. Historical fixture bodies remain exact, with only owner-directed rule and declaration changes. The paired root scan identifies42 prior clean-to-flag rule changes;41 align with main, while the plain parameter-default DATA sample was missed by main's raw regex and is explicitly covered by the resolved-echo decision. The nine earlier quiet identity examples now share this same echo class; substitution conservatism remains separate. New source/dot/eval echo redefinitions and mirrored printf controls retain genuine fixture bodies. Startup bodies in ordinary corpus use its plain Bash PROLOGUE and are quiet conservative samples; independent native-shebang paired proof records their actual startup leakage. No native leak is attributed to that ordinary corpus sample. Echo's plain-DATA fallback excludes already inventoried actual command-substitution spans, so it cannot introduce a parameter fallback after the raw predicate has missed a modifier. Four quiet colon-command controls pin dollar, backtick and both brace boundaries; direct plain parameter-default DATA remains conservative. Existing arithmetic and parameter diagnostics outside those command spans retain their bounded admission.

The superseding owner direction retains the inherited main positional-regex miss: `${ echo "${1:-fallback}" >&2; }` in an interpolating helper heredoc. Main9f, the structural cut and the signed echo repair all miss its sampled Bash5.3 leak; Bash5.2 rejects the syntax. Its exact fixture remains in `KNOWN_MISSES`, with only that entry's stale-miss assertion and summary qualified below Bash5.3. The [structural decision](https://github.com/nathanjohnpayne/mergepath/issues/1496#issuecomment-6156188282) keeps the raw substitution predicate unchanged; no parameter fallback is introduced.

The token-output gate uses one shared direct/deferred trace detector for `set -eo xtrace`, `set -euo xtrace`, `shopt -s -o xtrace` and `shopt -os xtrace`. Named set-option operands and positional delimiters retain their boundaries; unrelated options and shopt query-only modes do not imply tracing. This enabling repair preserves existing standalone disable handling and its function/conditional asymmetry, without granting new shopt or bundled named-option disable credit.
