# Repo-lint execution model

## Purpose

The `repo-lint` workflow preserves one stable required context named `lint` while avoiding duplicate work and keeping exhaustive regression nets off unrelated pull requests' critical path.

## Event contract

Target-repository pull-request heads run through `pull_request` only. Feature-branch pushes do not start a second copy of `repo-lint`, Markdown prose wrapping, or OWL validation. A `push` run is retained for `main`, and pull-request concurrency cancels an older in-progress head when a newer commit arrives. The target repository contains zero `merge_group` triggers. For #1058, a separately protected organization-owned public policy repository materializes the required repo-lint workflow beside the authorization workflow. The organization workflow ruleset binds both by source repository id, exact path, protected ref, and full SHA; a distinct target-repository ruleset supplies the native singleton merge queue. Public source visibility is mandatory for every target visibility because authorization's sole write-authority handshake fetches its exact SHA without credentials. The external repo-lint workflow supplies the pull-request and synthetic merge-group lint results without letting target content define its own group trigger. Scheduled and manually dispatched target runs remain deep CI in Mergepath and in consumers that carry the canonical `scripts/ci/` kit; kit-less consumers have no deep implementation to execute. A missing wired wrapper soft-passes only where the hub-only `scripts/sync-to-downstream.sh` marker is also absent; the same absence on the hub fails the step.

## Scope classifier

`scripts/ci/repo-lint-scope.sh` is the single scope decision. A pull request enters deep CI when it changes CI workflows, scripts, tests, specifications, rules, agent operating documentation, architecture decisions, either repository manifest, `AGENTS.md`, `REVIEW_POLICY.md`, or `ai_agent_tooling_standard.md`. Other pull requests use the fast lane. An unreadable pull-request diff fails closed to deep CI, and every non-pull-request event is deep once the canonical `scripts/ci/` kit is present. A consumer checkout that intentionally or temporarily lacks that kit emits `deep=false` because it has no deep check implementation to execute; the hub fails instead of taking this exception.

The classifier reads `scripts/ci/repo-lint-dependencies.json`, the machine-readable dependency graph for expensive wrapper checks. A direct change to `scripts/ci/check_<name>` selects that wrapper. A dependency named by the graph selects every wrapper that owns it. Changes to the classifier, graph, workflow, deep-safety harnesses, propagation contract, or governance-wide inputs select the complete deep surface. Unknown CI implementation paths also fail closed to the complete surface. The classifier emits one JSON array of selected wrapper names plus an explicit `full` bit; consumers must not reconstruct dependencies with source-text greps.

On a consumer checkout, which the classifier recognizes by the absence of BOTH hub markers (`scripts/sync-to-downstream.sh` and `.mergepath-sync.yml`), two of those rules narrow. A consumer's deep lane is only the kit's `--self-test` suites: the consumer-safety and residue harnesses SKIP there, and the self-tests build their own fixtures instead of reading the repository. Consumers also keep their own product files under `specs/`, `tests/`, `scripts/` and `docs/agents/`. So, in consumer mode, the governance-document full triggers (`specs/*`, `rules/*`, `docs/agents/*`, `docs/architecture/*`, `AGENTS.md`, `REVIEW_POLICY.md`, `ai_agent_tooling_standard.md`, `.repo-template.yml`) no longer force the complete surface, and the unknown-path catch-all covers only the kit-delivered CI shapes: `.github/`, `scripts/{ci,lib,workflow,hooks,phase-4b,gh-projects}/`, top-level `scripts/*.sh` and `scripts/*.cjs`, `tests/test_*` and `tests/fixtures/`. Consumer-local specs, app tests, `.mjs` scripts and app source take the fast lane. Direct wrapper changes, declared dependencies and non-pull-request events behave exactly as on the hub, and a checkout carrying either marker keeps the hub rules. On the hub, `tests/test_repo_lint_optimization.sh` checks every path in `.mergepath-sync.yml`: any delivered path the hub sends to deep CI must also be deep in consumer mode unless it is one of those governance documents, so a newly delivered shape cannot silently fall onto the consumer fast lane.

## Required result

`lint-fast` always runs the live repository assertions. The consumer and residue legs of the `deep-safety` matrix run in parallel only when the scope output is `deep=true`; the single matrix declaration keeps their isolated fixtures from duplicating workflow setup logic. For a partial deep selection, both harnesses receive the classifier's wrapper array and execute only those wrappers while retaining their cheap structural/non-vacuity assertions. A full selection executes every wrapper and every enrolled self-test. An always-running aggregator publishes the required `lint` result and fails unless the fast lane succeeds and the matrix has the result appropriate to the selected scope. Path filtering therefore never leaves branch protection waiting for a missing required context.

The token-output gate uses `--scan` in the fast lane and `--self-test` in deep CI. Documentation ownership and auto-clear workflow validation use `--check` in the fast lane and `--self-test` in deep CI, keeping live workflow assertions required while moving their implementation fixture suites off unrelated pull requests' critical path. The complete consumer simulation and residue lattice remain deep-CI checks. Consumer simulation recognizes only a wrapper's canonical `<check>: SKIP (...)` line as a skipped verdict; nested test output containing `SKIP` does not change the wrapper result.

The token-output gate's owning contract and execution-oracle corpus live in `scripts/ci/token_output_gate.py`. `printf -v NAME` and `printf -vNAME` assign only in option position before the format and `--`; operand-position spellings emit. The owner-ratified attached exemption is an allowlist: a target matching `^[a-z_][a-z0-9_]*$` except `_`, `auto_resume` and `histchars`; a literal format containing only `%s` conversions/plain text; literal values or one double-quoted plain ordinary-name expansion without modifiers, subscripts or arithmetic; no assignment prefix, redirection or wrapper; and the existing in-file builtin-provenance check. Other attached spellings remain conservative, and safe rejected forms carry written corpus declarations. The separate `-v NAME` and numeric-diagnostic scope remains unchanged. Finite callback-option provenance detection and the existing bounded quoted-target reader are retained; managed-variable denylists and per-case arithmetic/error/heredoc lexer annotations are removed. The scanner does not prove ambient shell state: imported `printf` functions can emit otherwise allowed arguments, and the noninteractive oracle does not settle terminal-only output. Those are explicit owner-accepted residuals. Existing captured diagnostics [#2058](https://github.com/nathanjohnpayne/mergepath/issues/2058), invalid-name indirection [#2059](https://github.com/nathanjohnpayne/mergepath/issues/2059) and separate-option diagnostic [#2061](https://github.com/nathanjohnpayne/mergepath/issues/2061) limits remain declared.

The token-output gate recognizes completed `name()` and `function name` headers whose brace or subshell body opens on a following line, including after inline or intervening shell comments. Helper discovery and function-body line spans consume the same matcher; function-local `set +x` receives no credit whether the function is called or uncalled. The called fixture is declared conservatism, not an invocation or control-flow model. Header parentheses are not mistaken for an empty body, and a header without a following compound command is not a definition. Multiline quoted data and real comment text are excluded using existing lexer context, including offsets remapped from child substitutions. Already-lexed executable substitutions inside interpolating heredocs remain discoverable while surrounding heredoc data, quoted delimiters and nested heredoc data stay masked. The separately measured preexisting adjacent-comment/unmatched-quote lexer limit remains declared under [#2080](https://github.com/nathanjohnpayne/mergepath/issues/2080).

Token-output helper discovery retains every recognized body per name and applies the existing emitter fixed point to all retained bodies (#1467). A name is emitting if any recognized body emits, including through another promoted helper. All-safe definitions and chains remain clean. The owning module documents and measures conservative findings when textual emitting definitions occur after a call, in a false branch, or before an executed safe redefinition; it does not infer invocation, control flow, definition execution or runtime lookup.

The fast `check_pr_review_policy_nudge --check` assertion requires the Label Gate job's literal JavaScript blocking-label array to equal the literal alternatives in `mergepath_is_blocking_label` in `scripts/lib/blocking-labels.sh`. Adding or removing a label on either surface alone fails with the named `blocking-label parity` diagnostic. An unreadable, empty, ambiguous or unrecognized representation also fails; the assertion reads both sources as data and executes neither. The two definitions remain separate so Label Gate retains its current inline execution and trust boundary. Deep CI runs the add/remove mutations on each surface in `tests/test_pr_review_policy_nudge.sh` and the real workflow behavior tests in `tests/test_label_gate_live_labels.sh`. The dependency graph includes the shell predicate so changing that surface selects the paired regression suite.

## Approval coordination

An approval records merge readiness in GitHub's review state; it does not reserve a runner while required checks execute. Candidate-controlled `pull_request` and `pull_request_review` jobs perform one-shot readiness probes with `github.token`; they reference none of `AUTHOR_MERGE_TOKEN`, `MERGE_QUEUE_POLICY_TOKEN`, or `MERGE_QUEUE_SOURCE_TOKEN`, and any armed state fails closed there. Successful canonical repo-lint, optional local-annex, and policy-gate completions re-enter trusted default-branch `workflow_run` continuation, while the five-minute scheduled sweep remains the backstop for a consumer annex whose display name cannot be enumerated. Those trusted jobs bind `merge-queue-policy` before receiving its three pairwise-distinct environment-only secrets. Each entry resolves the live PR by number or exact head SHA. Dependabot short-circuits to its separately governed durable lane. For every other PR, trusted continuation verifies all three credentials and the exact governing policy, revalidates a latest-state registered reviewer approval plus current-head checks, and runs merge clearance, complete feedback accounting, zero unresolved conversations, and #1099. An existing arm survives only when the policy token proves the exact active target rulesets, protected environment, complete repository/inherited-organization/environment secret inventories, and branch protection; the source token proves both exact disabled source workflows; both read tokens resolve to the governing author; and the latest live arm has one exact authorization marker. Every other armed result stops without mutation for human/admin disposition. GitHub provides no conditional disable or compare-and-swap primitive, so continuation never calls `--disable-auto`, creates or refreshes an arm, enqueues, dequeues, directly merges, or mutates protection.

Issue #1058's target-side trusted-default-branch `pull_request_target` observer, protected target `repository_dispatch` final auditor, and two external organization required workflows are canonical in [`merge_group_required_checks.md`](merge_group_required_checks.md). The observer handles `auto_merge_enabled` and `enqueued`, writing respectively the exact-head authorization marker and exact queue-entry attestation after stable live administrative checks. Administrator topology/activation and arm-policy proofs establish the exact target/`main` ruleset scope, no-bypass state, exact environment policy, and complete three-scope secret placement. The required authorization workflow's pull-request admission uses read-only `github.token`; it binds both rulesets and both source-pinned workflows, treats draft state neutrally, and rejects SHA-like head names, stack members, and every target `.github/workflows/**` destination or rename source before queue admission. On a group, read-only exact-target-base precheck and postcheck jobs surround one exact-SHA source-pinned handshake with the sole job-scoped `contents: write`. That job fetches the public source without credentials, sends exactly one nonce-bound same-repository dispatch, and never retries ambiguous delivery. The protected target auditor applies exact actor/repository/action/`main`/base/workflow guards before its three pairwise-distinct environment-only credentials, re-reads private topology/action/queue state, and writes the unique author marker; the observer and auditor are the only #1058 author-token writers. The handshake accepts only that marker plus an exact successful time-bound auditor run, then postcheck replays all public predicates and the final binding. The external repo-lint workflow supplies lint on the same PR and group surfaces. From handoff through native merge, all mutable administrative, public-source, rollout, PR/review/comment/thread/accounting, check/status, queue/action, default-base, and group inputs stay frozen; any mutation ejects or aborts and requires a fresh owner action/group. Target-base executable trust is transitive through the prior pinned bridge; neither external workflow nor either target writer is a queue controller or merge mutator. Rollout is human-only. It activates the organization workflow ruleset before the repository queue ruleset and removes them in reverse order; no agent merges, arms, enqueues, or removes `human-hold`.

This event-driven path does not treat CodeRabbit as an additional merge requirement after a registered reviewer has approved. CodeRabbit's required-severity and conversation state remain represented by their existing required gates; advisory review arrival is not polled by a runner.

## Latency telemetry

`.github/workflows/repo-lint-latency.yml` runs daily and on manual dispatch from the trusted default branch. `scripts/repo-lint-latency-report.sh` asks the Actions API for the most recent completed `repo-lint` workflow runs and their job/step timing records, retains the selected raw workflow-run list and complete per-run job responses, writes normalized run data plus JSON and Markdown summaries, publishes the Markdown to the Actions job summary, and uploads that evidence as a retained artifact.

An ordinary pull-request sample is a successful `pull_request` run with no active `deep-safety` job. A deep/governance sample is a successful `pull_request` run with at least one active `deep-safety` job. The report uses nearest-rank percentiles and requires at least 20 samples in a segment before enforcing ordinary p50 <= 5 minutes, ordinary p95 <= 8 minutes, and deep/governance p95 <= 12 minutes. A smaller sample is visible as `insufficient-sample`, not a false regression. Distinct workflow run IDs on the same head SHA are a duplicate-execution alert when the eligible `pull_request`/`push` group contains at least one pull-request run, even when one duplicate failed or was cancelled. Repeated scheduled or manually dispatched backstops on an unchanged SHA are not duplicates. Threshold or duplication alerts fail the scheduled audit while preserving the summary and artifact; collection and configuration failures are reported separately from audit alerts.

## Regression contract

`tests/test_repo_lint_optimization.sh` validates target trigger absence, concurrency, dependency selection, hub/consumer scope modes and consumer-mode completeness against the manifest, the stable aggregator, split gate modes, consumer verdict classification, and the event-driven approval continuation. The #1058 structural checker additionally proves external required-workflow materialization, public exact-SHA source execution, read-only precheck/postcheck separation from the sole dispatch-only write job, protected target-auditor runtime guards, nonce/run binding, exact successful auditor evidence, and post-audit replay/final-fence behavior. `tests/test_655_repo_lint_local_observed.sh` retains exact-head and optional-annex semantics without requiring a runner-held wait.

Token-output callback discovery recognizes literal `mapfile` and `readarray` short-option bundles such as `-tC`, rescanning only the callback value as shell source. For a literal option prefix it stops at `--` or the array operand and consumes other options’ values without interpreting them as source. A proven literal option sequence selects only its final callback; unknown callback values or option prefixes retain the existing per-known-callback fallback. An unresolved prefix retains conservative rescanning of later known callbacks rather than inferring runtime option consumption or array lookup. The bounded extractor, execution-oracle cases and unchanged deferred-depth contract live in `scripts/ci/token_output_gate.py` (#1450).

Helper arguments, error words and interpolating heredoc bodies use one positional-value decision; exact positional `@a` is attributes-only, while `@A` and `@Q` retain existing value-transform admission. Heredoc quotes are literal, and backslash quotes only dollar, backtick, backslash and newline; unescaped continued lines join before positional expansion is read. Actual backtick substitution bodies remove their source escape layer before the ordinary positional decision; plain heredoc escapes and modern substitution source remain distinct. The paired form with two backslashes in backtick source retains its explicitly measured existing conservative verdict rather than widening general tokenization. Actual substitution source reuses the existing literal deferred-operand extractor; discovered nested interpolating heredocs and deferred eval/trap/callback source share the existing one-hop child-inventory budget. Nested heredocs use the same owner/diagnostic admission and HD positional semantics. Current depth reaches child substitution readers without reset; ordinary source checks and legacy conservative reading retain their order. A real leaking depth-two nested-backtick HD sample is declared outside that inventory budget, while other deeper spellings may remain conservatively admitted by existing source reading. Direct body DATA retains conservative known-stdin-consumer admission and the existing fail-closed classification for unresolved or opaque owners. A source-only owner cannot prove its runtime stdin behavior; safe/quiet opaque bindings are declared conservative, while literal nonopaque printf/echo/read bodies retain their inert or storing boundary. Quiet cat/tee shadow and command-report cases remain measured conservatisms, deferred to #1052 item 3: textual declarations cannot prove active runtime bindings, and a catalog veto loses late-definition, false-branch and restored-builtin emission. Heredoc continuations are normalized before independent substitution/error-word searches. The existing expansion inventory opts into modern `$((...))` and legacy `$[...]` positional arithmetic spans and substring/index operands for conservative diagnostic evidence. When the exact reader cannot prove the end of an actual command substitution, a bounded remaining-source inventory retains possible evidence, including quiet or inert tail data; it does not parse case grammar or claim that the entire tail executes. Legacy arithmetic uses existing bounded compound reading with nested brackets; all actual arithmetic diagnostic operands retain heredoc quote/escape semantics. The diagnostic opt-in uses the existing escape-aware backtick reader and exact/compound error-word parameter bounds; quoted braces stay data while executable substitution programs keep ordinary source semantics. Positional and indirect named/positional error guards use the same HD-only default-false parameter-end opt-in for guard recognition and WORD-start calculation; length forms remain excluded and ordinary guard/span defaults stay unchanged. Arithmetic in actual substitution programs is inventoried from existing executable Lexer segment words using ordinary quote-aware expansion readers; only recognized arithmetic operands receive arithmetic positional semantics. Retained words are joined to preserve legacy arithmetic split by whitespace. Comments, inert nested HD data and literal/escaped program text stay outside that arithmetic context pass. Primitive arithmetic checking at reached source runs before the child-budget stop; HD and literal deferred children still share depth one, without reset. No arithmetic is evaluated; default callers remain unchanged. Independent substitution/error-word evidence remains discoverable for non-stdin owners. Captured or no-output substitution source retains explicitly measured helper-inventory conservatism, and deeper deferred programs retain the documented unmodeled boundary. The corpus pairs `${1:-unknown}`, direct `$1` and escaped `\$1`, plus quoted-delimiter and literal/escape controls. Existing parameter redaction and bounded exact/legacy reading remain applicable; no general parameter evaluation, input dataflow or compound-command heredoc ownership is introduced (#1496; compound ownership remains #1468).

Arithmetic-command and indexed-assignment diagnostics in actual HD substitution source additionally use an opt-in Lexer coordinate inventory (`arithmetic_contexts=False` by default). Only already-unquoted literal `((...))` command roles and literal-name indexed assignments followed by `=` or `+=` are recorded; existing compound/bracket bounds keep quoted or nested delimiters inside their operand. The existing command resolver reads a temporary tokenized prefix, including an in-progress literal reserved word at the arithmetic delimiter, rejecting assignment-looking arguments, quoted/escaped in-progress delimiter words and array-assignment DATA. Only recorded operands receive HD positional semantics at the current reached depth; RHS, later words, ordinary quoted source and comments retain their existing boundaries. This adds an optional constructor knob without changing default lexical output or ordinary reader APIs. Primitive checking precedes the unchanged one-hop child stop, with no depth reset, builtin arithmetic grammar or runtime evaluation. Measured nested-index, assignment-prefix and invalid redirection-prefix conservatisms, real second-deferred-child misses remain explicit. The same opt-in prefix check consumes only one raw literal `time` and optional raw `-p` after existing raw literal reserved words, then applies the unchanged resolver to the remainder. Quoted/escaped/wrapped time, unknown options and ordinary arguments stay excluded. Portable time/conditional/negation/index pairs are in the shared corpus; three literal time arithmetic forms leak on sampled macOS Bash 5.3.20 and are syntax-rejected on sampled Linux Bash 5.2.15, so their paired source admission and platform split remain separate evidence without unconditional disagreement declarations. The unchanged resolver may unquote later reserved-looking words (for example quoted `!` after time); its measured quiet conservatism remains qualified side evidence, and this coordinate inventory does not claim full pipeline grammar.

The token-output gate uses one shared direct/deferred trace detector for `set -eo xtrace`, `set -euo xtrace`, `shopt -s -o xtrace` and `shopt -os xtrace`. Named set-option operands and positional delimiters retain their boundaries; unrelated options and shopt query-only modes do not imply tracing. This enabling repair preserves existing standalone disable handling and its function/conditional asymmetry, without granting new shopt or bundled named-option disable credit. The module-owned oracle corpus records the conservative cases; the authoring PR records measured source hit-set deltas. Shopt `-p`/`-q` flags may accompany `-s` without cancelling enablement; an unresolved prefix conservatively retains later literal enable flags. A bundled set `-o` or `+o` consumes a known named operand, while an option-looking following word remains in the option stream. An actual unresolved word in the active set option stream may itself enable tracing or stop/abort parsing; the shared detector retains possible enablement at later positional stops and withholds subsequent disable credit within that command. It evaluates no runtime option values, including unresolved `+o` operands. Literal positional boundaries before the unresolved word still stop processing, missing `-o`/`+o` operands remain queries, and a lone shopt dash begins the option-name list rather than cancelling later `xtrace` evidence. Unresolved shopt words can supply missing flags or names, with non-enabling sampled values declared conservative. Named set options before invalid trailing letters retain written enable evidence; exact and bundled named operands use the same finite literal-name success proof before later disables, distinguishing `+ox` from `+xo`. This preserves the legacy short-x conservative claim and does not infer errexit or general error-path execution.

Known or conservatively retained active xtrace at an `eval`, literal `mapfile`/`readarray -C` callback or trap segment initializes the existing one-hop operand scan. This bridge adds no xtrace finding for untraced references or references after an inner disable credited by the existing standalone top-level disable handling; existing output-path analysis and command-boundary conservatism still apply. The recursion depth, discovery errors, pragma scope and opaque dynamic operands retain their existing behavior. This is a definition-site source check, not call-time trace analysis of earlier function/trap definitions, and independently scanned sourced files do not inherit the caller’s state. The bounded contract, paired oracle corpus and mechanism controls live in `scripts/ci/token_output_gate.py` (#1454). The existing bounded quoted-target reader uses the same recursive state bridge: a traced `printf -v'out[$(: "$GH_TOKEN")]'` now exposes the substitution’s real stderr leak, while `printf -v'out[$GH_TOKEN]'` retains its prior conservative finding under a clean letter-leading oracle sample. This adds no target eligibility, lookup or arithmetic model. Cross-seam oracle controls preserve the merged trace-option ordering and unresolved set/shopt predicates when their already-retained state enters the literal operand scan; safe sampled unknown values remain explicitly conservative. Already-retained deferred enable evidence reaches later segments on the same logical line through the existing lexer parent lineage, with added evidence local to the subshell or capture that enabled it. This source-order check does not infer function invocation, trap timing or callback input availability; the module-owned corpus declares the measured conservative cases.
