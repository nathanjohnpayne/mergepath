# Immutable Phase 4b Review Input

Every enabled Phase 4b run captures a coherent complete base/head pair from the PR API. A private isolated Git object store fetches those exact commit IDs, verifies them, computes their merge base, and generates one read-only binary full-index diff. The adapters require this supplied file and never query a mutable PR diff endpoint. A caller-supplied diff is accepted only when its byte digest equals the captured object-derived diff.

Git capture and curated-wave regeneration isolate Git configuration while preserving gh's existing configuration location and token environment. Credential resolution continues through the caller's existing gh context; snapshot isolation does not introduce a new credential source or hide credentials needed to read a private repository.

Propagation audits use a specialized `--wave-scope-file` request containing complete canonical range IDs and explicit historical mode. The trusted live verifier must bind the canary pair to that exact canonical head. Trusted wave code then independently regenerates the curated canonical diff or cumulative historical receipt package using the trusted hub policy and committed manifest. Capture mode cannot dispatch reviewers, publish receipts or advance watermarks. Supplied bytes must equal the regenerated payload; arbitrary alternate diffs remain rejected. The verdict records canonical scope and both the curated input and complete canary PR diff digests. The live verifier from #1546 must be installed before this path can run.

The reasoning model retains the existing strict verdict schema. After model validation, trusted adapter code adds the captured base, head, merge base, original diff digest, actual bounded review-diff digest and observed head-transition generation. The orchestrator validates that binding before acting on a verdict and records the commit IDs and digests in the posted review. Unbound standalone reasoning has no posting authority. Metadata or diff mutation, a changed head/base, unreadable generation evidence, and an observed A to B to A force-push cycle refuse the review write. The final review response must preserve the bound body and reviewed commit ID.

The real-object regression checks immutable A bytes while the mutable source branch names B. Lifecycle coverage executes the production orchestrator and verifies that an A to B to A cycle while the adapter runs posts no review, while unchanged authorized approval still posts. Existing policy byte-budget omissions remain explicit in the review; this change does not broaden their allowlist. Canonical propagation carries the helper and updated adapters together as part of the Phase 4b kit.

Curated-wave regression coverage uses a separate committed canonical repository, includes dirty working-tree bytes and hostile inherited scope overrides, and verifies the regenerated bytes and both digest fences. Wave capture coverage exercises ordinary diffs, a historical chunk, and cumulative receipt finalization while checking that no adapter runs and local/remote tags remain unchanged.

An explicit `--offline-diff --dry-run` preview freezes supplied regular-file bytes without live Git/transition capture and carries no postable review binding. It still validates the declared author and never posts. Final immutable-input revalidation precedes the final feedback-accounting read so feedback remains the last preparation observation before an approval POST.

The enablement collector reports an unavailable immutable input as a blocked dry-run result. Failure to allocate its private capture directory skips GitHub reads and adapter dispatch while preserving that structured report.
