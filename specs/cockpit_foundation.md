# Cockpit shared foundation

This foundation of #1586, part of #1585, provides the localhost security boundary, shared read client, source scheduler, repository inventory, SSE transport and shared visual shell. The shell follows the personally exercised runnable reference at design commit `4453251f`, its written specification and supplied fonts. No dependent panel provider or sync action is implemented here. Six sections honestly show unavailable data until their owning tickets register providers. Acceptance requires the integrated browser and hermetic evidence below, not the presence of files alone.

## Launch and credentials

`scripts/cockpit.sh [--agent codex|claude|cursor] [--port N]` consumes `scripts/op-preflight.sh --check --print-exports` only. It never reads 1Password, repairs a cache, invokes credential preflight interactively, or falls back to gh's keyring. Missing or stale cache stops launch. The resident Python server consumes the cached reviewer PAT only; the author PAT and ambient GitHub credentials are removed from its environment. Cache warming remains the ordinary operator-controlled preflight workflow in REVIEW_POLICY.md.

Python uses only its standard library. Repository inventory uses the hub's existing installed mikefarah/yq v4 executable once, without installation or bootstrap, to read the manifest's consumers. A fixed query and manifest path, ten-second subprocess timeout, output validation and an immutable tuple preserve the inventory. The hub is `nathanjohnpayne/mergepath`; the filter can select only that hub or a listed consumer. Malformed, empty, duplicate or unreadable consumer inventory refuses launch.

The launcher prints a clean `http://127.0.0.1:<bound-port>/` base URL identifying the bound service, and privately opens `/bootstrap` with a one-use nonce and a separate 256-bit random namespace in its fragment. The usable shell URL remains in that private browser tab; the printed unscoped base does not grant access. This intentionally differs from the ticket's literal “prints the session URL”: putting a session credential in console output would conflict with the stronger no-session-secrets-in-logs requirement. Browser opening detaches the opener's session and standard input/output; creation failure or a nonzero exit within ten seconds gives clean retry-launch guidance and never prints a nonce. An opener still running after that bound is accepted because Linux xdg-open may remain in the foreground until the browser exits; its timeout never kills the opener or healthy server. The namespace must match the fixed 43-character base64url grammar before interpolation. The entire fragment is removed before any await or network operation; successful bootstrap navigates to the private `/s/<namespace>/` root. The namespace is an independent capability, never derived from a port, cookie or nonce, and is redacted from provider data alongside session secrets. The nonce expires after two minutes and is consumed atomically. Relaunching creates fresh nonce, namespace, cookie and CSRF secrets.

## HTTP boundary

Except for the three bootstrap routes, the paths below are logical paths beneath the per-launch `/s/<namespace>/` prefix. Every protected shell, asset, API and SSE request requires both the exact secret prefix and the session cookie. Unscoped aliases and wrong prefixes return 404 without redirects or namespace disclosure, even with a replayed cookie. Cookies alone cannot isolate sibling ports: the independent path capability and scoped cookie Path prevent ordinary sibling requests from receiving this session and keep concurrent instances separate. Neither credentials nor namespace paths enter referrers or status-only logs. The shell, font URLs, fetch and native EventSource use relative paths within that prefix.

- Bind only `127.0.0.1`; there is no configurable host or remote variant.
- Accept exactly one Host header equal to `127.0.0.1:<bound-port>` or `localhost:<bound-port>`. Reject other hosts, duplicate headers, absolute request targets, malformed paths and cross-origin requests.
- The exact GET routes `/bootstrap` and `/bootstrap.js` are the sole pre-session exception. They expose only the transport document and script, with no operational data or embedded secrets. All ordinary API, SSE and static requests require the per-launch session cookie.
- POST `/api/bootstrap` authenticates the one-use nonce through `X-Cockpit-Bootstrap`, uses that same unguessable nonce as `X-Cockpit-CSRF`, and requires Origin to exactly match the request's permitted Host and scheme. It sets a distinct HttpOnly, SameSite=Strict, host-only cookie, scoped to `/s/<namespace>/`. Bootstrap first expires only a legacy same-name Path=/ cookie using a separate Set-Cookie field; it preserves other scoped-instance cookies and duplicate-name rejection. Plain HTTP on loopback prevents a portable Secure cookie; the server cannot bind remotely.
- Every non-GET request, including unsupported methods, requires same-origin Origin and CSRF. Ordinary non-GET requests also require the session cookie. Unsupported operations return 405 after validation. GET `/api/session` returns the CSRF value to an authenticated client, never the session credential or PAT.
- POST `/api/fleet/refresh` is a fixed read-only action after the same Host, session, Origin and CSRF checks. It accepts no body, query, source name or executable input. The launch-bound Fleet source alone is refreshed through the scheduler; duplicate requests coalesce and cannot bypass backoff. The browser coalesces concurrent refresh clicks, obtains CSRF from the scoped session endpoint and bounds the operation to ten seconds. It does not interpret successful dispatch as an audit observation.
- POST `/api/sync/preview`, `/api/sync/confirm` and `/api/sync/cancel` are fixed operations on the launch-bound confirmed-sync provider. Host, scoped session, exact Origin and CSRF guards apply before dispatch. Each request requires one application/json Content-Type and a positive Content-Length bounded to 4096 bytes; query strings, transfer encoding, duplicate JSON keys, non-object payloads, non-finite numbers and malformed bodies are refused. A ten-second absolute body-read timer closes the read side of a stalled or slow-drip request. The provider receives the server-owned session identity, never a browser-supplied identity. Dispatch returns the current action snapshot with 202; asynchronous preview/execution transitions publish through the existing snapshot/SSE revision. No additional browser poll is introduced. The separate confirmed-sync contract in `specs/cockpit_sync.md` owns preview expiry, choices, author-cache checks, process bounds and write semantics.

- Bodies are limited to 4 KiB; bootstrap requires an empty body. Chunked, duplicate-length and malformed framing is refused. Request timeouts and an eight-slot active request-handler pool prevent unbounded thread creation; at most two connections stream SSE. The single accept loop may hold one additional accepted socket while waiting at most 0.5 seconds for a handler slot, allowing a short asset burst to use capacity released within that bound. Saturation beyond the bound closes that socket without dispatch. The existing finite kernel listen backlog is unchanged; there is no additional userland request queue or worker thread. Shutdown may wait for the current bounded admission attempt.
- Static serving accepts only `/` for `mergepath/cockpit/index.html` and `/assets/<path>` under `mergepath/cockpit/assets/`. No source files, directory listings, traversal, escaped traversal or symlink escape are served. Assets remain authenticated. A missing index fails with `visual_shell_unavailable` and status 503. Tests also serve the real shell through the authenticated boundary.
- Every response carries a self-only connection CSP, self-only script/style/image/font sources, no inline scripts or unsafe eval, no framing, no MIME sniffing, no referrer and no-store caching. There is no CORS allowance. The bootstrap script uses textContent for its fixed diagnostic messages; future dynamic rendering must also use textContent.
- Access logs contain status codes only. Request paths, queries, headers, cookies, nonce, CSRF, PATs, upstream response bodies and exception messages are never logged or included in public error payloads.

## Read-only GitHub client

The client has one fixed origin, `https://api.github.com`, and supports GET REST reads plus explicitly validated GraphQL query documents. It accepts no arbitrary method, origin, redirect or credential override; environment proxy settings are ignored. GraphQL mutation and subscription documents are rejected before transport, including multiple-operation documents. Matched parentheses/brackets/braces distinguish input-object/list variable defaults from the single root selection set; mismatched delimiters, fragments and trailing operations are rejected before transport. Query strings and comments are lexed so quoted text is not confused with an operation. Each batched GraphQL request is one query document containing aliased fields, with optional variables and cursor helpers; only None defaults variables to an empty object. Variables must be a native dict whose entire tree passes the same strict copy used for scheduler samples; nested non-string keys, tuples, cycles, repeated dict/list identities, non-finite numbers, custom values and excessive recursion are refused as invalid_query_variables before request dispatch; it is not a batch of writes.

The typed read_job_log(repo, job_id) operation is the sole log-download exception to the generic fixed-origin JSON contract. Only the CI provider calls it, for an enrolled repository and a job identity it just observed. Its fixed GitHub Actions job-log GET uses the same serialized transport fence, caller deadline, reserve/backoff protection and response-header accounting. A 302 may supply one credential-free HTTPS download from the narrowly observed productionresultssa[digits].blob.core.windows.net host family; other destinations, userinfo, explicit ports, fragments, malformed URLs and further redirects fail unavailable. This allowlist reflects an observed GitHub.com response, not a guarantee covering every GitHub storage deployment. No Authorization or cookies are sent to storage, ambient proxies are ignored, and signed locations never enter the cache, browser payloads, error metadata or logs. Download failures preserve the API response budget observation; storage headers never become GitHub budget evidence. Complete log bytes must fit the existing 2 MiB cap and deadline; oversized responses fail response_too_large rather than presenting a capped prefix as a tail. This is a bounded availability limitation, not silent truncation. Tests in tests/test_cockpit_logs.py cover the separate authority boundary and shared limits.

REST responses cache payload, ETag and pagination Link together. A 304 reuses that page's payload and Link; pagination still walks every cached page. Next links must remain on the fixed origin and name either the same REST path or GitHub's numeric `/repositories/<id>/` alias of it with the same remainder, which is how GitHub paginates repository-scoped endpoints such as Actions runs. The alias never becomes a request: the client keeps requesting the enrolled `/repos/<owner>/<repo>/` endpoint, takes only the page cursor from the link, requires every original query filter to be present on it, and refuses a walk whose alias id changes. Cycles, malformed pages, missing cached 304s and page/response-size limits fail closed rather than report partial results. A request deadline bounds the whole pagination operation. GraphQL pageInfo helpers reject incomplete cursors instead of silently truncating a connection.

Every actual response, including 304, 403 and 429, updates that rate-limit resource's evidence from X-RateLimit-* headers. The resident reviewer client uses no `/rate_limit` probe. Limit, remaining, used and reset are nullable; absent or malformed evidence stays unknown. The budget snapshot records observed time and status alongside each resource, and records Retry-After separately. Each entry identifies its credential_source as `OP_PREFLIGHT_REVIEWER_PAT` and configured_identity from the cached `OP_PREFLIGHT_AGENT` export; this is labelled `preflight_configured`, not a live `/user` identity observation. A missing agent export leaves configured_identity unknown. Additional owner/robot clients must have separate source/pool namespaces and must never be silently combined with this reviewer budget. Primary-pool exhaustion (remaining zero with a future reset) and explicit secondary/throttle responses are separate conditions. A 403 or 429 with that primary evidence alone blocks only its observed pool until reset; other pools remain usable. Retry-After or explicit secondary-limit/abuse evidence on either denial retains shared backoff even when the primary pool is also exhausted. A 429 without sufficient primary evidence also retains shared throttle treatment; a generic permission-denied 403 is not exhaustion. Explicit secondary-limit messages inside a bounded GraphQL HTTP-200 errors array also establish shared throttle/backoff, as documented by [GitHub](https://docs.github.com/en/graphql/overview/rate-limits-and-query-limits-for-the-graphql-api#exceeding-the-rate-limit); successful data text and generic GraphQL errors do not. REST requests select core, search or code_search by endpoint and learn the actual response-resource identity for later GETs and pages of that endpoint; this mapping is bounded with the page cache. Local protection pauses reads until the observed reset when remaining requests reach min(configured reserve, floor(observed positive limit × 0.02)); the default configured reserve is 100, so core at 5,000 retains 100 while healthy search 29/30 and code_search 9/10 remain usable. Missing, malformed or nonpositive limits supply no local reserve and never imply a denominator. This protection returns primary_reserve and is distinct from primary_exhausted, which requires observed zero remaining plus a future reset; explicit throttle evidence gates all callers. No rate evidence is fabricated from configured limits, cache hits or a denominator in the design.

The transport uses a 15-second per-request budget, a 2 MiB response cap, bounded in-memory LRU cache and one serialized transport lock. Lock acquisition consumes the caller's remaining deadline; a late reply is discarded after its observed headers are accounted. Body reads use read1, remaining-time socket bounds and a daemon deadline timer that shuts down the active socket, so a slow-drip body cannot prolong the request through repeated idle timeouts. Header/status metadata survives bounded-body failure without retaining or logging its content. The platform's synchronous DNS resolver and connection setup cannot be forcibly interrupted before an active socket is available; their native timeout behavior is not an absolute process deadline. The scheduler marks such overruns stale and retains finite worker/single-flight fences, while snapshot reads use a separate state lock and remain responsive. Request failures reveal only a stable category and optional retry delay. ClientError accepts only the finite immutable code-owned ERROR_CATEGORIES vocabulary; arbitrary text, non-string values and unregistered identifiers become source_failed without string coercion, including Exception args. The scheduler revalidates at envelope publication so a mutated or subclass-provided category cannot bypass the boundary. Future adapters map failures to that vocabulary; additions require a reviewed shared-owner code change, never runtime category registration. A denied source must not make unrelated source data disappear.

## Scheduler and envelopes

Panel sources register a name, fetch callback, hot and idle intervals, timeout and maximum backoff. The launcher binds each installed provider to this shared scheduler; panel reads never create independent polling loops. There is one scheduler for all sources, at most two daemon workers, no unbounded executor queue, one in-flight job per source, and a single shared GitHub client. Its worker count must be a native integer of one or two; booleans, floats and higher counts are refused. Future fetch callbacks must honor the supplied monotonic deadline and bound every subprocess/transport call. The scheduler marks deadline overruns stale, discards late results, retains the single-flight fence until the callback returns, and shuts down without waiting indefinitely for a failed callback.

Defaults are 15 seconds hot, 120 seconds idle, 30 seconds source timeout, exponential error backoff capped at 900 seconds, and at least any provider retry delay. Billing and clone-heavy audits must register separate slow cadences in their owning tickets. On-demand refresh only moves a source's next due time; it never bypasses an in-flight job or current backoff. Repeated refreshes coalesce.

The shared retry_delay helper accepts only finite nonnegative native integer/float delays. Invalid, non-finite and overflowing numeric values fall back to zero without coercion; the scheduler then applies its ordinary backoff. Valid provider delays retain their value without an arbitrary duration cap. ClientError normalizes on construction and the scheduler normalizes again at publication so a mutated delay cannot bypass the boundary. A timestamp addition that would overflow falls back to ordinary backoff, with zero as the last resort if that addition is also unrepresentable. Malformed retry metadata cannot break snapshot/SSE JSON, hide unrelated sources or replace retained last-good data and age.

Provider samples must already be strict native JSON trees: null, strings, booleans, integers, finite floats, native lists and native dicts with string-only keys. The shared copy_json_tree in github.py serves both scheduler samples and GraphQL variables. Its strict recursive copy refuses tuples, non-string key collisions, non-finite numbers, custom objects and cycles instead of coercing them. Dict/list containers must form an unaliased tree: a whole-walk identity set also refuses repeated container references, including acyclic aliases, before copying their branch again. Equal-but-distinct containers and repeated scalar values remain valid. This implementation contract refinement corrects prior shared-container copy acceptance and prevents its exponential expansion; it does not establish an absolute process-memory or serialized-byte bound for huge already-materialized ordinary trees. Invalid data marks the source failed/stale and retains prior last-good data and observed_at. Source snapshots are JSON envelopes: data, observed_at (last successful observation), attempted_at, stale, error (stable category), retry_at and in_flight. The initial state is unavailable and stale, never a fabricated clear result. A failed refresh keeps the last-good data and observed_at, marks it stale, and records the failed attempt. Returned snapshots are copies so consumers cannot mutate the scheduler's stored result. Snapshot data must exclude credentials and session secrets.

The strict tree copy preserves Python structure and native types; it does not guarantee arbitrary integer precision after browser JSON.parse converts numbers to JavaScript Number. Browser-bound providers must preserve opaque IDs as strings and encode exact integers outside the JavaScript safe range, −(2^53−1) through 2^53−1, as decimal strings before publication and validate their own domain schema. The shared transport never automatically stringifies numbers or imposes browser numeric restrictions on GraphQL input variables. Shared hazard IDs already require strings, and PR counts require safe integers. The Python-to-Node consumer regression verifies both safe numeric bounds and exact decimal strings; it does not claim universal numeric fidelity.

GET `/api/snapshot` returns schema `cockpit/v1`, immutable repositories, per-resource response-header budget evidence, source envelopes, revision and generated_at. Optional `repo=<owner/repo>` filters the repository inventory to an exact enrolled repository; an unknown filter is refused. Future source adapters own projecting their per-repository data. GET `/events` sends an immediate snapshot, `retry: 2000`, revision IDs for snapshot updates, and a heartbeat every 15 seconds. Reconnection always sends the current complete snapshot, including when Last-Event-ID is stale or absent; event history is not replayed. Heartbeats do not poll GitHub. Broken pipes and shutdown close streams cleanly.

Authenticated GET `/api/panels/<id>` supplies each fixed panel's existing JSON envelope under `cockpit-panel/v1` as `{panel, source, envelope}`. The only IDs are `prs`, `ci`, `agents`, `history`, `fleet` and `budget`. Trusted provider setup first registers its scheduler source, then calls `Application.register_panel(panel, source)` once before serving; unknown panel/source names and rebinding are refused. Multiple panels may share one source, so agents/history can use one fetch job. Unbound panels return source null and a fresh canonical unavailable/stale SourceEnvelope with unknown data and observation times. Bound panels retain the scheduler's initial or last-good/stale envelope and reuse shared snapshot redaction. Unknown IDs return 404 and all query parameters are refused; browser input cannot select arbitrary source names, repository filters, upstream URLs or fetch callbacks. These read-only views never trigger fetch, refresh or additional polling. The page continues to use one full snapshot/SSE connection and client-only repository projection.

Authenticated GET `/api/ci/excerpt` accepts exactly one repo, run, attempt, job and step query value. A registered CI excerpt service validates the enrolled repository, observed run attempt/job and failed step against the bound CI envelope before any typed log read. There is no arbitrary source, upstream path or URL input. Missing service is unavailable; stale observations cannot initiate a log read. The handler supplies a 15-second monotonic deadline, retains the ordinary namespace/session/Host/Origin checks and applies shared secret redaction to every returned excerpt. This read-only on-demand route creates no recurring poll or rerun action.

## Shared shell and integration seams

All local stylesheet links precede deferred scripts, preserving stylesheet cascade order and script dependency order for cold-bootstrap compatibility.

`index.html` supplies semantic, fixed local sections: `road`, `prs`, `ci`, `agents`, `history`, `fleet` and `budget`. `assets/cockpit.css` contains the inspected theme, geometry and motion tokens; `assets/fonts/local-fonts.css` and the original WOFF2 binaries keep typography local with original SIL licenses and provenance manifest. `assets/components.js` owns pure six-state, meter, hazard validation/filtering, logarithmic Road selection/layout and DOM views. `assets/app.js` owns one connection controller and the panel projection registry. Both modules expose CommonJS exports for hermetic Node tests and browser globals for local scripts, without a framework or runtime dependency. No prototype scenario controls or example records enter the product.

`PanelRegistry.register(id, source, project, render)` registers one fixed section once. The pure `project(envelope, selectedRepo, now)` returns `{state, label, hazards, count}` (the optional budget projection also supplies `horizon: {cycleEnd, label}` from observed billing evidence, or null); only the optional named `prs` adapter supplies a nullable PR count for repository badges. Counts never aggregate heterogeneous provider rows and stay unknown until #1587. The optional render callback owns panel-specific DOM and disclosure state. The registry passes the unchanged SourceEnvelope; it never interprets arbitrary provider payloads. Missing observations produce idle/unavailable, even when an adapter proposes clear. Staleness remains independent of prior status; last-known models, boulders and their age survive failures. A provider may return stale: true when its selected repository coverage includes retained or missing observations; effective model staleness is envelope.stale OR projected.stale. A provider cannot promote a stale scheduler envelope to fresh. Ordinary repository denial is partial coverage, not invalid hazard output; readable repository rows retain their own ages and freshness, and filtering to wholly fresh coverage can withdraw the provider downgrade. Providers own per-repository observation metadata and partial-coverage copy; the shared observed_at remains the aggregate sample time. The aggregate separately counts fresh and stale observed panels; a live SSE connection does not make stale source observations current. A model retains its usable hazards, observation age and actual stale flag, but coverageValid is false if normalization refuses hazard output, source ownership is wrong, or aggregate hazard identity is duplicated. Such models cannot contribute to fresh-clear coverage. invalidPanels is a separate validation count that can overlap source staleness; diagnostics remain visible. Normal repository filtering does not invalidate coverage. Counts use projections over the unfiltered full snapshot. No sources are registered by the foundation product. A deterministic test adapter demonstrates the seam without defining later provider schemas.

The optional boolean projection hasObservations flag separates usable domain observations from a successfully published failed-attempt report. The validated model.observed flag still enables the adapter renderer; aggregate observed/fresh/stale coverage counts require model.observed AND hasObservations !== false. Providers set the flag from selected-scope repository observation times: successful empty results count as observed, while an all-never-observed selection does not invent last-known stale coverage. False only withdraws coverage; it cannot suppress hazards, invalid-data counts or diagnostics, or upgrade scheduler staleness. A non-boolean supplied flag is rejected.

Fleet alone may opt into `renderPending` when registering its adapter. A strictly empty scheduler envelope (`data` and `observed_at` both null, valid status fields) can render idle/running progress before the first observation. The pending projection must contain no hazards, no count, and false observation/coverage flags. The registry owns `renderable`, keeps all coverage counters unchanged and refuses malformed pending projections; non-null invalid data cannot enter this path. Valid observations, pending attempts and invalid-data withdrawal all use the same renderer ownership transition. The shared display clock updates elapsed progress without a network poll.

Projection context exposes a copied, deeply frozen current PR envelope as its optional fourth argument. Fleet joins that snapshot during projection, so its thirty-minute audit result never freezes a PR's fast-changing review state or starts another PR poll. Optional `coverageValid:false` can withdraw provider coverage without reporting malformed data; validation errors remain separate and cannot be overridden by a provider.

Shared states are `idle | running | clear | bump | boulder | done`. Worst-state precedence is boulder, bump, running, clear/done, idle. Labels accompany shapes; unknown/unreadable is idle with explicit unavailable text. A normalized hazard has a stable `id`, fixed panel `source`, enrolled `repo` or null for global scope, bump/boulder `state`, plain-text `title` and `detail`, timing `{kind:'now'}`, `{kind:'at', at:<epoch seconds>}` or `{kind:'unknown'}`, nullable `observed_at`, boolean `stale` and fixed local `section`. Invalid hazards are refused with a visible adapter diagnostic. The shell reserves shell-connection and the account-api-* identity namespace; adapters using them are refused with invalid coverage even while the corresponding system hazard is absent. A bump/boulder projection must supply at least one usable owned hazard before ordinary repository filtering, or its coverage becomes invalid with a diagnostic. Its model, observation age, actual stale flag and other usable hazards remain; no hazard is synthesized. No HTML or arbitrary navigation target is accepted. Stable identity, not revision or list position, governs entry motion. Filtering and repeated snapshots preserve nodes, focus and disclosure state; there are no reward animations in this slice.

The Road receives explicit `{now, horizonMinutes, horizonLabel}`, deriving the span from the validated optional budget projection cycle end. Applicable 15-minute, 1-hour and today ticks share the same mapping; narrow layouts omit colliding ticks. A valid positive horizon maps known times to 4..94 percent using `log1p(minutes) / log1p(horizonMinutes)`. There is no product fallback horizon: absent billing-cycle evidence displays “Horizon unavailable”, anchors immediate/past hazards at Now and retains future/unknown timings in the full list without invented positions. Deterministic fixtures supply an explicit cycle end. Beyond-horizon hazards are clamped and explicitly labeled in the list. Only bumps/boulders appear; nine strip slots choose boulders first, then known ETA. Every valid hazard remains in the full numbered list, with truthful overflow navigation. Unknown timing stays off the scaled strip. Collision-aware label lanes use measured text; narrow layouts can show numbered labels tied to the complete list. Absent observations display “No observations yet”; operational clear requires fresh observed coverage and a live connection. Stale-only empty coverage retains an idle shape with Last-known observations are stale, distinct from never-observed coverage. Mixed coverage explicitly reports fresh/stale panel counts and scopes any clear wording to fresh observed sources; stale hazards remain visible. When only invalid coverage remains and no usable hazards are visible, the Road uses idle with Observations unavailable, and the footer labels the number of sources reporting invalid data. Validation failure never invents a stale observation or a Road hazard. Shared connection/API hazards do not imply that unavailable panels are healthy.

Repository selection uses the full immutable enrolled inventory and one full SSE snapshot. No filtered network request is made. Projections retain selected-repository and null-repository global hazards. Connection health and each reviewer PAT resource pool remain globally scoped; core, search, code_search and GraphQL observations are never combined. Pool selection shows the observed denominator and truthful resource unit (GraphQL points, REST requests) even when throttled/exhausted; absent evidence displays unknown and no fill. Meters use observed usage, bump at 70 percent and boulder at 100 percent, correcting the unused prototype 90-percent API formula. Primary exhaustion and secondary throttling are explicitly distinct. Configured preflight identity is labeled as configured rather than live verified; the separate author meter labels successful viewer verification explicitly. Reset/observation times accompany evidence.

The selected meter and account hazards share one current time. When a known primary reset passes, old remaining/used/ratio and primary_exhausted no longer describe current usage: the meter becomes unknown without a fill and the old primary hazard disappears. The observed denominator/time and explicitly labeled last-known values remain visible; no refill, healthy state or new observation is inferred. Independent secondary-throttle evidence remains separately labeled as last observed and is not cleared by that primary reset; this introduces no new secondary-expiry guarantee. The existing one-second display clock detects a reset boundary crossing and renders this change even without a new snapshot or provider observation. It creates no additional network poll, timer or source refresh.

One bounded, abortable GET `/api/snapshot` per initial/reconnect generation observes HTTP status before opening one EventSource. EventSource does not expose HTTP status, so the probe is necessary to give terminal relaunch guidance on 401 (expired cookie) or 404 (old namespace after a server restart) from the fixed scoped snapshot route. There is no recurring snapshot timer, source refresh or upstream polling. A dropped connection immediately closes the old stream and retries after 2, 4, 8, 16 and at most 30 seconds; three failed attempts show Offline while retrying continues. A watchdog starts at stream creation and catches a missing valid snapshot/heartbeat after 45 seconds. Stream open alone does not reset accumulated failures. A 401 or 404 from that fixed route stops retries without discovering a replacement namespace. Last-good snapshots remain visible and explicitly stale until a current stream snapshot arrives. Generation guards discard late probes/timers/events and prevent duplicate reconnects. Page hide closes the stream; page show resumes. Updated reports nonnegative latest valid snapshot/data age from a monotonic browser clock, separately from source observed_at age; heartbeat `{}` proves liveness only and never refreshes data age.

### Panel layout

The operator can rearrange the six data panels (`prs`, `ci`, `agents`, `history`, `fleet`, `budget`). The header, Road ahead and Repositories controls stay fixed. `assets/layout.js` owns the order as pure helpers (`normalizeOrder`, `moveTo`, `rowsFor`, `dropSlot`) plus one DOM controller; `assets/layout.css` owns the handle, lift, drop-indicator and FLIP styles. Panels stack in the chosen order; CI and the Phase 4b agents share the shipped `row2` flex row whenever they are adjacent, in either order, and every other row is one full-width panel. A shared row is one unit for the other panels: dropping above its middle places the dragged panel before both, below places it after both.

Each panel head carries a `button.panel-handle` (`aria-label` "Move <title> panel", `aria-describedby` the toolbar hint, `aria-pressed` while grabbed or lifted). Only the handle starts a move, so buttons, links, text selection and scrolling inside panels are untouched. Mouse, pen and touch use Pointer Events on the handle with `touch-action: none`, pointer capture, a 4px threshold, a fixed-position accent drop indicator between rows, edge auto-scroll, and Escape or `pointercancel` to cancel. Keyboard: Space or Enter grabs, the arrow keys move one position (Home and End to the ends), Space or Enter drops, Escape cancels and restores the original order. The live region `#layout-announcement` announces grab, each move, drop and cancel with "position N of 6". The grabbed or dropped handle keeps focus across DOM moves, and a focused control inside a moved panel keeps focus too. Moves animate with a transform under `--t-med`; reduced motion jumps.

Live snapshots never touch section order: the shell only rewrites `*-content` containers, so an in-progress drag or grab survives a render, panel heights are re-measured on every pointer move, and handles and disclosure state are never recreated. The order persists with the existing local-preference pattern under `localStorage` key `cockpit-layout` (`{"v":1,"order":[...]}`), read and written behind try/catch. Corrupt or unavailable storage, unknown or duplicate ids and a missing entry all fall back to the default order, and a panel added later appends in default order. Reset layout in the toolbar restores the default order and clears the stored one; it is disabled while the order is the default. `tests/test_cockpit_layout_ui.cjs` covers the helpers, pointer and keyboard reordering, cancellation, reload persistence, resizing and live updates during interaction on a stub DOM, and asserts the shell markup and assets.

Light/dark and reduced-motion buttons use aria-pressed, keyboard focus and local preferences. OS reduced motion always applies; its change event updates an already-open page. Reduction sets all duration tokens and entry delays to zero, disables animation rather than freezing at an arbitrary phase, removes hover displacement and renders defined readable resting frames. The normal tokens are fast160, medium360, slow700, pop900 and glow2600 milliseconds with cubic-bezier(.2,.8,.2,1); shared loops preserve the inspected 1600ms spin, 2400ms connection breathe, 1000ms meter rumble and 2600ms boulder throb. Dynamic text uses textContent. Local section links target keyboard-focusable headings; live announcements occur on connection transitions, not every heartbeat. Mobile panels and Road list wrap without horizontal page overflow.

A provider can also return optional boolean coverageValid: false to disclose incomplete domain coverage even when its payload and hazards are structurally valid.
