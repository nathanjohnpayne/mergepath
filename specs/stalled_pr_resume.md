# Stalled pull-request finder and resume entry point (#2165)

The largest share of pull-request wall-clock in the fleet is time when nothing is waiting on a machine: a reviewer verdict lands outside working hours and no session is alive to act on it. Two scripts in the `scripts/workflow/` kit close that gap from the tooling side; the end-of-session rule in `docs/agents/shared-operating-rules.md` closes it from the behavior side.

## Finder: `scripts/workflow/stalled-prs.sh`

Read-only. Lists the open, non-draft pull requests of one repository (`--repo`, default the current repo) and classifies each by whose turn it is and how long nothing has happened. The only GitHub calls are paginated REST GETs (open PRs, each PR's reviews, issue comments, inline comments and head check runs, the repository activity API's push entries, and governing base-policy contents) plus the read-only required-head-checks resolution. It never comments, labels, requests or merges.

Evidence rules: the head's push time is server-generated, never the commit's own committer date (author-controlled metadata: a future-dated commit would read as perpetually live and a cherry-picked old one as instantly stale). In order: the repository activity API's push entry for the head SHA; else the earliest check-run start on the head; else the pull request's server-set `updated_at`, a value stable across runs and never earlier than the push. The source is reported as `head_pushed_at_source` (`push-activity`, `check-run`, `pr-updated-at`). Codex evidence (review objects, inline findings, verdict and Review Summary comments) requires the exact governing `codex.bot_login` (default `chatgpt-codex-connector[bot]`) and `user.type == "Bot"`; prefix lookalikes and User accounts never count as Codex. Live collection materializes the target repository’s base policy through the shared resolver, caches it per base revision and records `codex_bot_login` in each replayable PR record. An unreadable governing policy is infrastructure failure, not permission to borrow the local checkout’s identity. Older snapshots without this field retain the default login; a CodeRabbit or code-scanning review on the head is a verdict, never a Codex signal. A `CHANGES_REQUESTED` review counts only when it is anchored to the head commit or submitted after the head was pushed. A body-less `COMMENTED` review from a bot is the wrapper GitHub emits around a bot's inline reply (a CodeRabbit resolve acknowledgement) and is bot activity, never a verdict. Any non-bot reply on a finding thread answers it, since fix and rebuttal replies are posted under a registered reviewer identity rather than the author login, but only a reply posted after the finding was last edited or re-raised (the inline comment's `updated_at`). A provider rate-limit notice on the head stands until that provider recovers (its own verdict lands after the notice; an unrelated human or reviewer comment does not count) or the sanctioned failover exists (an `@codex review` posted after it), whether or not the trigger it refused is still outstanding: younger than the threshold it is `waiting-on-bot`, older it is `rate-limit-stale` and routes to `investigate` (the provider wait requests the failover itself), never to an automatic Codex request. A Codex Review Summary that still says `Running` is superseded by any head-anchored Codex verdict that landed at or after it.

Classes, one per PR:

- `stalled` — an agent must act and nothing has happened for at least the threshold (`--threshold-minutes`, default 60). Reasons: `unanswered-verdict` (the newest event is a bot review, a bot verdict comment, a reviewer-identity review or comment, or a human reply, with nothing after it); `head-unrequested` (the newest event is author-side, the head is CI-complete, and no review was requested and no Codex signal exists on it); `idle` (author activity after the verdict, then nothing); `request-unanswered`, `rate-limit-stale` and `ci-pending-stale` (a machine wait outlived the threshold).
- `live` — an agent must act and the newest event is younger than the threshold.
- `waiting-on-ci` — the newest event is author-side and the head's required head checks are `PENDING`. CI state is judged only on the checks `scripts/required-head-checks.sh` resolves for the repository (`lint` by default), newest run per name, never on the aggregate check rollup: the rollup also carries review-policy checks (Label Gate, Merge clearance gate) that fail by design until external review clears, and would route every threshold PR to a CI fix that does not exist. A head with no check runs at all is `NONE`.
- `waiting-on-bot` — a review request (`@codex review` / `@coderabbitai …` in any markup) is newer than the head with no verdict after it, Codex's Review Summary reports the head `Running`, or the newest event is bot activity that is not a verdict (a rate-limit notice, a resolve acknowledgement).
- `waiting-on-human` — a fork PR or one not authored by the configured author identity (`author_identity` in `.github/review-policy.yml`, default `nathanjohnpayne`), since an agent cannot push to a contributor's branch; a `human-hold`, `needs-human-review` or `policy-violation` label; or any issue comment, review body or inline comment on the PR that currently carries a handoff marker (`[mergepath-handoff]`, `<!-- mergepath-handback:`, or the `## External Review Required` heading), whoever posted it and whenever. Never picked up by the resume entry point. The handoff rule is deliberately conservative: there is no timestamp comparison and no later event that supersedes a handoff, because every such rule had an edge (a fallback timestamp, a mutable summary edit, an edited marker) that resumed a PR reserved for a human. A person clears it by removing the label, or by editing or deleting the handoff comment so it no longer carries the marker.

Next action, reported for every PR, in this precedence: `push fix` (CI red on the head — checked before any re-request — the latest head-scoped verdict requested changes, or findings on the head with no agent reply), `request codex` (a request outlived the threshold unanswered, or no Codex signal on the head and CI green or absent — a `NONE` rollup in a repository with no checks), `merge` (the repository's own complete policy agrees: the newest `Merge clearance gate` check run on the head is `success`, or that check does not exist in the repository and `scripts/codex-review-check.sh` exits 0 on the head; a passing Phase 4 gate with a failed clearance check is `investigate`), `investigate` (the gate's one-line reason, or a stale CI wait), `wait` (a machine or a human acts next). The gate runs only for stalled PRs on an agent's turn, and only in live runs; `--no-gate` skips it. It is always bounded (`STALLED_PRS_GATE_TIMEOUT_SECONDS`, default 300): GNU `timeout` where present, else perl's `alarm`, and with neither it is not run at all, since an unbounded gate could hang a scheduled routine before it reaches any later PR.

Verdict bodies are read with U+00A0 normalized to a space, because Codex posts NBSP inside `Reviewed commit:` lines. Draft PRs are excluded. The report is sorted stalled-first, oldest newest-event first. `--json` emits `stalled-prs-report/v1`; the human table prints one line per PR. `--dump FILE` writes the `stalled-prs/v1` snapshot after the gate stage, and `--input FILE` classifies a snapshot without any network call, which is how the suite builds its fixtures. `--now` pins the clock.

Exit codes: 0 nothing stalled; 1 at least one stalled PR; 2 usage; 3 a read failed (nothing is decided — a failed list is a status, never an empty report).

## Resume: `scripts/workflow/resume-stalled-pr.sh`

Runs the finder, selects the stalled PR whose newest event is oldest (or `--pr N`, which must still be stalled), and prints a work order: PR, head, reason, next action, a non-destructive checkout under the hidden per-repo folder, and the exact commands the review policy prescribes for that action. Every PR-controlled value in a printed command (the head ref, the repository slug) is shell-escaped, and the PR title is printed with control characters replaced. Fork PRs never reach the work order (the finder routes them to `waiting-on-human`), so the head branch is always on `origin`. The checkout is a detached worktree at the recorded head SHA: no local branch is created, moved or reset, so unpublished commits on a local branch of the same name are never orphaned, and fixes go back with a plain non-force `git push origin HEAD:refs/heads/<ref>` that refuses if the remote moved. The policy commands are run from that worktree, since the delegates read the governing policy of the repository they run in. Every policy command the work order prints is scoped to the selected repository. The `merge` work order lists the complete pre-merge sequence (the configured CodeRabbit selector and selected current-head wait with findings, advisory timeout, quota/failover and skipped-review routing, then feedback accounting, the thread gate, `scripts/required-head-checks.sh --verify` on the head — repositories may configure build checks beyond branch protection — the Phase 4b classifier, the Phase 4 gate, the clearance check state) before the author merge line. For an under-threshold exit-5 failover, the sequence verifies exact-head Codex clearance, requires a new reviewer approval after clearance with the provider and full SHA in its body, then uses `CODEX_REVIEW_CHECK_REQUIRE_APPROVAL_ON_HEAD=1` with `--require-codex-on-head` before merging. The replacement-approval step does not apply to the same-agent author of an above-threshold PR, which retains its Phase 4 route. The calling session executes the round per `AGENTS.md` § Workflow Summary.

The script is read-only and performs no GitHub write: it never requests a review, comments, labels, pushes or merges. Every write in the round, the Codex request included, is performed by the agent session through the repository's identity-verified wrappers, behind the session's own fresh reads rather than behind a snapshot taken minutes earlier. For `request codex` the work order prints the exact request to run: `scripts/codex-review-request.sh --trigger-only <N> <repo>` for a head nobody asked about, and the requester's polling mode (no `--trigger-only`) for a `request-unanswered` PR, since trigger-only would dedup on the existing unanswered trigger and post nothing; `MERGEPATH_PHASE_4A_GATED=true` is set only for a PR the repository's triage labelled `needs-external-review` (the threshold or protected-path verdict), and any other PR is left to the requester's own `codex.request_by_default` decision. It also prints the requester's routing exits, which the session acts on rather than retrying: 5 means Phase 4b for a Phase-4a-gated PR (the requester declines a gated PR only when `codex.enabled` is false) and the under-threshold approval-and-merge path otherwise; 6 means earlier feedback is unaccounted; 7 means the request budget is spent (`cap_exhausted.kind` `request-ceiling`: Phase 4b; `blocking-reviews`: human tiebreaker); 4, in polling mode only, means no answer within the review timeout (Phase 4b).

Exit codes: 0 a stalled PR was selected and its work order printed; 1 nothing to resume; 2 usage (including the removed `--execute` flag); 3 the finder could not read the repository.

## Scheduled routine

The routine itself is configured outside the repository. From a checkout at the default branch, with a read-only token for the finder, it runs `scripts/workflow/resume-stalled-pr.sh --repo <owner/repo>` and an agent session then performs the printed round, writes included, under its own author and reviewer credentials; `docs/agents/operating-rules.md` § Session finalization carries the operator detail.

## Coverage

`tests/test_stalled_pr_resume.sh` replays a fixture snapshot through `--input` for every class and reason above, the next-action derivation and its precedence, head-scoped change requests, the conservative handoff rule (a marker by any author, at any time, in any comment kind, keeps the PR waiting on a human), Codex-only head evidence, the merge-gate condition, NBSP tolerance, markup-tolerant trigger matching, draft exclusion, ordering, shell-escaped work orders with a detached checkout, the exact printed Codex request and routing exits, and the exit-code contracts of both scripts (including `--execute` as a usage error); then runs the live fetch against a PATH-shimmed `gh` with a stub gate script to assert pagination on every list read, the push-activity, check-run and `updated_at` push-time sources (the commit date is never read), gate delegation once per stalled agent-turn PR, `--dump`/`--input` round-tripping, and that an unreadable PR list exits 3 with nothing on stdout. `scripts/ci/check_stalled_pr_resume` wires it into `repo_lint.yml`.
