# Git identity hygiene

`scripts/ci/check_git_identity_hygiene` protects commit attribution and signing through three independent checks: local/worktree identity overrides, a repository-config snapshot comparison, and the static instruction scan. The static scan runs in every hub and consumer checkout (#1195); the presence of `scripts/sync-to-downstream.sh` controls only execution of the paired hub regression suite.

## Static scan scope

The production scan enumerates tracked regular shell scripts (including `.bats` files and `bats` shebangs) and Markdown documents with `git ls-files -z`; NUL-delimited paths preserve Unicode, quoted and newline-containing filenames. Symlink files and paths beneath symlinked directories are excluded: a tracked link names a link object, not machine-local target source. Fixture-root runs enumerate their supplied regular files without repository internals or symlink traversal. Repo-owned consumer surfaces, including `REVIEW_POLICY.md`, remain in scope even when a consumer retains a bootstrap-frozen copy. The same scanner, key classifier, command parsing and exemption rules apply in both environments. Its ASCII command grammar reads source under the C locale so unrelated non-UTF8 document bytes cannot abort enumeration of findings.

Shebang admission additionally recognizes one complete literal absolute path ending in `/env`, followed immediately by exact `-S` (attached or separated) or `--split-string=` / separated `--split-string`, then a complete unquoted interpreter from the shared existing inventory (`sh`, `bash`, `zsh`, `ksh`, `dash`, `ash`, `mksh`, `bats`). The existing shebang predicate remains in force; this additive predicate does not inspect later arguments or derive interpreter words from output. Preceding options/assignments, bundled `-vS`, quoted or escaped interpreter operands, split-string escape/variable expansion, runtime lookup and additional interpreter names gain no new admission guarantee. The scanner never executes a shebang or its operands. These inherited residual forms may omit a runnable source file from static scanning until the live-config checks detect a persisted override.

The scanner and `tests/test_git_identity_hygiene.sh` exclude themselves because they carry forbidden commands as examples and test input. Generated `docs/projects/*/prds/*` mirrors remain excluded because their source belongs to the central documentation repository. These exclusions do not exempt other test suites or repository-owned docs. Explicit repository targets (excluding literal empty `-C` paths, which leave cwd unchanged), unambiguous global/system option prefixes (including `--gl` and `--sy`), ephemeral identity overrides, reads/removals and deliberate `GIT_IDENTITY_SCOPE_EXEMPT: <reason>` comments keep their existing meaning. Shell-file markers bind to the command they terminate; an intervening command cannot exempt an earlier writer. A marker immediately after terminal control operators still belongs to the preceding command. A real owning-command marker also retains its intentional exemption for contained literal fixture instructions; later independent commands cannot supply that marker. Markdown retains deliberate physical-line exemption scope across its examples. Shell markers must be unquoted, unescaped comments; Markdown HTML markers must be complete comments outside fenced or indented code, including fences in blockquote and nested list containers in their source order. Ending an inner container ends its fence without discarding surviving outer containers. Container indentation uses four-column tab stops. Shell-comment exemptions remain valid inside fenced and indented examples. Indentation is measured after container prefixes; empty first children or list-marker spacing over four blanks use the marker-width-plus-one fallback. Indented code cannot interrupt an open paragraph; a list item must have nonempty first content to interrupt one, and an ordered item must also have start number 1. Standalone empty first children retain their existing indentation behavior. Blank lines, container changes, fences, headings and thematic/setext boundaries reset the bounded paragraph state. Shell comment boundaries accept space/tab and control operators, not vertical tab or form feed. Fence closers accept only spaces/tabs with an optional CRLF carriage return.

HTML exemption detection consumes the complete empty comments `<!-->` and `<!--->` before checking a later comment, and skips escaped markup, inline link destinations/titles (including angle-delimited destinations) and HTML tags with quoted attributes before testing complete comment bodies. This is bounded lexical recognition on a physical line or continued command, combined with per-file fence/container/paragraph state and equal-width backtick-run partitions within that line/logical command; it does not render Markdown or validate every Markdown construct. Literal marker text in those data contexts cannot exempt a write; a real comment after a closed construct retains its meaning.

In Markdown prose outside code blocks/spans, literal Git-command tokenization begins at a Git word whose option prefix leads to `config`, without re-entering consumed option data, so an earlier standalone Git mention, preceding apostrophes and prose quote wrappers cannot hide its key. A literal colon also separates a compact prose label from its Git instruction, including a path-qualified executable; complete-word recognition and the existing config-prefix/operand handling still decide the instruction. Argument quoting, quoted option data and subsequent command boundaries retain shell-word rules, including genuine trailing shell-comment exemptions. After code spans are removed for exemption recognition, apostrophes between letters in residual prose are word punctuation; real quote delimiters still protect marker data. Markers inside spans or quoted/escaped trailing data remain literal. Fenced/indented code, code spans and shell files keep shell quote handling. Command separation preserves single/double quotes and ordinary escapes around literal option words, so separators inside a Git `-c` value cannot disconnect the executable from `config`. Complete executable words and the following `config` subcommand are dequoted using ordinary paired quotes and escapes, while known prefix operands remain data; executables match `git` or a path ending in `/git`; variable expansion and runtime executable lookup are not evaluated. Balanced ordinary `$()` operand regions use ordinary quote/escape and parenthesis containment so their internal separators cannot split a literal outer command. An open region retains physical newlines in the existing per-file command buffer until its extent closes, ignoring shell-comment data through the newline; only this substitution syntax and existing backslash continuations join physical lines. Quoted or escaped literal dollars and shell comments do not open a substitution group. Output never supplies executable, key or scope words; direct literal instructions in the contained source retain the existing classifier, with unquoted newlines separating its commands so a later command cannot become the value of a plain read. Shell comment text cannot change quote/separator state or supply literal command words; its original bytes are retained for actual shell-comment exemptions on that independently read command. Those exemptions do not cover subsequent unmarked commands. Unknown extents fall back to literal source recognition rather than erasing body instructions. This does not parse compound Bash syntax, heredocs or other expansion forms, or infer the command created by expansion. Scope/read exemptions classify complete dequoted option words in the invocation prefix, skip the fixed set of separate option operands and stop classifying flags at `--`. Known negated scope/read selectors cancel their matching earlier positive selector; a later positive selector or an independent explicit target retains its meaning. Legacy read-action negation is accepted by older Git such as 2.43 and rejected by modern Git using non-negatable action options; static coverage conservatively rejects the cancelled read shape on either toolchain. ANSI-C word decoding and additional interpreter families remain outside this boundary. Quoted option-value data cannot supply an exemption or move the prefix to a literal `git` mentioned inside that value; a repository target directory named `git` remains an operand. The modern `rename-section` verb, like its legacy flag form, is a section operation rather than a protected-key assignment.

After an already literal protected key, the assignment classifier may skip one literal output redirection (`>` or `>>`) and its complete nonempty target word before checking for the value. Adjacent operators and ordinary paired/escaped target quoting use the existing word boundaries. Target source containing dollar, backtick, wildcard or brace bytes (`$`, backtick, `*`, `?`, `[`, `]`, `{`, `}`), or beginning with `#`, `&`, `|` or `~`, is conservatively outside this addition even when quoting could make those bytes literal. The target is data and cannot supply scope/read flags or an assignment value. A redirected read with no value remains a read, and Markdown `<addr>` placeholders retain their existing treatment. Multiple redirections, expansion targets, input redirections, descriptor duplication, clobber operators and redirections at other positions gain no new coverage guarantee. These inherited gaps can let a copied identity-writing instruction pass the source scan until the persisted override is detected by the live-config checks; this bounded addition does not interpret Bash redirection or runtime expansion generally.

The paired regression suite retains its marker-first consumer skip: it checks hub-maintained policy prose that is not propagated. Presence of a stale suite or policy copy never makes a consumer execute those hub assertions. Explicit suite overrides retain the existing post-suite identity, config and metadata tests.

## Regression coverage

`tests/test_git_identity_hygiene.sh` exercises the shared parsing cases with markerless fixtures and uses a real consumer index to verify policy/script findings, untracked-file exclusion, generated/self-fixture exclusions, scoped fixture writes, explicit exemptions, source encoding and the separate hub-suite gate. Existing identity/config/metadata tests remain intact. The hub consumer-safety and residue suites verify the wrapper in their canonical consumer models. Static modern `rename-section` coverage runs on every Git version; its private runtime oracle reports a genuine skip below Git 2.46. An unreadable version or a supported-version operation/readback failure records a failure and allows the suite to reach its summary, without fabricating successful results.
