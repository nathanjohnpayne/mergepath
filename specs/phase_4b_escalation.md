# Deterministic Phase 4b escalation

The owner retains model-authoritative Phase 4b for ordinary changes and accepts the hostile-diff residual (#1757). Three deterministic tripwires route egregious cases to human-mediated review: literal reviewer/verdict instructions in the diff, changes on the authorization/policy/publisher/credential inventory, and the existing disagreement, runaway and human-stop signals. The implementation authorization is recorded in #1757 comment6184085253. No independent human issuer or routine human-release requirement is introduced.

The trusted orchestrator runs the existing provider/feedback barriers and captures immutable PR objects before evaluating `scripts/phase-4b/escalation.cjs`. The helper checks the complete untrimmed PR diff. For curated waves it uses the original consumer `pr.diff`, not the curated reviewer payload. Changed paths come from a NUL-delimited, rename-disabled diff of the captured merge-base/head objects, so both sides of a rename participate. An unreadable or changed capture fails closed with infrastructure exit3. The helper neither reads credentials nor echoes candidate text; its Git subprocess receives no credential or inherited Git-configuration environment.

The literal text alarms recognize reviewer salutations, role-address forms and imperative requests near reviewer/verdict/APPROVED/CHANGES_REQUESTED words. Removed text and inert examples participate too. The exact case-insensitive patterns live in the helper. Descriptive mentions of reviewer counts or verdict history alone do not trigger. This is a finite alarm vocabulary, not a parser for arbitrary natural language or proof against prompt injection; unrecognized wording, obfuscation and semantic instruction attacks remain within the accepted hostile-diff residual.

The case-sensitive path inventory is deliberately conservative: REVIEW_POLICY.md, review-policy.yml, the exact `.codex/hooks.json` and `.claude/settings.json` guard-authorization configurations, the exact `.mergepath-sync.yml` review-exemption path policy and `scripts/sync-to-downstream.sh` author-credential/writer entrypoint, workflows/actions, the Phase4b package and exact `scripts/post-phase-4b-handoff.sh` manual dispatch renderer, author/reviewer/identity/preflight entrypoints, gate and administrative-merge entrypoints (including exact `scripts/coderabbit-wait.sh`, `scripts/gate-api-lineage-blocking.sh` and `scripts/wave-audit.sh`), feedback accounting, the exact `scripts/codex-record-feedback.sh` and `scripts/coderabbit-record-feedback.sh` finding-disposition recorders consumed by thread resolution, thread/archive entrypoints, self-approval/disagreement detectors, Firebase/gcloud/deploy entrypoints, and scripts/lib, scripts/workflow and scripts/hooks. Changes on these shared implementation directories require human review even if a particular change is harmless. Application source, ordinary documentation and tests do not trigger by path alone. The inventory lives in one helper; a new mechanism outside it is not automatically identified semantically.

A tripwire exits8 with `human_tiebreaker_required:true` and fixed reason codes before adapter dispatch, provisional review accounting, issue filing or review publication. It never returns the adapter-unavailable exit4 consumed by wave fan-out. The human selects the review/disposition path; an automated APPROVED cannot be produced by this run. Existing barriers retain their earlier stops and cannot be bypassed by a clear tripwire result. Pure offline/dry-run previews retain their existing behavior. A bound dry run whose caller retains reusable review evidence uses `--retain-evidence` and receives the same pre-model tripwire stop. The existing non-preview `wave-audit.sh --historical-end` path passes that intent before it may persist a prefix receipt; top-level `--dry-run` still runs a non-persisting preview. The flag grants no review publication or receipt authority, changes no receipt format and does not enable offline input to supply retained evidence.

**Verified-propagation exemption (#2633).** A curated wave capture whose input carries the `wave_audit` binding, which only `p4b_capture_wave_input` writes after `scripts/workflow/verify-live-propagation.sh` binds the canonical source, head and base, and whose binding records an ordinary wave (no `historical_end_sha`, no `finalize_historical`) with `head_on_hub_default: true` (the audited head is on the first-parent history of the hub's default branch as GitHub serves it, read live by an unauthenticated commit-only clone of the public hub, so it merged; no local ref or checkout state is consulted, because a stale `origin/HEAD` could name an old, unprotected branch and the trusted checkout's own `HEAD` could carry an unpushed commit (#2694); first-parent, because the hub allows merge commits; any clone failure withholds the exemption; the live verifier proves only byte equality with the source SHA, not that the source SHA merged) and `base_on_first_parent: true` (the base is on that head's first-parent history, so a merged hub state), returns `{decision:"model-review",tripwires:[],exemption:"verified-propagation"}`. The canary has no PR-authored bytes: each line already merged on the hub through its own review and its own tripwire stop, so re-escalating the mirror double-gated reviewed content and stopped every sync-all wave for a human. The `pr.diff` digest check still runs first, so a changed mirror still fails closed with exit3. A wave-shaped capture without that binding, with a malformed one, a historical chunk or finalization, an audited head that is not on the default branch's first-parent history, or a base off the head's first-parent history is classified as before: historical boundaries are checked only by plain ancestry and could fall on a never-merged commit.

**Admin automated 4b override (#2633).** `phase-4b-review.sh --admin-override "<owner quote>"`, passed through by `wave-audit.sh`, turns a deterministic tripwire into a recorded continuation to the real adapter. The tripwire runs after every provider barrier and before the review body renders, so no provider hold, request-budget snapshot or writer-boundary recheck is skipped. The wave-audit byte budget is not overridable: an oversized range would reach the adapter's own budget, fail to a proceedable reviewer-unavailable result, and lose the deterministic no-fan-out refusal, so it keeps the historical-prefix procedure. Barrier and Codex human stops are deliberately not overridable here: the barrier skips its CodeRabbit arm once a Codex human stop holds and carries its own budget evidence, so they keep the owner tiebreak (#2544). Its verdict posts under the reviewer identity as usual. The quote must be one non-empty line of at most 500 characters, and a value that starts with `-` is refused as a mistyped option, so `--admin-override --dry-run` cannot turn a preview into a posting run. Only a well-formed tripwire match is absorbed: decision `human-review` with a non-empty, duplicate-free list of the three fixed reason codes. Any other classifier result is an input-integrity stop (exit 3) under the override and keeps its fail-closed exit 8 without it. It is written into the posted review body with the overridden reason codes, emitted as `admin_overridden` and `admin_override_quote` in every terminal summary the run can reach after the tripwire (including the historical chunk summaries and the retained prefix receipt's `review_provenance`), and marked `admin-override=true` on the wave watermark, including a `--finalize-historical` watermark whose retained receipts record an override. `wave-audit.sh` applies the same quote checks before any capture, budget or empty-scope exit. Once a tripwire is overridden, an adapter that yields no usable verdict (missing, unavailable, timed out or malformed) does not reach the exit-4 manual fallback, which wave fan-out reads as proceedable: the tripwire still holds, so the run exits 8 with `human_tiebreaker_required:true` and renders no handoff. Holds (6), feedback accounting (7), input integrity and drift (3), request-budget evidence (10) and every provider-barrier result are never overridden. Like the scoped admin merge ([Scoped owner admin overrides](owner_admin_override.md)), the quote preserves the operator's account of the owner's authorization and is published on GitHub every time it is used. It does not independently authenticate the owner: agents hold the owner's credential, so no owner-authored GitHub comment can do so either, and a separate decision channel would need an explicit owner scope decision.

The PR implementing this policy changes the policy/authorization surface and itself requires human-mediated external review. The canonical issue remains open for the accepted residual and downstream acceptance. Source merge alone is not consumer verification. Coverage is in tests/test_phase_4b_escalation.cjs and the production-orchestrator controls in tests/test_phase_4b_automation.sh, using fake adapters and actual local Git objects without live models or credentials.
