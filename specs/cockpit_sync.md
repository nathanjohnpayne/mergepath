# Cockpit confirmed sync

This is Cockpit's only GitHub write path (#1593). Fleet and Open PRs continue to use read-only sources. Root/server integration owns exact Host, session, Origin, CSRF, unique-key JSON/body bounds and routes; the provider accepts selected manifest repository identities and fixed confirmation fields, never shell commands, local paths, executable names, credentials or arbitrary author labels.

## Launch and API seam

Construct `SyncProvider(inventory, trusted_root, fleet_fetch, cache_dir=..., agent="codex", operator="nathanjohnpayne", changed=app.publish, completed=refresh_existing_sources)`. The cache directory is resolved once at trusted launch from canonical preflight precedence. The resident server holds only its read credential. The provider's tools, root, operator, inventory and cache are launch-owned. Optional tool, lock directory, audit path and clock injection are for trusted launch/hermetic fixtures; HTTP input cannot select them.

The fixed protected JSON routes call `preview(server_session, {repos})`, `confirm(server_session, {preview_id, hub_sha, choices, ack_ahead})` and `cancel(server_session, {preview_id})`. They immediately return `cockpit-sync/v1`. Preview and execution are background operations; `snapshot(server_session)` joins the existing snapshot/SSE stream. There is no second browser poll. State phases are `idle`, `previewing`, `preview`, `running`, `done`, `error` and `canceled`. Other sessions see idle rather than another session's capabilities/results. Public snapshots contain no credential, local checkout/cache path or session identifier.

The UI integration is `CockpitSync.install(app, CockpitSync.createActions(fetch))`, returning a controller with `open(repos)`, `update(snapshot.sync)` and `close()`. Fleet calls its fixed `open` callback with manifest identities. Actions fetch the existing session CSRF and POST JSON to one fixed route with same-origin credentials and a ten-second request bound; the background work continues through SSE after that response.

## Preview and authority

Preview accepts a nonempty duplicate-free manifest consumer subset, excluding the hub. The immutable plan captures full hub SHA, manifest fingerprint, consumer baseline/ref identity, paths/classes/directions/overrides, complete open sync PR evidence, per-target allowed choices and a server-generated branch nonce. The checkout must be clean including untracked files, on `main`, exactly equal to local `origin/main`, and have the fixed hub HTTPS origin. Cockpit never fetches, resets or repairs the operator's checkout to make this true.

A fresh bounded Fleet fetch supplies current attempt evidence, independently of retained/displayed rows. Invalid, stale, missing or incomplete evidence refuses. A held Fleet audit lock reports `audit_busy`, with guidance to wait for completion and create a new preview; it does not wait, retry or add a browser poll. Other typed source failures report `audit_unavailable`. A selected healthy target needs drift/ahead status, matching hub SHA, a refreshed clean baseline and complete open-PR lookup. In-sync, override-only and failed targets remain visible as skipped. The fixed `--sync-all --repos ... --dry-run` command supplies proposed manifest scope; its network-free behavior cannot prove remote overrides, exact differences or absence of an existing PR. The dialog separately shows audited paths and this limitation.

The total preview bound is 180 seconds, shared with the fresh audit and dry run; the opaque session-bound preview expires five minutes after completion. Hub and manifest are checked again before publication. Existing PR targets default to Skip and allow only Skip/Recreate. Recreate uses a fresh branch and leaves every old PR and branch intact, with that explanation visible. Targets without old PRs allow Sync/Skip. All-skipped confirmations refuse before cache lookup or worker dispatch.

Confirmation must repeat the captured full hub SHA and supply exactly one allowed choice per preview target. A selected consumer-ahead path requires the separate boolean acknowledgment, including mixed-direction records. The UI names exact SHA and canonical repositories; returning Back creates a new unchecked acknowledgment. Unknown targets/choices, foreign, expired, canceled, changed or consumed previews refuse. A completed or partial run cannot be replayed. A disconnected page can observe the same run; hiding its dialog does not cancel execution or reopen the dialog on every SSE update.

## Guarded execution

Confirmation atomically claims a uid-owned OS `flock` shared by Cockpit launches for the same canonical trusted root and consumes the preview before dispatch. The lock file is a regular nonsymlink private file; a held/unsafe lock refuses. The descriptor is retained by the server and inherited by its worker/engine subprocesses. It is held until the worker's inherited process group has been terminated and its leader reaped. Ordinary legacy CLI invocations do not participate in this Cockpit lock; this does not claim distributed sync exclusion or detection of unchanged legacy CLI runs.

The private worker uses an allowlisted environment with isolated HOME/config/cache/tmp, fixed HTTPS Git credential helper and disabled interactive/keyring selectors, hooks, fsmonitor, SSH, ext and file protocols. It calls only the canonical fixed `op-preflight.sh --agent ... --mode review --check --print-exports`, bounded to ten seconds. It does not refresh or call `op`, parse credential cache files, switch gh accounts or repair authentication. The helper remains authoritative for cache validity/modes/TTL. A failing check, empty/reviewer-only, missing, duplicate or malformed author export refuses before sync/wrapper work. Only the exact author assignment is parsed as data; canonical cleanup statements and unrelated exports are ignored and never evaluated. Only its nonempty author PAT becomes the worker's `GH_TOKEN` and `OP_PREFLIGHT_AUTHOR_PAT`; the imported reviewer value is discarded. Ambient tokens, test bypasses, root overrides and tracing selectors cannot enter this environment.

Public GLOBAL Git name/email and `commit.gpgsign` are captured once at trusted launch through an allowlisted query, independently of repo-local overrides or ambient author variables. The worker applies that verified identity to both author and committer and enables `user.useConfigOnly`. This slice supports the currently configured unsigned mode (`commit.gpgsign=false` or the Git default); it does not weaken an enabled signing requirement. Enabled signing reports `unsupported_git_signing` before preview/write, while read-only observations remain available. No global config is passed wholesale and no signing program/socket or 1Password signer is invoked. A future noninteractive signing capability needs its own verified implementation; missing/invalid public identity reports `git_identity_unavailable`.

For each selected consumer, sequentially, the worker rechecks the clean exact-main hub and manifest and runs a fresh complete target-only `--audit --json --repos <repository>` audit in its private validated cache. The existing strict audit parser must return exactly one valid record for that expected manifest entry with a coherent exit code; missing, extra, duplicate, unexpected or malformed evidence refuses. The initial preview still audits the full inventory. Previewed baseline, path/direction/override and open-PR preconditions must still match. Then it invokes the existing engine with paired full-SHA fences and one fixed repository. The engine checks the expected hub before author verification and checks the actual cloned consumer commit before copying; it checks the clean exact-main hub again before copy and push. A failed hub-status command reports unavailable and refuses, even when its stdout is empty. Existing verified author wrappers continue to own GitHub author writes and verify the cached author identity. A mismatch refuses; no fallback credential is selected. The ordinary existing clone/git push mechanics remain unchanged.

The fixed total run bound is 900 seconds. Stdout/stderr are drained within worker bounds; retained public logs are limited to 256 KiB, 1,500 events and 4,096 characters per line. Oversized output/lines or malformed structured events abort and remain a visible failure. The private worker removes its actual author value and sensitive patterns/local launch paths before stdout reaches the server. No raw exports, author credential, cache path, unfiltered stderr or exception text reaches HTTP/SSE. Server redaction remains a second boundary for its own session/read secrets.

An append-only private `cockpit-sync-action/v1` journal in the launch cache records operator, time, full hub SHA, canonical target repositories, validated choices, run ID and outcome. Start is fsynced before dispatch and an unavailable/unsafe journal refuses; the completion record follows process cleanup. It contains no capability/session/credential. A completion-log error stays visible without denying already performed work.

Shutdown stops the scheduler and closes Fleet before waiting for a preview owner, then closes Sync. Sync kills/reaps its worker group before releasing the lock and cleaning private workspace; repeated close is safe. A failed group signal is recovered only by independently proving that the group is absent; a reaped leader alone does not prove descendant cleanup. Unknown cleanup finalizes IPC pipes, terminal state and the action journal with retained actual results, reports `cleanup_incomplete`, retains the lock/workspace and refuses new previews. Close retries proof before releasing those resources. Partial created-PR results remain truthful. No action promises rollback of an already pushed branch or created PR.

## Compatible engine seam

Existing CLI callers retain their defaults, text output, deterministic branch names and destructive `--recreate-existing` behavior. Cockpit never passes that destructive flag. New sync-all-only `--fresh-branch <32 lowercase hex>` appends a nonce to the existing scope-derived branch and never closes PRs/deletes branches. It is incompatible with audit, per-commit mode, no-PR mode and destructive recreate. Paired `--expect-hub <40 hex>` and `--expect-consumer <40 hex>` require exactly one repository selection. Invalid option combinations fail before I/O. Normal dry-run still does no PR probe.

Opt-in `--progress-json` emits tagged stage/result objects alongside legacy text. Fetch, diff, branch, commit and PR stages are emitted at their actual operation boundaries. No-change/idempotency and validated actual PR URLs produce result events. Missing telemetry is not synthesized from a timer or a fixture PR counter; nonobserved rails remain unknown. Legacy output has no tagged events unless requested.

## Dialog and validation

The pinned authentic sync dialog supplies the centered 660px scrollable rounded panel, three steps, path/class/direction plan, Skip/Recreate treatment, amber ahead acknowledgment, five rails, streamed log and actual-result PR chips. Its tokens are overlay360ms ease, panel/check/chip900ms cubic-bezier(.2,.8,.2,1), new log line160ms ease, cursor1s steps(2), completion burst2600ms ease-out. Manual and live OS reduction remove those animations/pause the cursor. At390px the panel retains reachable controls and wrapped full identities/paths. Progress never uses the prototype's fake one-second log/PR-number mechanics.

Dialog, log lines and result chips persist across repeated snapshots, preserving focus/choices and preventing entrance replays/duplicate lines. Changing between preview, confirmation, running and terminal views moves focus to the persistent dialog heading after controls are replaced; repeated snapshots of the same view retain the operator's focus. It has a labeled modal, focus containment/return, inert background, pressed-state choices and polite additions-only log. Scoped sync keyframes define the actual fade, pop, blink and burst motion, rather than relying on unrelated shared animation names. Stable refusals include human-readable recovery guidance; an unavailable cached author credential instructs terminal refresh followed by a new preview, with no authentication popup or automatic retry. Runtime refusal/partial/failure remain visible with retained actual results. Completion refreshes existing Fleet and Open PR sources rather than inventing fresh rows.

Tests use local fixture repositories, fake cached-preflight/gh/engine boundaries and offline DOM objects only. They exercise actual provider→private-worker commands, cached-only refusal/scrubbing, dirty/non-main/not-origin-main and moved identities, choice/ahead/cancel/expiry/replay, two launches sharing a lock, process-group shutdown, output bounds, partial outcomes, persistent DOM/focus and fixed authenticated requests. The existing engine suite includes actual local bare-remote fresh-branch, old-branch preservation, full identity fences and actual ordered stage/result controls. Browser acceptance uses the actual shared app/server routes with a local stub executor; no live downstream propagation or credential operation is a test.
