# Cockpit Fleet audit (#1592)

`FleetProvider(inventory, trusted_root, reviewer_token, *, cache_parent=None)` supplies read-only `fetch(deadline) -> Sample` under `cockpit-fleet/v1`. Its immutable launch inventory contains the hub and all selected manifest consumers. The sample includes `hub_repo`, ordered `repositories` with distinct current `attempt` and successful/retained `record`, `observed_at` and `attempted_at`, `stale`, canonical partial `sync_pr_rows`, `complete` and `audit_exit`. One fixed command runs `bash <trusted_root>/scripts/sync-to-downstream.sh --audit --json`; neither browser data nor ambient environment selects flags, roots, endpoints, tools or credentials. It consumes the established `specs/sync_audit_json.md` contract instead of recomputing comparisons.

Each provider creates its own mode0700 lifetime cache and isolated HOME, GH_CONFIG_DIR, XDG and temporary directories. Multiple instances cannot reset the same cache. `close()` removes only that private provider workspace after canceling a current audit. Existing entries must remain ordinary physical directories with a regular `.git/config`, exact enrolled HTTPS github.com origin and only ordinary clone bookkeeping configuration; symlinks, gitdir files, foreign origins, includes, executable config and unexpected cache entries are refused before any subprocess. The fixed reviewer-only Git helper is `gh auth git-credential`, scoped to HTTPS github.com. Git system/global configuration, inherited helpers, askpass, hooks and templates are disabled. The isolated gh config selects HTTPS. Only the nonempty resident reviewer token is passed as GH_TOKEN; author/other token selectors, SSH/proxy/debug/config injection and ambient credentials are omitted. Missing credentials refuse before spawn, without preflight, op, keyring or fallback. The child never invokes a sync/write command.

Every audit shares a monotonic total deadline capped at180 seconds. Streaming stdout is capped at8MiB and stderr at256KiB; all outputs are private and raw stderr is never published. Timeout, output-cap failure, cancellation and every exit path clean the process group, including descendants that outlive their leader. Stable categories describe unavailable evidence. No new runtime dependency is introduced.

Accept only complete exit0/1/3 NDJSON with exactly one validated record per manifest consumer, no duplicate/missing/unexpected identity, correct schema/shape and coherent exit precedence. Exit2, unexpected exits, invalid framing/JSON/fields, timeout or incomplete fleet rejects the attempt entirely; the scheduler retains the prior snapshot's original observation time and marks it stale. Complete exit3 advances healthy records while failed rows retain their prior successful record/time, latest attempted fetch-error/status/time and latest failure reason separately. A fetch-error without previous data remains explicitly unknown. The five statuses, every path class/direction/comparison/override reason/provenance, visibility and exact baseline/hub identity are retained. PR lookup null differs from a successful empty list. Fetch-error is a speed bump at NOW; drift/ahead alone do not create Road obstacles.

Root registers one `fleet` scheduler source with1800-second hot/idle cadence, timeout180 and max_backoff at least1800 (recommended7200). Initial, periodic and authenticated on-demand requests use this source's existing single-flight/backoff machinery; repeated refreshes do not queue more work. Root owns the fixed input-free POST `/api/fleet/refresh`, session/Host/Origin/CSRF validation and shutdown `provider.close()`. Buffered CLI records establish no progress percentage; the UI shows indeterminate running/elapsed state with existing rows retained. Before an actual dispatch it says Awaiting first audit, without inventing a queued indicator. The installer takes an injected `refresh` callback, with no authentication or upstream-fetch logic in the panel. Fleet alone registers `{renderPending:true}`: only an exact cold envelope with null data and null observed_at can render idle/running controls/status with count null, hasObservations/coverageValid false and no hazards; the shell's renderable status is distinct from an observation. Malformed non-null samples withdraw through the normal invalid-data path. The shell validates scheduler fields and re-renders elapsed progress while in flight.

`project(envelope, selectedRepo, now, context={prs: currentPRenvelope})` receives a read-only current shared PR envelope. Audit PR membership retains its independent audit observation/stale evidence. Valid matching shared rows supply current observations/budgets; unmatched IDs use the canonical `partial_row` seam with unknown budgets. No new PR poll, source mutation, invented current-HEAD clearance, duplicate PR-owned hazard or shared PR count is introduced. The same PR row renderer is available through a local disclosure. Sync controls remain disabled and labelled unavailable pending #1593.

The panel uses persistent keyed Fleet rows and disclosures, shared state badges and internally scrollable table, path/class/direction lists, original last-good ages and latest attempt reasons. Repository filtering and strict boolean hasObservations/coverageValid distinguish empty, partially measured and unavailable scope. Envelope stale OR row stale always applies; retained observations cannot become fresh on a failed refresh. Reattaching after a shared unavailable placeholder preserves surviving nodes, focus and disclosure. Disclosure entry follows the inspected360ms cubic-bezier(.2,.8,.2,1); current status colors follow360ms. Reduced motion removes movement/reset loops while retaining information.
