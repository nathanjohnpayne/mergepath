# Cockpit live Phase 4b agents

The fast `live_agents` source is separate from accounting history. `LiveAgentsProvider(inventory, heartbeat_dir, trusted_root).fetch(deadline)` scans the producer's machine-global directory once, independent of checkout roots. At startup Cockpit reads the producer's supported `P4B_HEARTBEAT_DIR` environment setting. An unset or empty value uses `~/.local/state/mergepath/phase-4b-runs`; an explicit absolute directory is operator-owned launch configuration, validated by the existing bounded resolver and captured for the provider lifetime. Relative or over-bound values refuse startup through generic configuration guidance; later environment changes do not redirect the source. No browser input can supply paths, processes, commands or repository enrollment. This source performs no GitHub, credential, model, ledger, accounting-helper or approval-cross-check operation.

## Bounded observations

The provider reuses history's `LocalReader`: every directory component and file open is no-follow; files must be regular, never symlinks, FIFOs or devices. The launch resolution permits macOS's normal `/var` alias; subsequent reads enforce no-follow against the resolved immutable path. The scan examines at most 512 directory entries, publishes at most 64 records in total and refuses records over 64 KiB. Within that observed subset, nonterminal rows take priority in stable ID order; terminal observations fill the remaining capacity by newest `stage_at_epoch`, with stable ID order breaking ties. Selection occurs before at most four process probes, so discarded rows spend no probes. Any selection or scan truncation marks coverage incomplete; neither active-run completeness nor observation beyond the scanned subset is implied. The elapsed cache remains bounded to the selected 64 records. Shared reader caps also bound total bytes and opens. Only enrolled repositories with valid `p4b-heartbeat/v1`, genuine filename-matching `run_id`, positive portable PID, process-start field, PR, head and ordered reached stages pass. Malformed or refused records produce bounded scrubbed diagnostics and incomplete coverage; numeric overflow and malformed scalar types are isolated to that record, preserving valid companions. Valid foreign repositories are outside scope. Machine paths and raw process-start strings are omitted from browser output.

An inaccessible or missing directory fails the source, retaining scheduler last-good data as stale. A readable empty scope establishes no observed runs. Malformed-only data never establishes empty coverage. File mtime and stage publication age do not establish process liveness: this producer records transitions, not periodic pulses.

For each valid observation, the default probe invokes the existing `p4b_heartbeat_status` helper from the trusted checkout against a private immutable JSON snapshot. The fixed shell argv and scrubbed environment prevent browser command injection or inherited credentials. The helper supplies canonical exact process-start/PID semantics: an exact match establishes running, rc1/empty or a reused PID establishes crashed, missing identity or indeterminate probes remain unknown, and valid done records remain done. At most four nonterminal process probes run per fetch. Each subprocess has a two-second maximum, 4 KiB output bound and bounded process-group cleanup; further rows remain unknown with incomplete coverage. Normalized done records need no process probe, matching the canonical helper's terminal branch. All probes/file reads share the source's monotonic deadline, with cleanup time reserved within it. Deadline exhaustion fails publication rather than turning unprobed rows into fresh evidence. The scheduler offers a five-second polling target with two shared workers; it cannot guarantee cadence while other bounded sources occupy them. A ten-second source deadline is an integration setting, not a separate per-record allowance.

The `cockpit-live-agents/v1` sample has `live`, `terminal`, observation time, `hasObservations`, `coverage_complete` and diagnostics. Rows are keyed by repository plus genuine run ID. Each row retains its separate process-status observation time, reached stages, invocation timing, adapter start/effective budget/measured elapsed, adapter exit/result, final summary fields, POST and acknowledgment evidence. Future, non-finite, invalid or zero-budget timing becomes unavailable. Done observations leave the active list.

## Evidence and clocks

Only a proven-running adapter with a recent comparable process observation can tick from `adapter_started_at_epoch`. The client expires extrapolation after ten seconds, independently of SSE connection health. A failed/stale envelope, unknown process or crashed owner stops the adapter clock at its last measured or verified-running value. A bounded per-process-instance cache publishes that value and its observation time; without prior compatible evidence, elapsed is unavailable. Process-start identity, PID, head and adapter start must match before a cached value is reused, so a reused PID does not inherit elapsed. The separate “Since invocation start (wall time)” caption reports invocation age at the current comparable observation, including later crash/unknown probes; it never claims the owner ran for that duration and never consumes adapter budget. The stopped-clock caption explicitly refers to the adapter. Posting holds reported adapter elapsed; posting duration does not count against adapter execution. Missing adapter start or budget shows unavailable rather than a prototype denominator.

Near timeout starts at 80 percent of the observed effective budget. Crossing the budget while still running reports “Budget exceeded · no terminal outcome observed”; it does not fabricate an exit/verdict. A real adapter exit124 supports a timed-out label. A canonical crashed process has a distinct boulder label. Runtime hazards are advisory and never establish review or merge clearance. Unknown and stale rows withdraw fresh coverage; retained crash/timeout hazards visibly retain their observation age.

The panel lists finished runs behind a disclosure button whose text carries the count ("N finished runs observed · show"); the list is collapsed by default, keeps one keyed item per run so repeated samples never recreate nodes, scrolls past 320px, and every sentence stays available as text. When the last finished run leaves, focus on the disclosure moves to the live summary before the disclosure hides. The one-sentence empty state uses the shared dashed `p.empty` box.

`adapter_verdict` alone is adapter output. Only `summary_emitted` plus `review_posted` on a non-dry run supports a posted-outcome readout. Final exit, verdict and acknowledgment remain separate: a posted approval with failed acknowledgment and exit7 remains posted with failure disclosed. The terminal readout adds no history rows or spend. The pure `join_history(terminals, history)` can annotate already-published history on compatible repository/run ID and PR/head/reviewer/start fields; conflicts produce diagnostics, unmatched IDs remain pending observation, and all existing rows/amounts are preserved. It never rescans ledgers or refreshes approvals.

## Rendering and verification

`assets/live_agents.js` registers the `agents` panel against `live_agents`. Persistent keyed cards retain stage/meter nodes through repeats, interruptions and recovery. Cards use the shared state badges, provider chip, repo/PR, four observed stages, adapter meter with an 80 percent tick, invocation caption and run/PID footer. Normal entry is 360 ms with the shared ease; stage pulse is 1.4 s ease-in-out; fill is 700 ms with the shared ease and colors 360 ms. Manual reduction and live OS preference remove animations/transitions and reset transforms while preserving every label/control; they do not freeze a loop at an arbitrary phase. The source and reference PNGs establish layout/tokens; actual browser interpolation, interruption, both 390 px themes and live reduced-motion switching require separate acceptance evidence.

`tests/test_cockpit_live_agents.py` uses fake files/status seams and the actual canonical helper with stub `ps` to cover identity, exact leading whitespace, dead/reused/denied processes, no-follow/oversize refusal, source/record/deadline/probe caps, old publication, terminal evidence and amount-preserving joins. Actual-main startup constructor capture covers unset/empty/absolute directory selection, relative/over-bound refusal, observation from that selected directory and immutable selection after environment mutation; unrelated launch boundaries are fake. `tests/test_cockpit_live_agents_ui.cjs` exercises the actual projection/renderer for threshold, barrier/posting, stale clock withdrawal, terminal readouts and keyed node retention; CSS assertions are declarations, not measured visual acceptance. Focused expected duration is under two seconds; tests use no network, credentials or paid adapter.
