# Scoped owner admin overrides

An admin merge through `gh-as-author.sh` requires `BREAK_GLASS_ADMIN=<full-PR-URL>@<full-head>` and `MERGEPATH_OWNER_ADMIN_AUTHORIZATION`, a version-1 JSON record with `pr_url`, `head_sha`, `authorized_at` (UTC seconds), `authorization_quote`, `allow_needs_human_review` and `allow_codex_inflight`. Both allow fields are explicit booleans. Inherited repository options before either command verb are recognized. The actual command must contain exactly one matching `--match-head-commit`.

The `gh-pr-guard.sh` admin hook also requires `BREAK_GLASS_ADMIN` to equal the resolved PR URL and full head exactly. A shape-valid marker for a different PR, repository or head refuses with exit 2 and a diagnostic naming the expected marker; unresolved PR URL or head data fails closed before the admin branch. `--admin=false` retains the ordinary merge path, while `--admin=true` requires the same exact binding as `--admin`. This defense in depth retains the writer's server-side head precondition and operator-attestation record; it does not independently authenticate owner approval. Native coverage lives in `tests/test_gh_pr_guard.sh` (#2684).

For merge handling, the wrapper recognizes literal `gh pr merge` commands. Other literal built-in `gh` commands retain their non-merge paths; aliases and executable extensions are rejected because their expansion can hide an admin merge. Repository options are recognized before `pr`, between `pr` and `merge`, or among the merge arguments: `--repo VALUE`, `--repo=VALUE`, `-R VALUE`, `-RVALUE` and `-R=VALUE`. Classification runs for every author-wrapper command, including non-merge writes. Only the repository options above may precede the PR subcommand: a layout such as `gh pr -b VALUE comment` is refused rather than passed through as unclassified. Put body options after `comment`, and merge options after `merge`; unsupported pre-verb option bindings remain refused.

The action flags `--admin`, `--auto` and `--disable-auto` accept a bare flag or an attached boolean: `=true`, `=t`, `=1`, `=false`, `=f` or `=0`, without case sensitivity. A separate following word is not that flag's boolean value. The value-taking options `--match-head-commit`, `--body`/`-b`, `--body-file`/`-F`, `--subject`/`-t` and `--author-email`/`-A` accept a separate value or `=VALUE`; the short forms also accept an attached value, such as `-bVALUE` or `-b=VALUE`. Option values remain values when they begin with a hyphen. Strategy and deletion option names are `--squash`/`-s`, `--merge`/`-m`, `--rebase`/`-r` and `--delete-branch`/`-d`; their arguments are forwarded to `gh`, which still validates CLI semantics. After `--`, arguments are positional; the classifier accepts at most one PR selector.

Unknown merge-option names and ambiguous short-option clusters are refused, even if another spelling is accepted by an upstream `gh` release. Use explicit flags from this finite grammar. Additional spellings require a separately reviewed parser change with adversarial coverage; this documentation does not widen the grammar. Recognition of `--auto` or `--disable-auto` does not release the native merge-queue or owner-action restrictions.

This parsing classifies the actual argument vector; it grants no authorization or merge clearance. The admin path still requires the exact PR/full-head binding, operator-attestation record and independent merge gates below. Raw REST and GraphQL pull-request merge mutations through the author wrapper are refused; GraphQL payloads require one literal query so a file or stdin cannot conceal a merge mutation. The contract scopes authorization and audit evidence to the admin pull-request merge path described in #1803. General branch merges, direct ref updates and Git pushes use their separate branch-write controls; this change does not sandbox every operation available to an owner credential.

The batch helper rechecks the authorized PR URL and head immediately before mutating review threads. The wrapper refuses a different PR/head, a future timestamp, an empty quote, an unreadable API, a later human-review escalation without explicit authorization, and an unanswered Codex request without explicit authorization. `human-hold` and `policy-violation` require human label removal. The wrapper posts the quote, timestamp, exact tuple and observed red gates before merging, verifies the comment's author/body, and rechecks the head, blocking labels and Codex request/response state. Each `gh` subprocess made by the owner-authorization preflight has a 300-second timeout and fails blocked on expiry. This bound does not cover the final merge writer. GitHub's head precondition closes the final push interval; request and label observations remain client snapshots.

The writer inventories the exact head's check rollup through a GraphQL cursor walk, including both check runs and commit statuses. Each page must identify the same canonical open PR, head, base commit and base branch, and the returned commit must match the authorized full head. Page shapes, context types and identities, pagination booleans, advancing cursors and consistent total/type counts are validated; duplicate contexts, missing or failed pages and incomplete totals refuse the action. An explicitly null rollup on the verified commit or a complete zero-count connection represents an empty inventory; missing response fields do not. Complete histories at and above 100 contexts are supported.

Every context retains its own identity and producer information during observation; the writer never selects a successful context by name across runs or producers. Every non-terminal check run and every check run or commit status outside the existing successful/neutral/skipped states contributes its name to the sorted non-green inventory. The published version-1 record remains unchanged. The complete check observation is repeated before publishing or reusing a record, and after its author/body/time-order readback; changed context identities, producer information or observed state refuse publication or the final writer respectively. The read-only authorization check uses the same complete inventory and pre-mutation fence. Existing label, escalation and Codex exception rules are rechecked before publication and after readback, followed by a final PR tuple and blocking-label read. These are finite client observations, not an atomic GitHub transaction: a change after publication can leave the recorded snapshot comment while preventing the merge, and GitHub's head precondition remains the final push fence.

The weekly audit validates author, PR/head and authorization/comment-creation/comment-update/merge timestamp order, and reports those records separately from unexplained violations, including records on otherwise compliant PRs and their recorded non-green gates. A recorded instruction preserves the operator's account of the owner's authorization; it does not independently authenticate a local chat transcript. The audit requires an explicit needs-human-review exception whenever that label was present at merge, regardless of when it was added; human-hold and policy-violation never receive an exemption. It also reconstructs unanswered Codex requests from paginated comments, reviews and inline comments bounded by the merge timestamp; a response arriving after merge cannot validate an earlier override lacking the in-flight exception. An author or Codex-bot comment created before merge and edited afterward leaves its original request/status body uncertain, requiring the in-flight exception. Exact, untrimmed Codex review commands are matched without case sensitivity, consistent with the shared request-evidence selectors. The latest head-anchored Completed review-summary row is terminal delivery at its update time, while Running remains in flight; this observation grants no review clearance. An existing record is reused only when its creation and update timestamps follow authorization and are not in the future; author/body/time-order readback is required for reused and newly posted records. Read failures and malformed records grant no audit exemption.

An operator who fabricates an instruction while holding the owner credential can misrepresent an override as recorded. The record identifies that publisher and preserves the quoted claim for review; it is not independent proof that the owner gave the instruction. Authenticating the owner through a separate decision channel is a stronger contract that requires an explicit owner scope decision.

The CODEOWNERS deadlock helper accepts `--authorization-file` with an array of version-1 records and selects exactly one record for each canonical PR URL/full head returned by GitHub, including renamed repositories. Missing, stale or duplicate matching records refuse that PR; CLEAN PRs keep the ordinary merge path. A single-PR call may use the scoped authorization environment variable instead. Provider-response observation may recognize a complete abbreviated Reviewed commit field; it grants no review clearance and cannot replace the merge gates.

The batch helper selects and validates the exact owner record before its first mutating thread-resolution gate. Unreadable, malformed, stale or ambiguous authorization cannot resolve or reclassify any finding. The preflight observes Codex under the bot identity parsed from the immutable governing base policy; malformed or unreadable policy refuses the merge. A changed base or head after recording also refuses. The published record retains that observed governing bot identity, which the weekly audit uses for historical response observation even after the current policy changes.

The observed automatic `PR opened` summary may be terminal with no commit anchor (#2642). For idleness only, recognize exactly one trusted v1 machine record with completed/null-SHA code review, paired false or paired null finding flags and dormant security review, paired with one consistent unanchored Completed table row and valid completion time within its comment observation. Null finding flags describe no finding verdict; only terminal activity is recognized. Duplicate, malformed, contradictory, unsupported, true or mixed finding flags and ambiguous shapes remain unknown. GitHub comment times have whole-second precision, so fractional UI completion time is compared in that same second. This summary contributes no response time or head association: an unanswered request, other running/unknown summary, edited historical evidence, moved head and all review/approval/hold gates retain their existing behavior. The narrow observation grants no external-review clearance or new owner exception.
