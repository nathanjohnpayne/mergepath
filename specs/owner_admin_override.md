# Scoped owner admin overrides

An admin merge through `gh-as-author.sh` requires `BREAK_GLASS_ADMIN=<full-PR-URL>@<full-head>` and `MERGEPATH_OWNER_ADMIN_AUTHORIZATION`, a version-1 JSON record with `pr_url`, `head_sha`, `authorized_at` (UTC seconds), `authorization_quote`, `allow_needs_human_review` and `allow_codex_inflight`. Both allow fields are explicit booleans. Inherited repository options before either command verb are recognized. The actual command must contain exactly one matching `--match-head-commit`.

Raw REST and GraphQL pull-request merge mutations through the author wrapper are refused; callers must use the head-pinned `gh pr merge` path. Author GraphQL API payloads require one literal query so an input file or stdin cannot conceal a pull-request merge mutation. The contract scopes authorization and audit evidence to the admin pull-request merge path described in #1803. General branch merges, direct ref updates and Git pushes use their separate branch-write controls; this change does not sandbox every operation available to an owner credential.

Wrapper payloads must name literal built-in `gh` commands; aliases and executable extensions are rejected because their expansion can hide an admin merge. The batch helper rechecks the authorized PR URL and head immediately before mutating review threads. The wrapper refuses a different PR/head, a future timestamp, an empty quote, an unreadable API, a later human-review escalation without explicit authorization, and an unanswered Codex request without explicit authorization. `human-hold` and `policy-violation` require human label removal. The wrapper posts the quote, timestamp, exact tuple and observed red gates before merging, verifies the comment's author/body, and rechecks the head, blocking labels and Codex request/response state. Each `gh` subprocess made by the owner-authorization preflight has a 300-second timeout and fails blocked on expiry. This bound does not cover the final merge writer. GitHub's head precondition closes the final push interval; request and label observations remain client snapshots.

The writer refuses a check rollup at the CLI's 100-context ceiling rather than publishing a potentially incomplete red-gate inventory. This conservatively refuses an exactly complete 100-context history too.

The weekly audit validates author, PR/head and authorization/comment-creation/comment-update/merge timestamp order, and reports those records separately from unexplained violations. A recorded instruction preserves the operator's account of the owner's authorization; it does not independently authenticate a local chat transcript. The audit requires an explicit needs-human-review exception whenever that label was present at merge, regardless of when it was added; human-hold and policy-violation never receive an exemption. It also reconstructs unanswered Codex requests from paginated comments, reviews and inline comments bounded by the merge timestamp; a response arriving after merge cannot validate an earlier override lacking the in-flight exception. An author comment created before merge and edited afterward leaves its original request body uncertain, requiring the in-flight exception. Read failures and malformed records grant no audit exemption.

The CODEOWNERS deadlock helper accepts `--authorization-file` with an array of version-1 records and selects exactly one record for each canonical PR URL/full head returned by GitHub, including renamed repositories. Missing, stale or duplicate matching records refuse that PR; CLEAN PRs keep the ordinary merge path. A single-PR call may use the scoped authorization environment variable instead. Provider-response observation may recognize a complete abbreviated Reviewed commit field; it grants no review clearance and cannot replace the merge gates.

The batch helper selects and validates the exact owner record before its first mutating thread-resolution gate. Unreadable, malformed, stale or ambiguous authorization cannot resolve or reclassify any finding. The preflight observes Codex under the bot identity parsed from the immutable governing base policy; malformed or unreadable policy refuses the merge. A changed base or head after recording also refuses. The weekly audit receives its governing configured bot identity for the same response observation.
