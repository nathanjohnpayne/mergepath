# Repository Rules

Agents must treat every entry here as a binding constraint, not a suggestion. If a proposed change would violate a rule below, stop and flag the conflict before proceeding.

## Structure Invariants

- Canonical root files must always exist: README.md, AGENTS.md, CLAUDE.md, DEPLOYMENT.md, CONTRIBUTING.md, .ai_context.md
- `CLAUDE.md` must contain only a reading-order pointer to `AGENTS.md`. It must never duplicate instructions from AGENTS.md or any other file.
- `AGENTS.md` is a lightweight index pointing to `docs/agents/`. Agent instructions live in focused sub-files under `docs/agents/`.
- Tool folders (.cursor/, .claude/, .vscode/) must contain configuration only—no instructions, no behavioral rules.
- No new top-level directories without justification documented in AGENTS.md or a plans/ entry.

## ESLint policy

Any repo with a root `package.json` MUST ship an `eslint.config.js` flat config at the repo root with at least the `@eslint/js` recommended ruleset, plus framework plugins appropriate to the stack (e.g., `typescript-eslint` for TypeScript, `eslint-plugin-astro` for Astro, `eslint-plugin-react` + `eslint-plugin-react-hooks` for React).

Repos without a root `package.json` (Mergepath itself is shell-only, for example) are exempt. The CI check (`scripts/ci/check_eslint_config_present`) early-outs with a not-applicable log line in that case.

Use the flat config format (`eslint.config.js`); legacy `.eslintrc.*` formats do not satisfy this rule. A starter config that covers JS + TS + Astro + React lives at `examples/eslint.config.js`. See `docs/agents/code-modification-rules.md` § ESLint flat-config policy for the rationale and the per-framework setup notes.

## Forbidden Patterns

- Never push directly to `main`. All changes must go through a pull request—even single-line fixes and documentation updates. The only exception is if the human explicitly authorizes a direct push in chat as a break-glass override.
- Instructions must not be duplicated between root files and tool folders.
- `dist/` must not be edited manually. Regenerate through the build system only.
- Tests must not be deleted to force a build to pass.
- Secrets must never be committed. Use environment variables or a secrets manager.

Required for `CLAUDE.md` step 8 Phase 4a (automated external review via the OpenAI Codex GitHub App) — missing a script silently forces callers to Phase 4b fallback or drops the feedback loop.

Enforces the Codex P1 unresolved-thread merge gate from #235. Gate is OFF by default (`codex.p1_gate.enabled: false`) everywhere except mergepath, which sets it `true` as the v1 narrow-start enforcement target.
- check_gh_as_author: `tests/test_gh_as_author.sh` and `tests/test_gh_pr_guard.sh` must exist and pass. Covers the #241 wrapper (`scripts/gh-as-author.sh`) and the identity-check addition to `scripts/hooks/gh-pr-guard.sh` that prevent the gh keyring active-identity glitch from landing a PR under the wrong account.
- check_coderabbit_config: when `.coderabbit.yml` is present, it must parse as YAML, and (in the Mergepath template repo only) set `reviews.profile: chill` — `assertive` re-enables 🧹 Nitpick comments per CodeRabbit's profile semantics. The file's existence is required *only* when `.github/review-policy.yml` does not have `coderabbit.enabled: false`; the sub-D wizard (#248) intentionally deletes `.coderabbit.yml` and flips `coderabbit.enabled: false` together when bootstrapping a private consumer repo (CodeRabbit's free tier is public-only), and the check honors that combined state. See #237 for the profile rationale (the 2026-05-13 sweep surfaced 56 unresolved nit threads across 9 repos, none substantive) and #256 for the private-repo scoping. Requires `yq` (mikefarah/yq v4+) on the runner.
- check_coderabbit_wait: runs `tests/test_coderabbit_wait_status_probe.sh` to verify `scripts/coderabbit-wait.sh` posts at most one timeout status probe, surfaces its reply in JSON without changing exit-4 semantics, and never treats a status reply as CodeRabbit clearance (#417).
- check_eslint_config_present: enforces the ESLint policy above. If `package.json` exists at the repo root, `eslint.config.js` must exist at the repo root and parse cleanly under `node --check`. Repos without a root `package.json` pass with a log line.
- check_eslint_config_policy: runs `tests/test_eslint_policy_check.sh` — unit tests for the policy check itself.
- check_disagreement_detector: `scripts/disagreement-detector.cjs` + `tests/test_disagreement_detector.sh` + the fixture directory `scripts/ci/fixtures/disagreement-detector/` must exist, and the fixture-driven suite must pass. The detector module holds the decision logic for `.github/workflows/agent-review.yml`'s `detect-disagreement` job — the workflow `require()`s it so the live job and the test share one implementation. The check also asserts the workflow still references the module (re-inlining the logic would let it rot silently). The detector scopes "live disagreement" to the current HEAD, takes the latest non-DISMISSED review per reviewer, and only fires `needs-human-review` when allow-listed reviewers conflict on `pr.head.sha` — closing the #259 false-positive where a stale CHANGES_REQUESTED re-applied the label after a clean APPROVED.
- check_verify_propagation_pr: `scripts/workflow/verify-propagation-pr.sh` + `tests/test_verify_propagation_pr.sh` must exist and the fixture-driven suite must pass. The verifier is the security-load-bearing teeth of the propagation-PR review lane (#264 / #268, REVIEW_POLICY.md § Phase 3.5): it byte-compares every file a sync PR changes against `mergepath@<sha>`'s content + manifest, so the lane only ever skips Phase 4 external review for a PR that is *provably* a verbatim mirror of already-reviewed content. A path-confinement-only check would be a hole — `.github/workflows/*` is itself propagation surface — so the check is a real content comparison sourced entirely from the immutable public `mergepath@<sha>` the PR's branch name points at.
- check_propagation_closure: the INVERSE of check_sync_manifest (#519/#521). Where check_sync_manifest validates every *declared* `requires:` is covered, this scans references *out of* every propagated `scripts/ci/check_*` + canonical `.github/workflows/*` file and fails if any on-disk `tests/`+`scripts/` reference is undeclared (not an exact manifest path, not inside a kit, not in any `requires:`). An undeclared, on-disk, propagated dependency does not travel to consumers, so the referencing tool fails closed at consumer lint time — the 3rd-occurrence drift class fixed reactively in #526. Skips refs that do not resolve to a real file (fixture strings, doc examples) and an explicit allow-list of orchestrator/mergepath-internal paths (the propagation engine, bootstrap seeders, the weekly-sweep pipeline, and self-tests of checks never wired into a consumer's repo_lint.yml). Requires `yq` (mikefarah/yq v4+); runs `tests/test_check_propagation_closure.sh` as its regression net. SKIPs on a consumer checkout (manifest absent + `scripts/sync-to-downstream.sh` absent), same posture as check_sync_manifest.
- check_doc_ownership: `.mergepath-sync.yml` must carry a `doc_ownership:` block that classifies EVERY `docs/agents/*.md` file on disk with EXACTLY ONE of `canonical` / `per-repo-owned` / `hub-only` (#780). Zero classes and more than one class both fail; so do a stale entry (a declared path that no longer exists), an out-of-scope entry (a path outside `docs/agents/`), an unknown class value, an unbacked `canonical` claim (classified canonical with no `paths:` entry and no `pending_manifest: true` + `note:` recording the deferral), and a `per-repo-owned`/`hub-only` doc that a `canonical`/`kit` entry would verbatim-mirror (the #744 clobber invariant, extended from check_sync_manifest's hard-coded denylist to the full inventory). A ninth arm cross-reads `check_sync_manifest`'s `IDENTITY_DOCS_DENYLIST` and fails if a denylisted doc is classified `canonical`, so the two declarations of the same governance fact cannot drift apart. `bootstrap-seeded` is deliberately NOT a class: bootstrap describes initial delivery, not durable ownership. A mixed document is transitional debt to be split — classify it by dominant ownership and record the split in `note:`, never invent a fourth class. A PR that adds a `docs/agents/*.md` file must add its `doc_ownership:` entry in the same PR. Requires `yq` (mikefarah/yq v4+); runs `tests/test_check_doc_ownership.sh` as its regression net; SKIPs on a consumer checkout (manifest absent + `scripts/sync-to-downstream.sh` absent), same posture as check_sync_manifest.
- check_git_identity_hygiene: no repository may carry a local- or worktree-scoped `user.name` / `user.email` / `user.signingkey` / `commit.gpgsign` / `tag.gpgsign` override, `.git/config` must be byte-identical across a `repo_lint` run (`--snapshot` early, the plain check last), and — on mergepath only, gated on the `scripts/sync-to-downstream.sh` marker — no tracked shell script or Markdown doc may write one of those keys through a `git config` that names neither a target repository (`-C`, `--git-dir`, `--file`, `--blob`) nor an out-of-repo scope (`--global`, `--system`). An override set to the empty string is an override: it masks the global value instead of deferring to it, and `git var GIT_AUTHOR_IDENT` fails with "empty ident name" rather than falling back. The lookup passes `--includes`, because a scope-restricted read has includes off by default and an `include.path` supplying an identity key is a local-scope override every commit obeys while a plain `--local --get-all` reports nothing. It then walks the same include graph a second time — following `include.path` and `includeIf.<condition>.path` alike and IGNORING the conditions — because `--includes` evaluates an `includeIf` against the *current* checkout: an `includeIf "onbranch:release"` target that sets `user.email` reads as absent while the check runs on `main` and applies the instant that branch is checked out, with no write at that moment for a later run to catch. The entry is repo-local and durable either way, and the invariant asserted is that the repository carries no local identity override, not that none is active this second. That walk resolves an include path the way git does, `~user/…` through the passwd database included — treating it as a relative path turned `~alice/config` into a nonexistent `<parent-dir>/~alice/config` and dropped a target git expands and obeys — and FAILS CLOSED on a path it cannot expand, because git performs its own expansion and "this check could not read it" must not be recorded as "there is nothing there"; a path that resolves to a file which does not exist is NOT a failure, since git ignores a missing include and it carries no identity. The failure generates its remediation from the offenders it found — one deduplicated `--unset-all` per offender actually found — that is, per distinct key *and* scope *and* origin file, so three keys in one file yield three commands and one key set in two scopes (or in both `.git/config` and an included file) yields one command each, in the scope that actually holds the value, against the file that actually holds it (an include target, not the parent config), and prefixed with `git -C <inspected repo>` because the inspected repository is routinely not the caller's current directory — because a fixed command list would omit checked keys, name the wrong scope, and edit the wrong repository, so following it would clear nothing. The static scan joins backslash-continued lines into logical commands before matching, since a write split as `git \` + `config user.email …` matches nothing line-at-a-time, and then cuts each logical command at shell separators (`&&`, `||`, `;`, `|`) so that a target or read flag belonging to one command cannot suppress the write standing next to it on the same line. In Markdown the cut runs on backticks as well, because a doc sentence carries no shell separators and would otherwise be judged as a single piece: setting the sanctioned `--global` form beside the forbidden one — which is how any doc explaining this rule reads — then lets the first suppress the second, making the act of writing the rule down the thing that silences it. It recognises the value token by what it is NOT — an option, a `#` comment, a redirection, a closing command substitution or code span, or a line continuation — rather than by an allow-list of opening characters, which exempted every path-valued write of `user.signingkey` — the key that decides which key signs every commit, and the one almost always given a path such as `~/.ssh/id_ed25519.pub` or `/tmp/key.pub`. A suppressing flag is honoured only where a flag can be — as a whole option TOKEN in the option region between the `git` word and the identity key — because searching the whole invocation let text that is not a flag act as one: `--get` inside the value read as a read (`git config user.email` given the value `author--get@example.com` writes that address), and `--global` in prose or in an adjacent word no separator split off covered the bare write next to it, which is the Markdown `--global` hole one layer below the code-span cut; every form git accepts puts its options before the key, and a trailing `--global` does not scope the write at all — `git config user.email <addr> --global` writes the LOCAL config. Keys are matched case-insensitively, since a git config key is case-insensitive in section and name alike and `git config User.Email <addr>` writes exactly the override a later lowercase read returns; a path-qualified executable counts, since `/usr/bin/git config user.email <addr>` writes the file a bare `git` writes; and "shell script or Markdown doc" is taken at its word — extensions are matched case-insensitively across the Markdown spellings GitHub renders (`.md`, `.markdown`, `.mdown`, `.mkd`) and the shells scripts get written in, and an extensionless file is classified by shebang including `#!/usr/bin/env sh`, which has no slash before the interpreter word and so escaped a `/sh` substring test, because a surface the classifier skips has no gate on it at all. Reads (`--get*`, `--list`), removals (`--unset*`, `--remove-section`), and the ephemeral `git -c key=value <cmd>` form are not writes and are never flagged; a deliberate exception carries `GIT_IDENTITY_SCOPE_EXEMPT: <reason>` — spelled `# …` in a script or a doc code block and `<!-- … -->` in Markdown, where it renders invisibly — which must BE a comment and not merely appear on the line, since honouring it anywhere let string data and plain prose switch the scan off (an `echo` of the marker exempted the write beside it, and so did a sentence naming it with the write in a code span), and which exempts the logical command it terminates but not the other physical lines joined to it, since a self-contained write on its own line is judged on its own marker; in Markdown the marker is read with code spans stripped, so a mention inside backticks counts as a citation rather than a use, which is what kept the paragraphs documenting this very check from ever being scanned; a doc example is better rewritten into a form that will not run — key and value in separate spans, or a placeholder value — than exempted, since an exemption leaves a pasteable command in place; every offending line in a joined group is reported, not just the first. `MERGEPATH_ALLOW_LOCAL_GIT_IDENTITY=1` opts a checkout out of the live-repo assertion. Closes #777, where `REVIEW_POLICY.md` § Git Identity Switching instructed agents to run a bare repo-local `git config user.email` carrying the fixture address `nathan@nathanjohnpayne.example`; two commits reached `main` misattributed to that undeliverable address and unsigned. The static scan covers Markdown because a documented snippet an agent executes is a writer like any other. Runs `tests/test_git_identity_hygiene.sh` as its regression net and then repeats the identity assertion and the baseline comparison, so a suite that writes the live config cannot slip past the check that runs it — and asserts the repository METADATA survived too, because both of those read the repository through `.git` and a suite whose fixture cleanup lands one directory too high (`rm -rf "$ROOT/.git"`) took the evidence with the subject and left every post-suite assertion with nothing to check; what they need is captured before the suite starts and the baseline is copied outside the repository, since a deleted config is not byte-identical to its snapshot and the diff is still the actionable half when the baseline itself is gone.
- check_session_finalization: `scripts/session-finalization-check.sh` + `tests/test_session_finalization_check.sh` must exist and pass. Guards the session-closeout workflow against orphaned local implementation work, stale stashes, and dirty auxiliary worktrees.
- check_ci_scripts_wired: every `scripts/ci/check_*` file (executable or not — see r5 below) must be invoked as an explicit `run: ./scripts/ci/check_X` step in `.github/workflows/repo_lint.yml` OR in the optional consumer-local annex `.github/workflows/repo_lint_local.yml` (#601), OR carry a documented exemption on a `# WIRED-EXEMPT: check_X — reason` line in either file. The guard scans the UNION of the two files; the annex absent → identical to the single-file scan. Comment-only mentions of a check (e.g. inside a comment block) do NOT count as wiring — only real `run:` lines. Pure-bash so it can run before the yq install. Catches the #269 failure mode where a check ships on disk and passes review under its own tests yet never actually executes in CI because the matching workflow step was never added. The check itself must be wired into repo_lint.yml. Fleet enforcement (#601): `repo_lint.yml` is a canonical, consumers-all entry in `.mergepath-sync.yml` (previously it was seeded exactly once by the bootstrap template-mirror and never updated, so this wiring contract was enforced on mergepath only — consumers ran a bootstrap-era step subset against the full, kit-propagated `scripts/ci/`). A new check and its `run:` step land in the same PR and travel to consumers in the same sync PR (atomicity), so the contract holds on every repo at every sync point; `check_sync_manifest` asserts the manifest keeps the entry (canonical, consumers: all) and the `scripts/ci/` kit `requires:` it. Consumers wire their own repo-local checks (and record consumer-local exemptions) in `repo_lint_local.yml` — never by editing the canonical `repo_lint.yml`, which the next sync wave overwrites. Every step in `repo_lint.yml` must be consumer-safe: SKIP-guard hub-only checks via the `scripts/sync-to-downstream.sh` marker idiom, depend only on manifest-propagated files, or soft-pass when the backing script is absent (#590); the hub-only `tests/test_repo_lint_consumer_safety.sh` net runs every wired check against a consumer-shaped fixture tree and asserts each exits 0. **Residue invariance:** that net models a consumer by *stripping* files, so it can only test a check against files that are missing; the opposite shape — a hub-only file left *present* on a consumer by a bootstrap snapshot taken before the mirror exclusion existed — is enforced separately by the hub-only `tests/test_consumer_residue_safety.sh` net, which derives the consumer shape from `.mergepath-sync.yml` and asserts that for every wrapper, the presence of any subset of the hub-only paths it references never changes its verdict (exit status plus whether the canonical consumer-SKIP line was emitted) — measured from a fixture restored to its committed baseline before every probe, so a wrapper that writes cannot make one probe depend on the last. The wrappers that already violate this on `main` are grandfathered one by one in the suite's `KNOWN_RESIDUE_VIOLATIONS` ratchet, which records the WORST divergence class in each wrapper's lattice and fails equally on a new violator, a stale entry, and an escalated class — so the list can neither grow to buy silence nor outlive the bugs it records. "The hub-only paths it references" is measured by reading the wrapper's source, so two structural assertions guard that step: a wrapper that declares a consumer gate must reference at least one hub-only path — otherwise its gate reads a dependency the net cannot see and no lattice is ever built for it — or, when the gate legitimately reads nothing but the hub marker, `.mergepath-sync.yml`, or manifest-DELIVERED files, be recorded with that justification in the suite's `MARKER_ONLY_CONSUMER_GATES` ratchet, which fails on its own stale entries (a listed wrapper whose H is non-empty, or that no longer declares a gate, or that no longer exists), and every SKIP line such a wrapper emits must be spelled `<name>: SKIP (...)` — the literal the verdict pair greps for; the `SKIP: <reason>` form is reserved for tooling skips inside `tests/`. The practical rule for a new hub-only check: put the `scripts/sync-to-downstream.sh` marker test FIRST, above any test of the check's own hub-only artifacts, so the consumer-SKIP decision is a function of what the manifest delivered and not of what a stale bootstrap left behind. Note (#269 r5): the guard counts ALL `check_*` files regardless of executable bit. The earlier r3-r4 spec carved out non-executable files as "WIP skip", but repo_lint.yml runs `chmod +x scripts/ci/*` BEFORE this guard, so on CI every check_* is executable regardless of pre-chmod permission. Aligning the guard with production reality is more honest than enforcing a contract the workflow order silently breaks.
