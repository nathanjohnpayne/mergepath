## Repo-lint execution

Lint-fast supplies active npm Dependabot alternate-target refs through its bounded depth-one setup step before checking coupled families. It retains `persist-credentials: false`, fetches no unrelated branch history and fails on unavailable declared targets. The workflow-step fixtures in `tests/test_dependabot_coupled_groups.sh` and `specs/repo_lint_execution.md` own this checkout contract (#2464).

The required `lint` context is an aggregator over a fast live-assertion lane and a change-aware deep lane of three `deep-safety (...)` jobs: the consumer-smoke and residue legs run for every deep selection, the sharded complete consumer replay runs when the consumer shape or the lane itself changes (and on every main push and scheduled run), and the self-test legs run when an affected wrapper is enrolled in them. Pull requests that change CI implementation, propagation, or tests select the wrappers the dependency graph declares for those paths, or fail closed to the complete surface when a path is undeclared; governance documents and specifications request the deep legs in smoke mode. Main pushes, the daily schedule, and manual runs always select the complete surface. Do not add path filters to the aggregator itself: every pull-request head must publish exactly one stable `lint` result, and the aggregator must keep reading every deep job's result against the scope bit that selected it.

## Pre-push hook

The ignored `.mergepath/prepush-timings.tsv` cache records completed local check durations and starts the slowest selected checks first on later runs. It initializes without an existing cache; new measurements replace old duplicates while unselected historical measurements remain. Timing persistence is advisory: unavailable cache storage changes neither selected checks nor their outcomes. The existing native hook suite covers cold/warm cache behavior and passing/failing runs when storage is unavailable (#2539).

Install the repo-lint pre-push hook once per clone with `scripts/install-git-hooks.sh` (hub only; consumers do not receive it). The installer is idempotent and writes one key, `core.hooksPath=scripts/git-hooks`, to the clone's local git config, which every worktree of that clone shares; `--check` reports whether it is installed, `--uninstall` removes it, and it refuses to replace a different `core.hooksPath` without `--force`. From then on `git push` runs `scripts/repo-lint-prepush.sh` before anything leaves the machine, and a failing selected check blocks the push with the check named and its log tail printed.

The hook computes the pushed range against the merge base with the remote default branch, feeds the changed paths to `scripts/ci/repo-lint-scope.sh` (the classifier the CI `scope` job runs), and reads the step list and `run:` bodies from `.github/workflows/repo_lint.yml`, so it never keeps a second copy of the selection. It always runs the cheap live assertions (fast-lane steps whose wrapper is not in the dependency graph) and the graph-declared wrappers the classifier selects. Graph-declared wrappers the classifier does not select are skipped by default and run with `MERGEPATH_PREPUSH_LIVE=all`, which mirrors CI's whole fast lane. A changed path that no wrapper, trigger or full trigger declares makes CI's classifier fail closed to the complete surface, and CI keeps doing so; the hook does not (#2580). It re-classifies without those paths, names them in one `UNDECLARED PATH` line, runs only the live assertions for them, and leaves the expansion to CI's `lint` (`MERGEPATH_PREPUSH_LIVE=all` runs its wrappers here too, and adding `MERGEPATH_PREPUSH_DEEP=1` runs its deep steps). A complete selection for any other reason (a full trigger, a push to the default branch, a `mergepath-sync/*` head, no merge base) is unchanged. The run prints why its wrappers were selected (`N wrappers selected by path, M by undeclared-path fallback`), and `--plan` lists the expansion in the `fallback` and `deep_fallback` lanes. Declare a new script under the wrapper whose suite exercises it: `tests/test_repo_lint_optimization.sh` fails when a declared wrapper, or a suite it runs, names a top-level `scripts/*.sh` that the wrapper does not declare. The deep-lane steps the classifier selects (enrolled `--self-test` suites, the consumer-smoke and residue legs, the consumer replay) are listed and run only with `MERGEPATH_PREPUSH_DEEP=1`. Every check runs under `nice` (`MERGEPATH_PREPUSH_NICE`, default 10) with at most `jobs_max` at once (2 while the one-minute load average is below the CPU count, 1 once it is not, re-read during the run, #2842), so a loaded machine stays usable; `MERGEPATH_PREPUSH_JOBS` pins the concurrency instead. Each check starts without git's hook-local repository variables (`GIT_DIR` and the rest of `git rev-parse --local-env-vars`, which git exports to a hook run from a linked worktree), because under them a fixture `git init` reinitializes the real repository. The `jobs=` line and the verdict print the host load: a check that passes standalone but fails here on a saturated machine is usually an assertion pipeline such as `echo "$out" | grep -q …` under `pipefail`, which fails whenever `grep` exits on its match before the producer finishes writing, as it often does under load; read captured output through a here-string (`grep -q … <<<"$out"`) instead (#2575, #948). For every pushed branch, the hook creates a tool-managed detached worktree at its exact committed tip and retires it after the checks. Non-HEAD pushes are checked at their own tip; uncommitted or untracked original-checkout files cannot affect the result, including locally recreated committed deletions. It also needs the tooling CI provisions, ShellCheck and the Python packages (PyYAML, plus markdown-it-py for the deep lane), because several checks skip assertions and pass without them; a missing tool, unreadable/conflicting workflow pins or an installed package version that differs from those committed pins blocks the push as an environment error. Nested `python3` calls run through a launcher that executes the selected interpreter path, so a validated virtual environment keeps its packages. The launcher uses `/bin/sh` directly and preserves literal interpreter paths and arguments even when nested fixtures remove Bash from PATH. Package metadata is checked with an isolated Python invocation: install CI's pinned versions for some `python3` and, if it is not first on `PATH`, name it with `MERGEPATH_PREPUSH_PYTHON`. Run it by hand with `scripts/repo-lint-prepush.sh` (HEAD against `origin`'s default branch), add `--plan` to see the selection without running it, or `--paths-from <file>` to classify an explicit path list.

The hook's first output line is always `repo-lint pre-push: hook invoked for remote <name>`, so a push log without it means git never ran the hook. A checkout the hook cannot resolve fails the push with the cause named instead of passing it silently: git reporting the checkout as bare (a shared `core.bare = true`, which with `extensions.worktreeConfig` reaches every linked worktree of the clone at once), a top level that does not resolve, or a runner that is present but cannot be read or exec'd. Only a checkout with no runner at all soft-passes, and it says `SKIP`. `scripts/install-git-hooks.sh --check` checks the same bare state, requires the hooks path git resolves from the current worktree to hold an executable `pre-push`, and warns when a linked worktree inherits the relative `core.hooksPath`, which resolves against that worktree's own checkout (#2578).

CI stays authoritative. Branch protection keeps requiring the Actions `lint` check, because a result reported from a developer machine cannot be trusted, and CI also runs everything the hook skips by default. Bypass the hook only in an emergency, with `git push --no-verify` or `MERGEPATH_PREPUSH_SKIP=1 git push`. `tests/test_repo_lint_prepush.sh` (run in the fast lane by `scripts/ci/check_repo_lint_prepush`) proves selection parity: for each changed-path list it runs the workflow's own classify step and evaluates every job and step `if:` expression independently, and fails when the hook's plan differs, so a workflow or classifier change that the hook does not follow fails on the PR that makes it. Its one documented difference is the undeclared-path expansion: the hook's runnable lanes are compared with CI's selection for the same push without the undeclared paths.

Each repository sets how much of this runs locally in `.github/prepush.yml` (#2840); mergepath's copy sets every key, each at its built-in default except `full_suite: defer` and `max_minutes: 15` (#2841, below). Each key resolves as `--set KEY=VALUE` (repeatable, manual runs) over its environment variable over the file over the built-in default, and the run's `policy` line (a `policy` row under `--plan`) prints every effective value with its source: `default`, `.github/prepush.yml`, `env <NAME>` or `flag …`. The same line reports `retry_failed` and its source (`--retry-failed` or `MERGEPATH_PREPUSH_RETRY_FAILED`, #2843); it has no file key, because a retry is a per-push action rather than repository policy. The keys: `mode` (`MERGEPATH_PREPUSH_MODE`, default `full`): `full` runs the live assertions and the selected wrappers as described above, `selected` runs only the classifier's selected wrappers and leaves the live assertions to CI, `off` runs nothing and passes with a `skipped` line naming the source. `full_suite` (`MERGEPATH_PREPUSH_FULL_SUITE`, `run` or `defer`, default `run`) decides what a complete-surface selection runs, and `max_minutes` (`MERGEPATH_PREPUSH_MAX_MINUTES`, whole minutes, `0` for no budget, the default) caps the check time; both are described below. `deep` (`MERGEPATH_PREPUSH_DEEP` or `--deep`, default `false`) runs the selected deep-lane steps. `nice` (`MERGEPATH_PREPUSH_NICE`, default 10) is the checks' nice level. `jobs_max` (`MERGEPATH_PREPUSH_JOBS_MAX`, default 2) and `load_per_cpu_threshold` (`MERGEPATH_PREPUSH_LOAD_PER_CPU_THRESHOLD`, default 1) size the concurrency: `jobs_max` checks at once while the one-minute load average per CPU is below the threshold, one once it is not. The load is read again during the run (#2842, below); `MERGEPATH_PREPUSH_JOBS` or `--jobs` pins the concurrency for the whole run instead. A missing file means the defaults. Anything else that is not one YAML mapping of these keys with valid values (an empty or comment-only file, unparseable YAML, several documents, an unknown (or empty) or repeated key, a list or empty value, an out-of-range value, a directory or any symlink at the path, dangling or not) fails the run closed with exit 2 and the reason, even when the environment overrides the offending key; an invalid environment or `--set` value is refused the same way. An environment variable set to the empty string counts as unset, as `MERGEPATH_PREPUSH_NICE`, `_DEEP` and `_JOBS` always have, so the next tier decides. Nothing falls back to `off` or to the defaults. The file is a file of its own rather than a block in `.github/review-policy.yml`, which the propagation engine merges into every consumer and the review tooling reads, while this hook is hub-only local tooling that a consumer should be able to adopt without touching its review configuration. A hook run reads the copy in the pushed commit's own snapshot, the same tree the workflow, classifier and graph come from, so the commit that changes the policy is the first push to use it and an uncommitted edit changes nothing; manual runs read the checkout. It deliberately does not read the remote default branch's copy: the hook never fetches, so that copy is whatever ref the clone last saw (and there is none without a merge base), and a policy change could not be exercised by the PR that makes it. A branch gains no bypass from this, since the environment already overrides every key and CI's `lint` is unaffected. `tests/test_repo_lint_prepush_policy.sh`, run by `scripts/ci/check_repo_lint_prepush`, covers the missing-file default, the precedence of every key, invalid-file refusal, the pushed-commit copy and the shipped file (the defaults plus `full_suite: defer` and `max_minutes: 15`), and re-runs the first three against runner mutations that must fail them.

Hook runs on one machine take turns (#2581). Before its first snapshot the hook takes an exclusive `flock(2)` on `${XDG_CACHE_HOME:-$HOME/.cache}/mergepath/prepush.lock`, through `flock(1)` where it exists and through python3's `fcntl` on the same inherited descriptor otherwise (macOS ships no `flock(1)`; every host that can run the checks has a python3, since the run requires one), and holds it until its last check, so the kernel drops it with the holder and nothing is ever reaped by deleting a file; a host with neither tool fails the push closed as an environment error, and `MERGEPATH_PREPUSH_LOCK_TOOL=python3` forces the python3 path so a Linux runner can exercise what every macOS machine runs. The lock file records the holder's branch, pid, start time and progress, refreshed per completed check. A second push waits, printing `repo-lint pre-push: waiting for the run of <branch> (pid N, started HH:MM UTC, k of n checks)` every 30 s, and gives up with a nonzero exit after `MERGEPATH_PREPUSH_LOCK_WAIT` seconds (default 3600) rather than run concurrently; a holder whose pid is gone, or no longer runs the hook, is reaped with a message. The concurrency follows the machine for the whole run (#2842): before each check starts, and at most every 5 seconds (a fixed interval, not a setting) while the run waits for a free slot, the one-minute load is read again and the concurrency set between 1 and `jobs_max` by the same `load_per_cpu_threshold` rule that sized the start. A run that began on a busy host speeds up when the load falls, and one that began quiet slows down when it rises, with each change logged as `repo-lint pre-push: concurrency 1 -> 2 (host load 3.10 on 10 CPUs)`; checks already running are never stopped, and a load that cannot be read on a re-read keeps the current concurrency (at start it still gives `jobs_max`). `MERGEPATH_PREPUSH_JOBS` or `--jobs` pins the concurrency, disables the re-sizing and says so in the output. The `running N checks` line prints the starting concurrency, load average and CPU count. The lock itself is unchanged. `tests/test_repo_lint_prepush_load.sh`, run by `scripts/ci/check_repo_lint_prepush`, drives the concurrency up and down within one run through a fake `sysctl` whose load a check rewrites mid-run, covers the start-loaded, pinned and throttled cases, and re-runs them against runner mutations (one that pins the first reading) that must fail. Under the lock a leftover `prepush-<sha>.*` snapshot worktree from a killed run is retired with a message; a snapshot a `--committed-snapshot` process is still working in, and any worktree that is not a snapshot, are left alone. Manual runs (`--paths-from`, HEAD against the default branch, `--plan`) take no lock.

Re-run only what failed (#2843). Every hook run records, for each pushed branch, the commit it checked, a fingerprint of its selection (both scope readings, the lanes it ran, and every selected step's lane, job, name, `run:` body and env) and each selected check's result, in `${XDG_CACHE_HOME:-$HOME/.cache}/mergepath/prepush-results/<branch>.tsv` beside the hook lock. The file is local, never committed, and records not rewritten for 30 days are dropped. After a push fails, `MERGEPATH_PREPUSH_RETRY_FAILED=1 git push` (or `--retry-failed` on the runner) re-runs only the checks the record does not show passing, failed or never reported, when the pushed commit and the selection both equal the record's; the push passes when they all pass, and the record is rewritten with their new results. A changed commit or selection (another `MERGEPATH_PREPUSH_LIVE` or `MERGEPATH_PREPUSH_DEEP`, say), a missing, unreadable, incomplete or malformed record, and a manual run (which checks the working tree, not a committed snapshot) refuse the retry with the reason named and run the full selection: a missing record is never read as "nothing failed". The lock and the snapshot are unchanged. `tests/test_repo_lint_prepush.sh` covers each case, and a mutant that reads a missing record as a pass must let a failing push through there.

Defer the full suite and cap the check time (#2841). CI's `lint` runs every check whatever the hook does, so the hook may leave the expensive part to CI, but never silently: it names every step it leaves as deferred to CI, and a run that deferred anything says so on its last line (`PASS with checks DEFERRED TO CI (... deferred: <n> by full_suite=defer, <m> by the <N>-minute budget, named above)`, or, when a check failed, a closing `this run also DEFERRED checks TO CI` line after the failure). Under `full_suite: defer`, a change that selects the complete surface (a full trigger such as `scripts/ci/repo-lint-dependencies.json` or `.github/workflows/repo_lint.yml`, a push to the default branch, or a `mergepath-sync/*` head) runs the live assertions and only the wrappers its changed paths select on their own: a full-trigger path selects the wrappers that list it in the graph's `wrappers` map (and itself, when it is a `scripts/ci/check_*` wrapper), an undeclared path selects nothing, and every other path is classified as a pull request from an ordinary branch. Every other graph wrapper is listed under `deferring <n> wrappers to CI`, and `--plan` shows them in the `fallback` lane with a `defer` row naming the reason; `MERGEPATH_PREPUSH_LIVE=all` still runs them. Deferral needs the changed paths and a graph the classifier accepts: without a merge base, or when it rejects the graph, the complete selection runs and the hook says why. Under `max_minutes: N`, the hook does not start a check whose previous duration (the timing cache above) would end it more than N minutes after the first check started, nor any check once N minutes have passed. Checks already running finish; the ones not started are listed as deferred to CI and the run exits 0, unless a check failed, which blocks the push whatever the budget. The budget counts check time, not the wait for another run's lock, which `MERGEPATH_PREPUSH_LOCK_WAIT` bounds on its own, and a later `MERGEPATH_PREPUSH_RETRY_FAILED=1 git push` runs the unstarted checks, because the retry record holds them as `none`. Checks start one at a time from a feeder that hands `xargs` the next check only when a slot frees, which is where both the budget and the concurrency are decided; `xargs` still runs the workers, so an interrupt reaches every check as before. mergepath's own policy sets `full_suite: defer` and `max_minutes: 15`. `tests/test_repo_lint_prepush_defer.sh`, run by `scripts/ci/check_repo_lint_prepush`, covers the deferral (full trigger, undeclared path, propagation-lane head, partial selections untouched), a step that would pass the budget, a spent budget, a failed step that still blocks after deferral, `full_suite: run` unchanged, and a hook push of a committed deferring policy, and re-runs each property against runner mutations that must fail it.

## Direct checker runtime prerequisites

`scripts/codex-review-check.sh` needs one working structured YAML parser on the caller's PATH: mikefarah yq v4, Python3 with PyYAML, or Ruby with YAML and JSON. The shared `policy_yaml_to_json` selects them in that order; an installed executable alone does not prove its required modules or syntax work. Python's standard library does not include PyYAML. This requirement also applies to direct checker calls and approval continuation, without passing through `scripts/merge-clearance-gate.sh` (#2314).

The canonical caller inventory below describes checked-in job declarations, not a promise about software bundled into a future hosted-runner image. Every listed job currently selects `ubuntu-latest`; auto-clear and approval continuation do not explicitly install a parser. Their runner provisioning must retain one supported implementation. Repo-lint provisions pinned PyYAML in its isolated CI environment; that installation does not provision another job. Local and custom runners have the same prerequisite.
