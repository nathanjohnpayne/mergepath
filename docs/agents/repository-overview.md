# Repository Overview

This repository is **Mergepath**, the reference implementation of the AI Agent Tooling Standard. It provides a canonical starting structure for projects that require consistent behavior across multiple AI coding agents and development tools.

Primary stack: Markdown documentation, shell automation, YAML review-policy configuration, and the Mergepath Playground (static HTML + JS at `mergepath/playground/`). Agent role: maintain Mergepath's structure, the review-policy tooling and Playground, and the supporting developer workflows — ensuring documentation and tooling behavior do not drift over time. See [`BRAND.md`](../../BRAND.md) at repo root for the umbrella vocabulary.

The read-only credential-isolation audit reports matched authority names from its fixed inventory, without copying secret metadata into diagnostic labels. The output contract and regression coverage are in `specs/credential_isolation.md` and `tests/test_credential_isolation.py`.

The publisher structural fence prevents workflow and job concurrency for all three native required producers. The contract and mutation coverage are in `specs/required_check_publisher.md` and `tests/test_merge_clearance_gate.sh`.

The shared pull-request body parser and its standalone generated runtime are specified in [`specs/pr_body_contract.md`](../../specs/pr_body_contract.md). The weekly audit records per-PR parser timeouts, continues auditing later PRs, reports unaudited PRs when its time budget is spent, and fails incomplete runs.

Explicitly deferred CodeRabbit findings retain the `deferred-to-followup` ledger disposition and resolver tag. The recorder and resolver evidence contract is in `specs/review_feedback_accounting.md`.

The Playground's local simulator and public-repository loader read author-agent declarations at source column zero and fall back to the GitHub login for prose mentions or indented lines. Their reporting contract and regression coverage live in specs/mergepath_playground.md and tests/test_mergepath_playground.sh.

The hub-only Cockpit includes a read-only Fleet audit source: a thirty-minute schedule and authenticated manual refresh share one bounded subprocess and retain last-good rows on failure. Audit workers use the cached reviewer credential in an isolated cache; refresh does not invoke propagation. The separate confirmed-sync flow previews current hub/consumer evidence, requires explicit confirmation and runs the fixed author-wrapped executor; its contract is [Cockpit confirmed sync](https://github.com/nathanjohnpayne/mergepath/blob/main/specs/cockpit_sync.md). Its contract is [Cockpit Fleet](https://github.com/nathanjohnpayne/mergepath/blob/main/specs/cockpit_fleet.md).

The token-output gate's owning contract and execution-oracle corpus live in `scripts/ci/token_output_gate.py`. `printf -v NAME` and `printf -vNAME` assign only in option position before the format and `--`; operand-position spellings emit. The owner-ratified attached exemption is an allowlist: a target matching `^[a-z_][a-z0-9_]*$` except `_`, `auto_resume` and `histchars`; a literal format containing only `%s` conversions/plain text; literal values or one double-quoted plain ordinary-name expansion without modifiers, subscripts or arithmetic; no assignment prefix, redirection or wrapper; and the existing in-file builtin-provenance check. Other attached spellings remain conservative, and safe rejected forms carry written corpus declarations. The separate `-v NAME` and numeric-diagnostic scope remains unchanged. Finite callback-option provenance detection and the existing bounded quoted-target reader are retained; managed-variable denylists and per-case arithmetic/error/heredoc lexer annotations are removed. The scanner does not prove ambient shell state: imported `printf` functions can emit otherwise allowed arguments, and the noninteractive oracle does not settle terminal-only output. Those are explicit owner-accepted residuals. Existing captured diagnostics [#2058](https://github.com/nathanjohnpayne/mergepath/issues/2058), invalid-name indirection [#2059](https://github.com/nathanjohnpayne/mergepath/issues/2059) and separate-option diagnostic [#2061](https://github.com/nathanjohnpayne/mergepath/issues/2061) limits remain declared.

The token-output gate recognizes completed `name()` and `function name` headers whose brace or subshell body opens on a following line, including after inline or intervening shell comments. Helper discovery and function-body line spans consume the same matcher; function-local `set +x` receives no credit whether the function is called or uncalled. The called fixture is declared conservatism, not an invocation or control-flow model. Header parentheses are not mistaken for an empty body, and a header without a following compound command is not a definition. Multiline quoted data and real comment text are excluded using existing lexer context, including offsets remapped from child substitutions. Already-lexed executable substitutions inside interpolating heredocs remain discoverable while surrounding heredoc data, quoted delimiters and nested heredoc data stay masked. The separately measured preexisting adjacent-comment/unmatched-quote lexer limit remains declared under [#2080](https://github.com/nathanjohnpayne/mergepath/issues/2080).

The shared CI yq bootstrap installs mikefarah/yq v4.53.6 only after checking the downloaded Linux binary against its pinned SHA-256. Its local no-op behavior, test overrides and fail-closed install contract are specified in [`specs/yq_bootstrap.md`](../../specs/yq_bootstrap.md).

`scripts/ci/check_doc_ownership` is a fail-closed repository-integrity check. It validates the `doc_ownership` inventory and verifies that canonical agent documentation does not contain rendered relative links to hub-only documentation that consumers do not receive. Its Markdown extraction contract is defined in [`specs/doc_ownership_validation.md`](../../specs/doc_ownership_validation.md) and covered by `tests/test_check_doc_ownership.sh`.

Failed review triage preserves an exact-head registered approval only after two live observations match its event snapshot, while keeping classification and merge blocked. Bounded transient-read retries and the unchanged drift protection are specified in [`specs/approval_triage.md`](../../specs/approval_triage.md).

The Codex requester and same-agent merge fallback share the substantive review-run selector and approval predicate. Threaded replies alone cannot suppress a needed request, and P0/P1 findings in review bodies retain their approval boundary. See [`specs/codex_request_evidence.md`](../../specs/codex_request_evidence.md).

Blocked review diagnostics bind request age and acknowledgement to an exact `@codex review` command comment; later prose mentions do not replace that evidence. The diagnostic filter preserves requester deduplication and clearance behavior. Its contract and coverage are in [`specs/codex_request_evidence.md`](../../specs/codex_request_evidence.md) and `tests/test_codex_request_evidence.sh`.

The publisher structural fence pins both complete permission maps, excludes extra Checks-API writers and requires the phase-1 token binding. Its contract and mutation coverage are in `specs/required_check_publisher.md` and `tests/test_merge_clearance_gate.sh`.

Cockpit live observations read bounded local Phase 4b heartbeat records independently of accounting history. The launch-owned default directory, canonical process identity, observed adapter clock and separate POST/final-summary facts are specified in `specs/cockpit_live_agents.md`; shared HTTP/SSE and scheduling remain in `specs/cockpit_foundation.md`.

The Cockpit header shows nathanjohnpayne’s author GraphQL allowance first, obtained by a bounded fixed read-only worker using the canonical noninteractive cached-author check; the resident server retains only its reviewer credential and displays that active reviewer’s response-header pools separately. Independent identity, reset, stale and backoff evidence is specified in `specs/cockpit_foundation.md`; telemetry never warms credentials or invokes confirmed sync.

The propagated publisher structural fence also prevents scheduled and manually dispatched runs of the native body/label gate. Its parsed-YAML contract is in `specs/required_check_publisher.md` and its mutation cases are in `tests/test_merge_clearance_gate.sh`.

The required lint lane checks blocking-label parity between Label Gate and the shared shell predicate. Its literal-source contract and add/remove mutation coverage are documented in `specs/repo_lint_execution.md` and `tests/test_pr_review_policy_nudge.sh`.

Phase 4b adapter availability uses the manual-handoff status independently of immutable-input integrity refusals. Missing reviewer CLI/schema and unavailable subscription auth use exit 4; missing jq remains an orchestrator prerequisite with exit 3; binding and live head/base refusals retain exit 3 and cannot enable wave fan-out. See [`specs/phase_4b_immutable_input.md`](../../specs/phase_4b_immutable_input.md).

Phase 4b approvals without a request-budget snapshot capture and revalidate Codex request history under the PR's governing base-policy author identity. Both capture and the merge checker use the shared parsed-author selector, so valid flow-style or quoted YAML keys select the same authority; a present invalid author fails closed in both. A different identity in the trusted local checkout cannot supply request authority; unreadable governing policy or history fails closed when Codex requests are governed. If the governing policy disables Codex, the approval caller may proceed without a request record despite unreadable history. The contract and sourced-helper regressions live in `specs/codex_request_evidence.md` and `tests/test_codex_request_evidence.sh`.

Codex request reuse takes its freshness window from the PR's governing base policy before any timing decision. This read does not validate request caps; new trigger writes retain the separate governing-budget fence. The contract and production-requester regressions are in `specs/codex_request_evidence.md` and `tests/test_codex_review_request_trigger_only.sh`.

Phase 4b request-generation records distinguish a genuinely absent manual record from damaged automated evidence. Prefix detection, fail-closed parsing and production-checker regression coverage are specified in `specs/codex_request_evidence.md`; malformed or duplicate records never enable the manual timestamp fallback.

Phase 4b approval writers compare the original governing request generation with one final live generation-only read after feedback accounting, including snapshot routes. Drift or unreadability refuses with exit 10 and existing pre-POST cleanup, without rebuilding the Codex ledger. The governing Codex-disabled exception remains. The contract and regression fixtures are in `specs/codex_request_evidence.md` and `tests/test_phase_4b_automation.sh`.

Ordinary author-wrapped merges run a fresh threshold-aware clearance check at the final writer boundary. Exact default-commit code loading, governing-base policy materialization, canonical target/head checks and the non-atomic request-observation limit are specified in [`specs/codex_request_evidence.md`](../../specs/codex_request_evidence.md); production-writer integration runs through the guard suite.

Token-output helper discovery retains every recognized body for each function name and runs its existing emitter fixed point over all of them. Any emitting body promotes the name; all-safe chains remain clean. Definitions after a call or in a false branch can conservatively flag a safe runtime call because the scanner does not infer definition execution or runtime function lookup. The contract and execution-oracle regressions live in `scripts/ci/token_output_gate.py` (#1467).

Token-output callback discovery recognizes literal `mapfile` and `readarray` short-option bundles such as `-tC`, rescanning only the callback value as shell source. For a literal option prefix it stops at `--` or the array operand and consumes other options’ values without interpreting them as source. An unresolved prefix retains conservative rescanning of later known callbacks rather than inferring runtime option consumption or array lookup. The bounded extractor, execution-oracle cases and unchanged deferred-depth contract live in `scripts/ci/token_output_gate.py` (#1450).
