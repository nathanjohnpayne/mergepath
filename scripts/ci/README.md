# scripts/ci/

CI enforcement scripts for this repository.

The checks defined here mirror the steps in `.github/workflows/repo_lint.yml`
and can also be run locally before pushing.

Local scripts:

- `check_required_root_files`
- `check_no_tool_folder_instructions`
- `check_no_forbidden_top_level_dirs`
- `check_dist_not_modified`
- `check_spec_test_alignment`
- `check_duplicate_docs`
- `check_codex_scripts` — verifies `scripts/codex-review-request.sh`, `scripts/codex-review-check.sh`, and `scripts/codex-record-feedback.sh` exist and are executable, then runs the Phase 4a helper test suites including `tests/test_codex_record_feedback.sh` (the #487 validated-👍/👎 feedback loop)
- `check_review_feedback_accounting` — verifies and tests `scripts/review-feedback-accounting.sh`, the complete-history gate that reconciles inline and top-level review-body findings with finding-bound disposition evidence before another Codex round, Phase 4b dispatch, or merge (#1000)
- `check_codex_p1_gate` — verifies `scripts/codex-p1-gate.sh` + `.github/workflows/codex-p1-gate.yml` + `tests/test_codex_p1_gate.sh` exist, then runs the fixture-driven test suite (Codex blocking-tier unresolved-thread merge gate — P1-only when `feedback_policy` is absent, generalized to the resolved `required` tiers in #577; #235)
- `check_coderabbit_severity_gate` — the CodeRabbit twin of `check_codex_p1_gate`: verifies `scripts/coderabbit-severity-gate.sh` + `.github/workflows/coderabbit-severity-gate.yml` + `tests/test_coderabbit_severity_gate.sh` exist, checks the workflow trigger shape, then runs the fixture-driven suite (CodeRabbit blocking-tier unresolved-thread merge gate, gated by `coderabbit.severity_gate.enabled`; #574/#577)
- `check_sync_manifest` — validates `.mergepath-sync.yml` (manifest read by `scripts/sync-to-downstream.sh`): schema version, consumer shape, every referenced path exists, every path type is recognized. Requires `yq` (mikefarah/yq v4+) on the runner. See #168.
- `check_propagation_closure` — the INVERSE of `check_sync_manifest` (#519/#521). Scans references *out of* every propagated `scripts/ci/check_*` + canonical `.github/workflows/*` file and fails if any on-disk `tests/`+`scripts/` reference is undeclared (not an exact manifest path, not inside a kit, not in any `requires:`) — i.e. a propagation dependency that would silently *not travel* to consumers and make the referencing tool fail closed there. Skips refs that do not resolve to a real file (fixture strings, doc examples) plus an allow-list of orchestrator/mergepath-internal paths. Requires `yq` (mikefarah/yq v4+); SKIPs on a consumer checkout. See #521.
- `check_doc_ownership` — validates the `doc_ownership:` inventory in `.mergepath-sync.yml`: every `docs/agents/*.md` on disk must carry EXACTLY ONE ownership class (`canonical` / `per-repo-owned` / `hub-only`), no entry may be stale, out of scope, or use an unsafe/noncanonical path spelling, a `canonical` class must be backed by a fleet-wide `paths:` entry without an unsupported destination remap (or declare `pending_manifest: true` with a `note:`), and a `per-repo-owned`/`hub-only` doc must not be verbatim-mirrored by a `canonical`/`kit` entry. Also cross-checks `check_sync_manifest`'s `IDENTITY_DOCS_DENYLIST` for a contradictory `canonical` class, and enforces consumer-truthfulness: a `canonical` doc must not reference a `hub-only` doc by repo-relative path (that link 404s in every consumer; absolute URL occurrences are masked individually, while any bare repo-relative occurrence on the same line still fails). Requires `yq` (mikefarah/yq v4+); `--check` runs the live inventory assertion, `--self-test` runs `tests/test_check_doc_ownership.sh`, and the no-argument compatibility mode runs both. SKIPs on a consumer checkout. See #780 and `specs/repo_lint_execution.md`.
- `check_coderabbit_config` — validates `.coderabbit.yml` parses as YAML and (in the Mergepath template repo only) stays on `reviews.profile: chill` (the nit-suppressing profile per CodeRabbit's docs). Consumer repos inheriting this workflow via the template-mirror bootstrap get the parse + existence checks but may override `profile: assertive` locally without failing CI. Template detection prefers `GITHUB_REPOSITORY` (CI) and falls back to the `origin` remote URL for local runs; override via `MERGEPATH_TEMPLATE_CHECK=force|skip`. Requires `yq` (mikefarah/yq v4+) on the runner. See #237 and #256 P2.
- `check_coderabbit_config_tests` — unit tests for `check_coderabbit_config` itself. Drives the template-vs-consumer detection via fixture repos under `tests/test_check_coderabbit_config.sh`. See #256 P2.
- `check_coderabbit_wait` — runs `tests/test_coderabbit_wait_status_probe.sh`, covering `scripts/coderabbit-wait.sh` timeout status probing, unchanged exit-4 semantics, and the guard that prevents status replies from counting as review clearance. See #417.
- `check_lint_tooling` — runs `tests/test_lint_tooling.sh`, unit tests for `scripts/lib/lint-tooling.sh`, the shared visibility helper for OPTIONAL lint tooling. Makes a missing local `shellcheck` loud (a WARN locally, a hard FAIL under CI or `MERGEPATH_REQUIRE_SHELLCHECK=1`) instead of a silent skip, closing the gap where a local run without shellcheck passes before CI catches warning-level issues. The helper also runs directly (`bash scripts/lib/lint-tooling.sh`) as a one-shot lint-tool availability report; `check_phase_4b_automation` consumes it for its shellcheck step. See #588.
- `check_eslint_config_present` — enforces the ESLint flat-config policy (`rules/repo_rules.md` § ESLint policy). If a root `package.json` exists, `eslint.config.js` must exist at the repo root and parse under `node --check`. Repos without a root `package.json` (mergepath itself) pass via an early-out. See #250.
- `check_eslint_config_policy` — runs `tests/test_eslint_policy_check.sh` (unit tests for the policy check).
- `check_sweep_unresolved_feedback` — runs unit tests for the #236 weekly feedback sweep pipeline (`scripts/sweep-unresolved-feedback/enumerate.sh`, `render.sh`). PATH-shims `gh` against synthetic fixtures; hermetic.
- `check_disagreement_detector` — runs `tests/test_disagreement_detector.sh` against fixtures under `scripts/ci/fixtures/disagreement-detector/`. Exercises `scripts/disagreement-detector.cjs`, the decision function extracted from `.github/workflows/agent-review.yml`'s `detect-disagreement` job so the workflow and the test share one implementation. Asserts the workflow still `require()`s the module. See #259.
- `check_agent_review_triage_defers` — structural guard that `.github/workflows/agent-review.yml`'s `triage` job skips its `needs-external-review` add ONLY for a head the propagation lane has byte-verified (a `github-actions[bot]` comment pinning `mergepath-propagation-lane verified-head=<current head sha>`), staying fail-closed for every unverified sync head. Asserts the `PROPAGATION-LANE-DEFER (#656)` anchor, the three-file marker lockstep (agent-review.yml, pr-review-policy.yml, merge-clearance-gate.sh), head-pinning, the `github-actions[bot]` trust scope, fail-closed on a failed marker read, and that the label add survives. Anti-regression canary for the tadlockpsychiatry#93 flap AND for the fail-open variant Codex P1'd on the closed first attempt. No yq, no network. See #656.
- `check_consumer_residue_safety` — runs `tests/test_consumer_residue_safety.sh`, the RESIDUE-INVARIANCE net. `check_repo_lint_consumer_safety` models a consumer by *stripping* a hand-written list out of the hub tree, so it can only ever exercise a check against files that are **missing**; bootstrap residue is the opposite shape — a hub-only file left **present** on a consumer by a bootstrap taken before the mirror exclusion existed (gaycruisebingo carries ~24 such paths). This suite derives the consumer shape from `.mergepath-sync.yml` instead of a hand list, computes for each `check_*` wrapper the hub-only paths it references — the manifest-undelivered paths, out of exactly the set the derived baseline strips, whose literal path or `/<basename>` appears in the wrapper's source — and asserts the wrapper's verdict, exit status *and* whether the canonical consumer-SKIP line was emitted, is identical for every subset of those paths. Two structural assertions cover what reading the wrapper's text cannot: a wrapper that declares a consumer gate (a hub-marker test, or a consumer-SKIP line) must reference at least one hub-only path or be recorded in `MARKER_ONLY_CONSUMER_GATES` — otherwise its gate reads something this net cannot see and it is enrolled in no lattice at all — and every SKIP line such a wrapper emits must use the canonical `<name>: SKIP` spelling, because that literal is what the verdict pair greps for. The design rule it enforces: put the `scripts/sync-to-downstream.sh` marker test FIRST, above any test of the check's own hub-only artifacts. Wrappers that already violate it are recorded in a `KNOWN_RESIDUE_VIOLATIONS` ratchet that fails on a new violation, on a stale entry, and on an escalated divergence class — a listed wrapper is probed past its first divergence so the recorded class is the worst one in its lattice, never just the first one found. Hermetic (PATH-shimmed `gh`, no token, no network); SKIPs on a consumer checkout via the marker. Requires `yq` + `rsync` + `timeout`.

- `check_git_identity_hygiene` — guards commit attribution against a repo-local git identity override (#777). Three parts: (A) fails when THIS checkout's git config carries a local- or worktree-scoped `user.name` / `user.email` / `user.signingkey` / `commit.gpgsign` / `tag.gpgsign` — the exact corruption that reached `main` twice, misattributing and unsigning every commit from every worktree sharing the config. A key set to the empty string counts, because it masks the global value rather than deferring to it (`git var GIT_AUTHOR_IDENT` then fails outright). The lookup passes `--includes`, since a scope-restricted read has includes OFF by default and an `include.path` that supplies `user.email` is a local-scope override ordinary lookup obeys — invisible to a plain `--local --get-all`. It then re-walks the same include graph ignoring the conditions, because `--includes` evaluates an `includeIf` against the checkout as it stands: an `includeIf "onbranch:release"` target that sets `user.email` reads as absent on `main` and applies the moment that branch is checked out, with no write left at that point for a later run to catch. The walk resolves an include path as git resolves it, `~user/…` through the passwd database included — read as a relative path, `~alice/config` became a nonexistent `<parent-dir>/~alice/config` and was dropped while git expands the same string against alice's home and obeys what it finds — and FAILS CLOSED on a path it cannot expand, since "could not read it" must not be recorded as "nothing there"; a path that resolves to a file which simply does not exist is not a failure, because git ignores a missing include. The failure prints one deduplicated unset command per offender actually found — per distinct key *and* scope *and* origin file, so three keys in one file yield three commands and one key set in two scopes (or in both `.git/config` and an included file) yields one command each, aimed at the repository that was inspected (`git -C <repo>`, which is not necessarily the caller's cwd — the check runs by absolute path and `MERGEPATH_GIT_IDENTITY_ROOT` repoints it) and at the file that actually holds the value, which for an included value is that file rather than the parent config; (B) `--snapshot` records `.git/config` and a later plain run byte-compares against it, which is why `repo_lint.yml` wires the snapshot as an early step and the check itself as the LAST step — together they assert that running the wrapped test suites leaves `.git/config` untouched; (C) a hub-only static scan (gated on the `scripts/sync-to-downstream.sh` marker) that fails any tracked shell script or Markdown doc writing one of those keys through a `git config` that does not name a target (`-C`, `--git-dir`, `--file`, `--blob`) or an out-of-repo scope (`--global`, `--system`). Keys are matched case-insensitively (a git config key is case-insensitive in section and name alike: `git config User.Email <addr>` writes exactly the override a later lowercase read returns) and a path-qualified executable counts (`/usr/bin/git config user.email <addr>` writes the file a bare `git` writes). "Shell script or Markdown doc" is taken at its word: extensions match case-insensitively across the Markdown spellings GitHub renders (`.md`, `.markdown`, `.mdown`, `.mkd`) and the shells scripts get written in, and an extensionless file is classified by shebang — `#!/usr/bin/env sh` included, which has no slash before the interpreter word and so escaped a `/sh` substring test. A surface the classifier skips is a surface with no gate on it at all, so the Markdown half of the list is kept in lockstep with the backtick-cutting test in the scanner. The scan joins backslash-continued lines into logical commands first, so a write split as `git \` + `config user.email …` — where neither half matches anything on its own — is still caught, then cuts each logical command at shell separators (`&&`, `||`, `;`, `|`) and judges the pieces separately, so a suppressor belonging to one command cannot cover another: in `git -C "$fix" status && git config user.email <addr>` the `-C` is the read's, not the write's. Inside one command a suppressor is read only from the OPTION REGION — the text between the `git` word and the identity key — and only as a whole token, because searching the whole command let things that are not flags act as flags: `--get` inside the value (`git config user.email` given the value `author--get@example.com` writes that address), `--get` inside another option's argument, and `--global` sitting in prose or in an adjacent word no separator split off. Every form git accepts puts its options before the key, and a trailing `--global` does not scope the write at all — `git config user.email <addr> --global` writes the LOCAL config. Markdown is cut on backticks too — a doc sentence has no shell separators, so the whole paragraph would be judged at once, and putting the sanctioned `--global` form next to the forbidden one (which is how this rule gets explained) would let the first wave the second through. A value token is anything that is not an option, a `#` comment, a redirection, a closing substitution or code span, or a line continuation — defining it as an allow-list of opening characters instead exempted every path-valued write, and `user.signingkey`, the key that decides which key SIGNS each commit, is almost always given a path (`~/.ssh/id_ed25519.pub`, `/tmp/key.pub`). Reads, removals, and the ephemeral `git -c key=value` form are never flagged; a line may opt out with `GIT_IDENTITY_SCOPE_EXEMPT: <reason>` — `# …` in a script or a doc code block, `<!-- … -->` in Markdown, the spelling `docs/audits/git-identity-leak-2026-07.md` uses to quote the #777 writer — which has to BE a comment rather than merely appear on the line, since honouring it anywhere let an `echo` of the marker, or a sentence naming it with the write in a code span, switch the scan off; it exempts the logical command it terminates (a multi-line command can only carry a trailing comment on its last physical line) but never the other physical lines a backslash joined to it — a self-contained write is judged on its own marker, so an exempt line ending in `\` cannot wave through the write on the line below. In Markdown the marker is tested with code spans stripped, so a mention inside backticks is a citation of the marker and not a use of it — honouring those mentions exempted every paragraph that documents this check, which is to say the paragraphs most likely to carry the forbidden shape. In a doc, rewriting the example so it cannot run (key and value as separate spans, or a placeholder value) is preferred over exempting it, which leaves a pasteable command sitting there. Every offending line in a joined group is listed, not just the first, so one pass of the printed remediation clears the file. Set `MERGEPATH_ALLOW_LOCAL_GIT_IDENTITY=1` to skip part A on a checkout that wants its own identity. Runs `tests/test_git_identity_hygiene.sh` as its regression net, then re-runs parts A and B afterwards — the suite is the last thing the check does and the static scan deliberately excludes its file, so without the second pass a suite that corrupted `.git/config` would still leave the job's final step reporting PASS. The same pass asserts the repository metadata survived: parts A and B both reach the repository through `.git`, so a suite whose fixture cleanup lands one directory too high (`rm -rf "$ROOT/.git"`) destroyed the evidence along with the subject and left each of them reporting nothing to check. What they need is captured before the suite starts, with the baseline copied outside the repository — a deleted config is not byte-identical to its snapshot, and the diff is still the actionable half once the baseline is gone.

When `check_git_identity_hygiene` sees a `.git` entry but Git cannot inspect its metadata or config, it fails closed instead of treating the read error as a non-repository skip.
